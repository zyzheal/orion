## 三、设计缺陷 (架构层面的问题)

### 3.1 过度依赖 LLM

**当前状态:**
- ✅ 有降级策略框架
- ❌ 没有为每个 LLM 调用定义具体降级方案
- ❌ 没有 AI 输出验证机制

**LLM 依赖清单:**

```
Orion 中 15+ 处依赖 LLM:

P0 (核心功能, 必须有降级):
├─ AI Code Review        → 降级: 规则引擎 (semgrep)
├─ Aegis 风险评估        → 降级: XGBoost 模型 + 规则
├─ Kintsugi 诊断         → 降级: 规则引擎 + 历史匹配
└─ 工单 NLP 理解         → 降级: 关键词匹配 + 分类模型

P1 (重要功能, 可以有降级):
├─ AI 修复建议           → 降级: Runbook 模板
├─ AI 自动排单           → 降级: 规则排单
├─ AI 效能分析           → 降级: 模板报告
├─ 数字孪生分析          → 降级: 规则模拟
└─ 零代码接入            → 降级: 交互式表单

P2 (锦上添花):
├─ 变更日志生成          → 降级: git log 格式化
├─ 配置审计              → 降级: 规则引擎
├─ Postmortem 生成       → 降级: 模板
├─ 知识提取              → 降级: 关键词索引
└─ 智能路由              → 降级: 规则路由
```

**每个 LLM 调用必须定义:**
```yaml
llm_call_spec:
  ai_code_review:
    model: qwen3-235b
    fallback: rule_engine (semgrep)
    timeout: "30s"
    max_cost: "¥0.50"
    output_validation:
      - must_be_json
      - must_have_required_fields
      - severity_must_be_valid_enum
    hallucination_check:
      - cross_reference_with_semgrep_results
      - confidence_score_required
```
