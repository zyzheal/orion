ChatOps 看板设计评审

UX视觉 + 产品领域专家评审稿

🎨 UX视觉设计要点

信息层次

  • 指标卡片 → 趋势图 → 明细排行，F型阅读路径，符合视觉习惯
  • 数据密度分三级：卡片(粗) → 图表(中) → 表格(细)，渐进式披露
  • 环比箭头（↑↓）用色彩编码，一眼感知变化趋势

潜在风险

  • 四个指标卡片并列可能显得信息碎片化，需统一卡片高度和间距
  • 三栏布局中"热门命令"和"平台分布"内容密度差异大，可能导致视觉重心不均
  • 时间选择器在移动端表现差，需考虑响应式降级方案

📐 布局与视觉规范

配色方案

主色#1890ff（平台主色）
成功#52c41a（成功率、正向指标）
失败#ff4d4f（失败数、告警）
警告#faad14（运行中、待处理）
辅助#722ed1（响应时间等次要指标）

间距系统

  • 卡片间距：16px (spacing[4])
  • 模块内间距：12px (spacing[3])
  • 指标卡片高度：80px 固定
  • 图表最小高度：200px
  • 圆角：8px（卡片）、4px（表格）

📊 交互细节

  • 卡片 Hover：悬浮时显示 tooltip，展示计算口径（如"成功率 = 完成数 / 总执行数"）
  • 趋势图交互：鼠标悬停柱状图时显示具体数值和日期
  • 热门命令：点击命令名可快速跳转到执行记录并过滤该命令
  • 最近执行：点击行可展开查看执行详情
  • 时间切换：切换时显示 loading skeleton，避免数据跳变
  • 空状态：无数据时显示引导提示（"还没有执行记录，开始第一次对话吧"）

💼 产品价值分析

用户价值

  • 运维效率：一屏了解 ChatOps 使用情况和执行健康度，减少切页面
  • 问题定位：失败率 + 热门命令组合可快速发现高频失败命令
  • 趋势感知：环比数据帮助判断运维效率是改善还是退化

业务约束

  • 需要后端新增聚合端点，增加开发工作量
  • 首次上线时数据为空，需要良好的空状态设计
  • 自定义时间范围查询可能涉及大数据量，需考虑分页和性能

🔧 技术可行性

  • 前端：复用现有 ExecutionDashboard 和 AuditLogViewer 组件作为 Tab 内容
  • 后端：需新增 GET /v1/chatops/dashboard/stats 聚合接口
  • 数据源：复用现有 ChatOpsExecutionRepository 和 ChatOpsAuditLogRepository
  • 性能：预加载2个Tab数据，查询量可控（<50条记录），响应时间预期 <500ms
  • 依赖：使用 ECharts 或 Ant Design Charts 绘制图表
