## 并行开发策略

### 第一批次 (可并行启动)
- **Infra**: F001 (无依赖)
- **Frontend**: F101 (无依赖)

### 第二批次 (依赖 F001/F101)
- **Infra**: F002 (依赖 F001)
- **Frontend**: F102 (依赖 F101)

### 第三批次 (依赖 F002/F102)
- **Infra**: F003, F004, F005 (依赖 F002)
- **Core**: F301 (依赖 F002, F003)
- **Support**: F401, F403 (依赖 F003)
- **Frontend**: F103 (依赖 F102)

### 第四批次 (依赖 F103)
- **SubApp**: F201 (依赖 F103)

### 第五批次 (SubApp 并行改造)
- **SubApp**: F203, F204, F205 (依赖 F202，3 个子应用可并行)

## 关键路径

```
F001 → F002 → F003 → F301 → F302  (关键路径，总计 8 天)
              ↓
           F401 → F402  (非关键，可与 Core 并行)

F101 → F102 → F103 → F201 → F202 → F203/F204/F205 → F206  (前端 + 子应用线，总计 16 天)
```

## 配置说明

```json
{
  "parallel_features": true,  // 允许并行开发无依赖的功能
  "control_level": "medium"   // 中等人工确认级别
}
```

当 `parallel_features: true` 时：
- 所有无依赖的功能可以并行启动
- dev-enegine 会自动识别可并行的 features
- 每个功能完成后会自动开始下一个可用的功能
