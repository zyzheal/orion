# 技能审核三端用户交互设计

> 本文档补充技能审核系统中不同角色的页面展示和交互流程设计

---

## 1. 角色定义与权限矩阵

### 1.1 角色定义

| 角色 | 英文标识 | 说明 | 权限范围 |
|------|---------|------|---------|
| **普通用户** | `user` | 技能使用者/开发者 | 浏览、安装、提交技能 |
| **技能作者** | `skill_author` | 技能的创建者 | 管理自己的技能、提交审核 |
| **审核人员** | `skill_reviewer` | 负责技能审核 | 审核技能、查看待审核列表 |
| **管理员** | `skill_admin` | 全面管理 | 审核、下架、配置、查看所有 |

**说明**：
- `skill_author` 是 `user` 的子角色（拥有技能）
- `skill_reviewer` 和 `skill_admin` 可以重叠（同一人）
- 权限优先级：`skill_admin` > `skill_reviewer` > `skill_author` > `user`

### 1.2 权限矩阵

| 功能 | 普通用户 | 技能作者 | 审核人员 | 管理员 |
|------|---------|---------|---------|--------|
| 浏览技能市场 | ✅ | ✅ | ✅ | ✅ |
| 安装/卸载技能 | ✅ | ✅ | ✅ | ✅ |
| 提交新技能 | ❌ | ✅ | ✅ | ✅ |
| 修改自己的技能 | ❌ | ✅ (draft/rejected) | ✅ | ✅ |
| 提交审核 | ❌ | ✅ (自己的draft) | ❌ | ❌ |
| 审核技能 | ❌ | ❌ | ✅ | ✅ |
| 下架技能 | ❌ | ❌ | ❌ | ✅ |
| 查看所有审核历史 | ❌ | ❌ | ✅ | ✅ |
| 查看自己的审核历史 | ✅ (自己的) | ✅ | ✅ | ✅ |
| 配置审核规则 | ❌ | ❌ | ❌ | ✅ |

```
┌─────────────────────────────────────────────────────────────────┐
```

### 4.3 状态对应的操作按钮

| 状态 | 可执行操作 | 按钮样式 |
|------|-----------|---------|
| `draft` | 编辑、提交审核 | `[编辑]` `[提交审核]` |
| `review` | 查看进度（不可编辑） | `[查看审核进度]` |
| `published` | 查看 | `[查看]` |
| `rejected` | 修改、重新提交审核 | `[修改]` `[重新提交]` |
| `archived` | 查看（不可编辑） | `[查看]` |

## 9. 验收检查点

### 9.1 角色可见性检查

- [ ] 普通用户只能看到 `published` 技能
- [ ] 技能作者能看到自己的 `draft/rejected` 技能
- [ ] 审核人员能看到 `review` 状态的技能
- [ ] 管理员能看到所有状态

### 9.2 操作权限检查

- [ ] 普通用户不能访问 `/skills/submit`
- [ ] 技能作者不能审核自己的技能
- [ ] 审核人员不能下架技能
- [ ] 只有管理员可以配置审核规则

### 9.3 交互流程检查

- [ ] 提交审核有确认弹窗
- [ ] 批准/拒绝有确认弹窗
- [ ] 下架有确认弹窗
- [ ] 操作成功/失败有提示消息
- [ ] 审核历史有时间线展示
