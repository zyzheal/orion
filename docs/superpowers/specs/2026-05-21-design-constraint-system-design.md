## 1. 背景与痛点

### 1.1 Orion 项目规模

| 维度 | 数量 | 人工检查耗时 |
|------|------|-------------|
| 后端 services | 101 | ~50 小时 |
| 前端 pages | 149 | ~75 小时 |
| API routes | 104 | ~30 小时 |
| 微服务 | 35 | ~20 小时 |
| **合计** | 389+ | **~175 小时** |

### 1.2 痛点

- 模块众多，无法人工检查核对每一个细节
- 交互缺失、功能遗漏是常态
- 兼容性、扩展性、生态能力没有系统管控

## 20. 自动识别引擎

  代码类型识别 → 模块识别 → 文档关联 → 检查项加载 → 执行检查

```bash

/skill design-constraint:check --scan-mode full

/skill design-constraint:check --scan-mode changed
```

## 24. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 检查项过多 (196项) | 执行时间长 | 分级执行，P0 必检，P1 可选 |
| 检测复杂度高 | 实现难度大 | 分阶段实施，先核心后扩展 |
| 配置复杂 | 维护成本高 | 提供模板，限制自定义范围 |
| 识别不准确 | 检查项错误 | 允许手动覆盖 --override |
