# V2.7 补丁：Milvus 向量数据库方案

> **版本**: V2.7
> **触发原因**: 将向量存储从 pgvector（PostgreSQL 扩展）升级为 Milvus 专用向量数据库
> **适用场景**: 当前 3 万向量无瓶颈，但设计面向未来百万级扩展，Milvus 提供更优的横向扩展能力、更低的查询延迟、和更丰富的索引算法
> **代码库状态**: 当前 `internal/vector` 模块使用 JSON 存向量（`vector_record` 表），`SearchVectors` 按 `created_at DESC` 排序（非向量检索），需全面改造

---

## 一、方案选择理由

### 1.1 Milvus vs pgvector vs 纯 JSON（当前）

| 维度 | 当前（JSON 存储） | pgvector（V2.5-2.6） | **Milvus（V2.7）** |
|------|-------------------|---------------------|-------------------|
| 检索方式 | `ORDER BY created_at`（❌ 非向量检索） | HNSW 索引（原生 SQL） | HNSW/IVF_FLAT/DISKANN（多种算法） |
| 检索延迟（3 万向量） | 返回随机数据 | ~2ms | **~1ms** |
| 检索延迟（100 万向量） | 不可用 | 15-50ms（退化） | **~2ms**（稳定） |
| 存储规模上限 | 无上限但性能退化 | 百万级（单机） | **十亿级**（分布式） |
| 多租户隔离 | 应用层 SQL WHERE | 应用层 SQL WHERE | **Collection 级别**（天然隔离） |
| 事务一致性 | ACID | ACID | 最终一致（可配置强一致） |
| 运维复杂度 | 零（复用 PostgreSQL） | 低（装 1 个扩展） | **中**（独立部署） |
| Go 客户端 | 已有（sqlx） | 已有（pgx） | 需新建（`go-milvus` SDK） |
| 与业务数据 JOIN | ✅ 原生 | ✅ 原生 | ❌ 需应用层桥接 |
| 向量检索 + 标量过滤 | ❌ | ✅（pgvector 原生） | ✅（Milvus 原生混合查询） |

### 1.2 为什么选 Milvus

| 因素 | 权重 | 评估 |
|------|------|------|
| **性能扩展性** | 高 | 当前 3 万向量无瓶颈，但 Orion 292 模块持续扩展，每模块 ~50 节点 × chunk，3 年内预计达百万级。Milvus 在百万级下延迟稳定 2ms，pgvector 退化至 50ms+ |
| **多租户天然隔离** | 高 | Milvus Collection 天然支持多租户隔离，每个租户独立 Collection，无需应用层 `WHERE tenant_id` 过滤 |
| **索引算法丰富** | 中 | HNSW/IVF_FLAT/IVF_PQ/DISKANN/AUTOINDEX，可根据数据特征选最优算法。pgvector 仅支持 HNSW/IVFFlat |
| **混合查询能力** | 高 | 向量 + 标量过滤一体化（`expr: "tenant_id == 'x' AND node_type == 'api'"`），pgvector 需先 SQL 过滤再向量搜索 |
| **独立运维** | 低 | Milvus 需独立部署，运维成本高于 pgvector，但对 Orion 当前的 K8s 基础设施（已有 Deployment/Service 模式）可接受 |

## 三、Milvus Collection 设计

### 3.1 多租户 Collection 策略

Orion 是多租户系统，每个租户的数据必须隔离。Milvus 有两种策略：

| 策略 | 描述 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| **A: 每租户 1 个 Collection** | `rag_orion_acme` / `rag_orion_globex` | 天然隔离，零代码过滤 | Collection 数量多时管理复杂 | 租户 > 100 时 |
| **B: 全局 1 个 Collection + tenant_id 字段过滤** | 所有租户共享，`expr: "tenant_id == 'x'"` | 管理简单 | 需确保所有查询带过滤 | 租户 < 100 时 |

**推荐**: 采用策略 B（全局 Collection + 标量过滤），当前 Orion 租户数量有限，且策略 B 的性能损耗可忽略（Milvus 标量过滤走索引）。

package milvus

import (
    "context"
    "fmt"
    "time"

    "github.com/milvus-io/milvus-sdk-go/v2/client"
    "github.com/milvus-io/milvus-sdk-go/v2/entity"
)

const (
    CollectionName = "rag_knowledge_embeddings"
    EmbeddingDim   = 768
    DefaultTopK    = 30
)

type Client struct {
    conn       client.Client
    addr       string
    collection *entity.Collection
}

type Config struct {
    Address string // "localhost:19530"
    User    string
    Password string
}

// NewClient 创建 Milvus 客户端
func NewClient(ctx context.Context, cfg Config) (*Client, error) {
    c, err := client.New(ctx, client.Config{
        Address: cfg.Address,
        Username: cfg.User,
        Password: cfg.Password,
    })
    if err != nil {
        return nil, fmt.Errorf("connect milvus: %w", err)
    }

    cli := &Client{conn: c, addr: cfg.Address}
    if err := cli.ensureCollection(ctx); err != nil {
        return nil, err
    }

    return cli, nil
}

// ensureCollection 确保 Collection 存在，不存在则创建
func (m *Client) ensureCollection(ctx context.Context) error {
    if has, _ := m.conn.HasCollection(ctx, CollectionName); has {
        coll, err := m.conn.DescribeCollection(ctx, CollectionName)
        if err == nil {
            m.collection = coll
        }
        return nil
    }

    schema := entity.NewSchema().
        WithID(entity.NewField().
            WithName("id").
            WithDataType(entity.FieldTypeInt64).
            WithIsPrimaryKey(true).
            WithAutoID(true)).
        WithField(entity.NewField().
            WithName("entity_id").
            WithDataType(entity.FieldTypeVarChar).
            WithMaxLength(500)).
        WithField(entity.NewField().
            WithName("node_type").
            WithDataType(entity.FieldTypeVarChar).
            WithMaxLength(30)).
        WithField(entity.NewField().
            WithName("tenant_id").
            WithDataType(entity.FieldTypeVarChar).
            WithMaxLength(255)).
        WithField(entity.NewField().
            WithName("store_id").
            WithDataType(entity.FieldTypeVarChar).
            WithMaxLength(100)).
        WithField(entity.NewField().
            WithName("embedding").
            WithDataType(entity.FieldTypeFloatVector).
            WithDim(EmbeddingDim)).
        WithField(entity.NewField().
            WithName("text").
            WithDataType(entity.FieldTypeVarChar).
            WithMaxLength(5000)).
        WithField(entity.NewField().
            WithName("parent_id").
            WithDataType(entity.FieldTypeVarChar).
            WithMaxLength(500)).
        WithField(entity.NewField().
            WithName("bm25_tokens").
            WithDataType(entity.FieldTypeVarChar).
            WithMaxLength(500)).
        WithField(entity.NewField().
            WithName("created_at").
            WithDataType(entity.FieldTypeInt64)).
        WithField(entity.NewField().
            WithName("updated_at").

    err := m.conn.CreateCollection(ctx, schema, entity.DefaultIndex, 1)

    }

    return m.conn.LoadCollection(ctx, CollectionName, false)
}

### 4.2 Upsert 操作

```go
// UpsertRequest 单次 upsert 请求
type UpsertRequest struct {
    EntityID   string            // 业务实体 ID
    NodeType   string            // 节点类型
    TenantID   string            // 租户 ID
    StoreID    string            // 向量库 ID
    Embedding  []float32         // 768 维向量（已 L2 归一化）
    Text       string            // chunk 原文
    ParentID   string            // 父节点 ID
    BM25Tokens string            // jieba 分词结果
}

// UpsertBatch 批量写入向量（每次最多 1 万条）
func (m *Client) UpsertBatch(ctx context.Context, batch []UpsertRequest) error {
    if len(batch) == 0 {
        return nil
    }

    // 构建列数据
    entityIDs := make([]string, len(batch))
    nodeTypes := make([]string, len(batch))
    tenantIDs := make([]string, len(batch))
    storeIDs := make([]string, len(batch))
    embeddings := make([]entity.FloatVector, len(batch))
    texts := make([]string, len(batch))
    parentIDs := make([]string, len(batch))
    bm25Tokens := make([]string, len(batch))
    now := time.Now().Unix()

    for i, req := range batch {
        entityIDs[i] = req.EntityID
        nodeTypes[i] = req.NodeType
        tenantIDs[i] = req.TenantID
        storeIDs[i] = req.StoreID
        embeddings[i] = req.Embedding
        texts[i] = req.Text
        parentIDs[i] = req.ParentID
        bm25Tokens[i] = req.BM25Tokens
    }

    columns := []*entity.Column{
        entity.NewColumnVarChar("entity_id", entityIDs),
        entity.NewColumnVarChar("node_type", nodeTypes),
        entity.NewColumnVarChar("tenant_id", tenantIDs),
        entity.NewColumnVarChar("store_id", storeIDs),
        entity.NewColumnFloatVector("embedding", EmbeddingDim, embeddings),
        entity.NewColumnVarChar("text", texts),
        entity.NewColumnVarChar("parent_id", parentIDs),
        entity.NewColumnVarChar("bm25_tokens", bm25Tokens),
        entity.NewColumnInt64("created_at", makeInt64Slice(now, len(batch))),
        entity.NewColumnInt64("updated_at", makeInt64Slice(now, len(batch))),
    }

    result, err := m.conn.Insert(ctx, CollectionName, "", columns...)
    if err != nil {
        return fmt.Errorf("insert vectors: %w", err)
    }

    // 刷新使数据可查询（Milvus 默认异步，Insert 后立即查询可能返回空）
    return m.conn.Flush(ctx, CollectionName, false)
}
```

### 4.3 向量搜索（核心查询）

```go
// SearchRequest 向量搜索请求
type SearchRequest struct {
    TenantID  string    // 租户 ID（必传）
    Embedding []float32 // 768 维查询向量
    TopK      int       // 返回数量
    Filter    string    // 可选标量过滤条件（如 "node_type == 'api_endpoint'"）
}

// SearchResult 搜索结果
type SearchResult struct {
    EntityID string  `json:"entity_id"`
    NodeType string  `json:"node_type"`
    Text     string  `json:"text"`      // 匹配的 chunk 原文
    ParentID string  `json:"parent_id"` // 父节点 ID
    Distance float64 `json:"distance"`  // 余弦距离（0 = 完全匹配，1 = 完全不同）
}

// Search 执行向量相似度搜索
func (m *Client) Search(ctx context.Context, req SearchRequest) ([]SearchResult, error) {
    if req.TenantID == "" {
        return nil, fmt.Errorf("tenant_id is required")  // 多租户隔离保障
    }
    if req.TopK <= 0 {
        req.TopK = DefaultTopK
    }

    // 构建过滤表达式（多租户 + 可选标量过滤）
    expr := fmt.Sprintf("tenant_id == '%s'", sanitizeExpr(req.TenantID))
    if req.Filter != "" {
        expr += fmt.Sprintf(" && %s", sanitizeExpr(req.Filter))
    }

    searchParams := entity.NewHammingFlatSearchParams(
        entity.NewIndexHNSWSearchParams(200)) // ef=200

    results, err := m.conn.Search(
        ctx,
        CollectionName,
        expr,           // 标量过滤
        []string{"embedding"}, // 向量字段
        entity.NewFloatVector("embedding", EmbeddingDim, req.Embedding),
        []string{"entity_id", "node_type", "text", "parent_id"}, // 返回字段
        req.TopK,
        searchParams,
    )
    if err != nil {
        return nil, fmt.Errorf("search milvus: %w", err)
    }

    // 解析结果
    var searchResults []SearchResult
    for _, row := range results[0].Rows() {
        var sr SearchResult
        // 从 row 中提取字段...
        searchResults = append(searchResults, sr)
    }

    return searchResults, nil
}

// sanitizeExpr 防止 Milvus 表达式注入
func sanitizeExpr(s string) string {
    // 移除引号防止注入: tenant_id == 'x' || 1==1'
    s = strings.ReplaceAll(s, "'", "")
    s = strings.ReplaceAll(s, "`", "")
    return s
}
```

## 五、RAG 检索链路集成

### 5.1 混合检索（Milvus + BM25 + Graph）

```go
package service

import (
    "context"
    "github.com/yourorg/orion/internal/vector-store-go-milvus"
)

type HybridRetriever struct {
    milvus   *milvus.Client
    bm25     *BM25Retriever   // PostgreSQL semantic-search
    graph    *GraphRetriever  // 知识图谱
    embedding *EmbeddingEngine // 本地 bge-base-zh ONNX
}

type RetrievalResult struct {
    Nodes []KnowledgeNode
}

// Search 执行三路混合检索 + RRF 融合
func (r *HybridRetriever) Search(ctx context.Context, query string, tenantID string, topK int) (RetrievalResult, error) {
    // 1. 生成查询向量（本地 ONNX, ~8ms）
    queryVec := r.embedding.Encode(query)

    // 2. 三路并行检索
    type searchResult struct {
        source string
        nodes  []KnowledgeNode
    }
    results := make(chan searchResult, 3)

    // 2a. Milvus 向量检索（~1ms）
    go func() {
        sr, _ := r.milvus.Search(ctx, milvus.SearchRequest{
            TenantID:  tenantID,
            Embedding: queryVec,
            TopK:      topK * 3,  // 过采 3x 供融合
        })
        nodes := convertToKnowledgeNodes(sr)
        results <- searchResult{source: "vector", nodes: nodes}
    }()

    // 2b. BM25 检索（~1ms）
    go func() {
        nodes, _ := r.bm25.Search(ctx, query, tenantID, topK*2)
        results <- searchResult{source: "bm25", nodes: nodes}
    }()

    // 2c. 图谱查询（~5ms）
    go func() {
        nodes, _ := r.graph.Query(ctx, query, tenantID, topK*2)
        results <- searchResult{source: "graph", nodes: nodes}
    }()

    // 3. 收集结果
    var vectorNodes, bm25Nodes, graphNodes []KnowledgeNode
    for i := 0; i < 3; i++ {
        r := <-results
        switch r.source {
        case "vector": vectorNodes = r.nodes
        case "bm25":   bm25Nodes = r.nodes
        case "graph":  graphNodes = r.nodes
        }
    }

    // 4. RRF 融合
    fused := rrfFuse(vectorNodes, bm25Nodes, graphNodes, topK)
    // 权重: 0.50 vector + 0.35 bm25 + 0.15 graph

    return RetrievalResult{Nodes: fused}, nil
}
```

### 5.2 Parent Retrieval 展开

```go
// ParentRetriever 将 chunk 检索结果展开为父节点全文
type ParentRetriever struct {
    nodeStore *NodeRepository  // PostgreSQL rag_knowledge_nodes
}

// Expand 将 Top-K chunk 结果去重 parent 后返回完整文档
func (r *ParentRetriever) Expand(ctx context.Context, chunks []milvus.SearchResult, topK int) ([]KnowledgeNode, error) {
    seen := map[string]bool{}
    var nodes []KnowledgeNode

    for _, chunk := range chunks {
        if seen[chunk.ParentID] {
            continue
        }
        if len(nodes) >= topK {
            break
        }
        seen[chunk.ParentID] = true

        node, err := r.nodeStore.GetByID(ctx, chunk.ParentID)
        if err != nil {
            continue
        }
        nodes = append(nodes, *node)
    }
    return nodes, nil
}
```

| 新建 `internal/vector-store-go-milvus` | **新模块** | Milvus 客户端 + RAG 检索 |

### 6.2 RAG 索引构建流程更新

```
RAG Indexer Worker（定时/事件触发）
    │
    ├── Step 1: 读取数据源
    │   ├── handler_registry_entries（handler-registry 模块 API）
    │   ├── runbook（runbook 模块 API）
    │   ├── alert_rules（alert-rule-engine 模块 API）
    │   ├── 前端路由（CI postbuild 钩子上报）
    │   └── 数据表（migration DDL 扫描）
    │
    ├── Step 2: 分块 + 分词
    │   ├── Parent Retrieval 分块: 每个文档 → 200 字 chunk（重叠 50 字）
    │   └── jieba 中文分词: chunk → "token1 token2 token3"
    │
    ├── Step 3: Embedding（本地 bge-base-zh ONNX）
    │   ├── 每个 chunk → 768 维向量（L2 归一化）
    │   └── 批处理: 每 100 条 batch，避免 OOM
    │
    ├── Step 4: 写入 Milvus
    │   ├── UpsertBatch（每 1000 条一批）
    │   ├── 写入字段: entity_id / node_type / tenant_id / embedding / text / parent_id / bm25_tokens
    │   └── Flush（确保立即可查询）
    │
    ├── Step 5: 写入 PostgreSQL（BM25 + 知识图谱）
    │   ├── semantic_search_results（BM25 索引）
    │   ├── rag_knowledge_nodes（图谱节点）
    │   └── rag_knowledge_edges（图谱边）
    │
    └── Step 6: 更新同步状态
        └── rag_sync_status 表
```

## 七、性能预算（Milvus 方案）

| 阶段 | 组件 | 延迟 | 累计 |
|------|------|------|------|
| Embedding | bge-base-zh ONNX（本地） | **8ms** | 8ms |
| 向量检索 | **Milvus HNSW** | **1ms** | 9ms |
| BM25 检索 | PostgreSQL GIN | **1ms** | 10ms |
| 图谱查询 | PostgreSQL 图查询 | **5ms** | 15ms |
| RRF 融合 | 内存计算 | **0.5ms** | 15.5ms |
| Parent Retrieval | PostgreSQL 查询 | **2ms** | 17.5ms |
| Re-rank | bge-reranker ONNX（本地） | **10ms** | 27.5ms |
| 防幻觉 Layer A+B | handler-registry + 前端校验 | **15ms** | 42.5ms |
| LLM 生成 | Qwen2.5-3B ONNX（本地） | **500ms** | 542.5ms |
| Layer C 答案校验 | regex + 白名单 | **2ms** | **544.5ms** |
| **总计** | | | **~545ms** |

对比 pgvector 方案（538ms）: 延迟仅增加 7ms（Milvus 网络往返 vs 本地 pgvector 连接），但换来百万级扩展能力。
