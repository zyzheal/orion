# V2.9 补丁：可扩展多系统索引 + Orion 原生集成

> **版本**: V2.9
> **触发原因**: 用户提出两项能力提升需求：(1) RAG 索引不限于 Orion，可接入其他系统；(2) 完美融入 Orion 系统并有合理的启用/关闭入口
> **核心原则**: Adapter 抽象层实现索引能力可插拔 + 三层开关实现 Orion 原生集成

---

## 一、多系统索引能力

### 1.1 架构设计

```
RAG Indexer（统一索引引擎）
    │
    ├── Indexer Core（通用索引逻辑）
    │   • Chunking（Parent Retrieval, 200字chunk）
    │   • Embedding（bge-base-zh ONNX, 768维）
    │   • Milvus Upsert（向量写入）
    │   • BM25 写入（PostgreSQL 全文索引）
    │   • Sync Status 追踪（rag_sync_status 表）
    │
    └── Adapter Registry（适配器注册中心）
        │
        ├── 内置适配器（Orion 内部系统）:
        │   • orion-handler   → handler_registry_entries（CDC）
        │   • orion-runbook   → runbook 模块 API（Webhook）
        │   • orion-alert     → alert-rule-engine（Webhook）
        │   • orion-frontend  → routes.tsx 解析（CI 钩子）
        │   • orion-migration → migration DDL 扫描（轮询）
        │
        └── 外部系统适配器（任意系统）:
            • gitlab-code        → GitLab API/Webhook（代码文件）
            • prometheus-rules   → Prometheus HTTP API（告警规则）
            • servicenow         → ServiceNow REST API（CMDB/工单）
            • grafana-dashboard  → Grafana HTTP API（监控面板）
            • jenkins-pipeline   → Jenkins REST API（流水线定义）
            • 任意系统           → 实现 IIndexAdapter 接口即可接入
```

### 1.2 统一适配器接口

```go
// IIndexAdapter 所有索引数据源的统一接口
type IIndexAdapter interface {
    Name() string                           // 唯一标识
    SourceType() SourceType                 // orion/git/monitoring/ticket/external
    Discover(ctx, config) ([]KnowledgeNode, error)  // 发现可索引节点
    Watch(ctx, config) (<-chan ChangeEvent, error)  // 监听变更（返回 nil = 不支持）
    Health(ctx, config) (AdapterHealth, error)      // 健康检查
    Schema() AdapterSchema                  // 配置 Schema（动态表单）
}
```

### 1.3 内置适配器配置

| 适配器 | 数据源 | 节点类型 | 同步方式 | 配置字段 |
|--------|--------|---------|---------|---------|
| `orion-handler` | handler-registry | api_endpoint | CDC LISTEN/NOTIFY | —（自动发现） |
| `orion-runbook` | runbook 模块 | runbook | Webhook + 轮询 | —（自动发现） |
| `orion-alert` | alert-rule-engine | alert_rule | Webhook + 轮询 | —（自动发现） |
| `gitlab-code` | GitLab 仓库 | code_file | Webhook（push） | `git_url` / `access_token` / `branch` / `extensions` |
| `prometheus-rules` | Prometheus | alert_rule | HTTP API 轮询 | `prometheus_url` / `auth_token` |
| `servicenow` | ServiceNow | incident / cmdb_ci | REST API 轮询 | `instance_url` / `username` / `password` |
| `grafana-dashboard` | Grafana | dashboard | HTTP API 轮询 | `grafana_url` / `api_key` |
| `jenkins-pipeline` | Jenkins | pipeline_definition | Webhook + REST API | `jenkins_url` / `api_token` |

### 1.4 外部系统接入流程

```
第三方系统接入 RAG 的完整流程:

Step 1: 实现 IIndexAdapter 接口
  └── 最少实现: Name() + Discover() + Health() + Schema()
      (Watch() 可返回 nil，Indexer 自动降级为轮询)

Step 2: 注册到 Adapter Registry
  └── 新建或更新 rag_adapter_registry 表记录
      { adapter_name: "my-system", source_type: "external", status: "disabled" }

Step 3: 配置适配器参数
  └── 通过 Schema() 返回的 ConfigField 列表生成管理界面表单
      管理员填写 git_url / token 等配置

Step 4: 启用适配器
  └── 管理界面点击 [启用] → status: "disabled" → "enabled"
      Indexer 自动触发首次全量索引

Step 5: 索引完成
  └── Discover() 返回节点 → Chunking → Embedding → Milvus Upsert
      rag_adapter_registry.node_count 更新 → 管理界面显示状态
```

## 二、Orion 原生集成（三层开关）

### 2.1 开关架构

```
┌─────────────────────────────────────────────────────────────────┐
│ Level 1: 系统级开关（全局）                                      │
│   入口: 控制台 → AI 平台 → RAG 引擎配置                          │
│   影响: 全局 — 所有租户                                         │
│   存储: unified_config (key: "rag.enabled")                     │
│   操作: 启用 / 停用                                              │
├─────────────────────────────────────────────────────────────────┤
│ Level 2: 租户级开关（按租户）                                    │
│   入口: 租户管理 → 功能订阅 → RAG                                │
│   影响: 仅该租户                                                │
│   存储: rag_tenant_quota.enabled                                │
│   操作: 启用 / 停用（按租户）                                    │
├─────────────────────────────────────────────────────────────────┤
│ Level 3: 适配器级开关（按数据源）                                │
│   入口: RAG 引擎配置 → 数据源管理                                 │
│   影响: 仅该数据源的索引                                        │
│   存储: rag_adapter_registry.status                             │
│   操作: 添加 / 启用 / 停用 / 删除                                │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 三级开关联动逻辑

```
用户请求 RAG:
  │
  ├── Level 1: 系统级开关是否启用？
  │   ├── 否 → 返回 "AI 助手功能已停用"
  │   └── 是 → 继续
  │
  ├── Level 2: 该租户是否启用？
  │   ├── 否 → 返回 "当前租户未启用 AI 助手，请联系管理员"
  │   └── 是 → 继续
  │
  ├── Level 3: 各适配器是否启用？
  │   ├── 全部停用 → 返回 "暂无可用知识数据源"
  │   └── 部分启用 → 仅检索已启用的适配器数据
  │
  └── 执行 RAG 查询
```

### 2.3 适配器注册表

```sql
CREATE TABLE rag_adapter_registry (
    adapter_name   VARCHAR(100) PRIMARY KEY,
    source_type    VARCHAR(30) NOT NULL,        -- orion/git/monitoring/ticket/external
    status         VARCHAR(20) DEFAULT 'enabled', -- enabled/disabled/syncing
    config         JSONB,                        -- 适配器配置
    node_count     INT DEFAULT 0,
    last_sync_at   TIMESTAMPTZ,
    health_status  VARCHAR(20) DEFAULT 'unknown', -- healthy/degraded/unreachable
    sync_interval  INT DEFAULT 3600,             -- 轮询间隔（秒），0 = 仅 CDC/Webhook
    created_at     TIMESTAMPTZ DEFAULT NOW(),
    updated_at     TIMESTAMPTZ DEFAULT NOW()
);
```

## 三、管理后台 API 设计

```
# RAG 引擎管理 API

# 系统级开关
GET  /rag/admin/status                  # 获取引擎状态
PUT  /rag/admin/enable                  # 启用引擎
PUT  /rag/admin/disable                 # 停用引擎

# 适配器管理
GET    /rag/admin/adapters              # 列出所有适配器
POST   /rag/admin/adapters              # 注册新适配器
GET    /rag/admin/adapters/:name        # 获取适配器详情
PUT    /rag/admin/adapters/:name/config # 更新配置
PUT    /rag/admin/adapters/:name/enable # 启用适配器
PUT    /rag/admin/adapters/:name/disable # 停用适配器
DELETE /rag/admin/adapters/:name        # 删除适配器
POST   /rag/admin/adapters/:name/sync   # 手动触发全量同步

# 租户级开关
GET  /rag/admin/tenants/:id/rag         # 获取租户 RAG 状态
PUT  /rag/admin/tenants/:id/rag/enable  # 启用租户 RAG
PUT  /rag/admin/tenants/:id/rag/disable # 停用租户 RAG

# 健康检查
GET  /rag/admin/health                  # 所有组件健康状态
GET  /rag/admin/adapters/:name/health   # 单个适配器健康状态
```

## 四、与现有 Orion 模块的集成点

| Orion 现有模块 | 集成方式 | 复用内容 |
|---------------|---------|---------|
| `capability` | RAG 作为 capability 注册 | 租户级功能订阅复用 capability 框架 |
| `plugin` | 适配器作为可插拔 plugin | Plugin 注册/卸载生命周期 |
| `unified-config` | 引擎配置存储 | 复用 `unified_config` 表的 key-value 结构 |
| `handler-registry` | 内置适配器数据源 | 9 条 API + handler_registry_entries 表 |
| `tenant` | 租户级开关 | 复用 tenant_id 传递和校验 |
| `feature-flag` | 特性开关 | 复用 feature-flag 的 A/B 实验能力 |
