## 二、缺口 1：语义缓存与 Milvus 迁移冲突（P1）

**问题**: 主设计 §16.2b 的语义缓存使用 pgvector HNSW 索引，但 V2.7 已将向量存储迁移到 Milvus。V2.5 P0-4 已修复了缓存缺少 `role_level` 的问题，但 V2.7 后缓存的向量引擎归属不清。

**现状分析**:
```
V2.5 定义: rag_semantic_cache 表（pgvector HNSW）
V2.7 定义: Milvus 作为唯一向量引擎
→ 冲突: 两套向量引擎并存
```

**修复方案**: 语义缓存移入 Milvus，作为独立 Collection。

```sql
-- 废弃: 主设计 §16.2b 中的 pgvector 语义缓存表
-- CREATE TABLE rag_semantic_cache ...

-- 新建: Milvus Collection rag_semantic_cache
Collection: rag_semantic_cache
字段:
  query_embedding: FloatVector(768)    -- 查询向量
  query_text:      Varchar(500)        -- 原始查询
  answer:          Varchar(5000)        -- 缓存答案
  citations:       Varchar(5000)        -- JSON citations
  graph_links:     Varchar(5000)        -- JSON graph_links
  tenant_id:       Varchar(255)        -- 租户（过滤）
  max_role_level:  Varchar(50)         -- 权限级别（解决 V2.5 P0-4）
  hit_count:       Int64               -- 命中次数
  created_at:      Int64               -- 创建时间
  expires_at:      Int64               -- 过期时间（24h TTL）

索引: HNSW (M=16, ef=256, COSINE)
```

缓存查找流程（含权限过滤）:
```go
func (c *Cache) Lookup(ctx context.Context, query string, tenantID, roleLevel string) (*CacheHit, error) {
    vec := c.embedding.Encode(query)

    results, err := c.milvus.Search(ctx, SearchRequest{
        TenantID:  tenantID,
        Embedding: vec,
        TopK:      1,
        // 权限过滤 + 过期过滤
        Filter: fmt.Sprintf("max_role_level <= '%s' && expires_at > %d", roleLevel, time.Now().Unix()),
    })
    if err != nil || len(results) == 0 {
        return nil, ErrCacheMiss
    }
    // 相似度阈值 0.92（distance < 0.08）
    if results[0].Distance > 0.08 {
        return nil, ErrCacheMiss
    }
    return &CacheHit{Answer: results[0].Answer, Citations: results[0].Citations}, nil
}
```

## 三、缺口 2：Milvus 宕机降级路径（P0）

**问题**: V2.7 引入 Milvus 后，向量检索从"同库 pgvector"变为"外部服务 Milvus"，宕机影响面显著扩大。主设计 §16.4 降级表未定义 Milvus 宕机场景。

**修复方案**: Circuit Breaker + 三级降级。

```
Milvus 宕机检测:
  • 每 10s 执行 Milvus Connect 探活（超时 2s）
  • 连续 3 次失败 → Circuit Breaker OPEN
  • OPEN 30s 后 → HALF_OPEN（单次探活）
  • 探活成功 → CLOSED（恢复）

三级降级:

  级别 1 — Milvus 宕机:
    检索: BM25(PostgreSQL) + Graph(PostgreSQL)
    权重: 0.65b + 0.35g
    前端提示: "⚠️ 向量检索服务暂不可用"
    告警: P1 → 通知 oncall

  级别 2 — Milvus + Embedding 同时宕机:
    检索: BM25(PostgreSQL) only
    权重: 1.0b
    前端提示: "⚠️ AI 检索服务降级中，结果可能不够精确"
    告警: P0 → 立即通知

  级别 3 — PostgreSQL 也宕机:
    检索: 无（完全降级）
    返回: 静态 FAQ 列表 + "系统维护中"
    告警: P0 → 立即通知
```

```go
type MilvusCircuitBreaker struct {
    state        CircuitState  // CLOSED / OPEN / HALF_OPEN
    failureCount int
    lastFailure  time.Time
    milvus       *milvus.Client
}

func (cb *MilvusCircuitBreaker) Search(ctx context.Context, req milvus.SearchRequest) ([]milvus.SearchResult, error) {
    switch cb.state {
    case CircuitOpen:
        if time.Since(cb.lastFailure) > 30*time.Second {
            cb.state = CircuitHalfOpen
        } else {
            return nil, ErrMilvusUnavailable
        }
    case CircuitHalfOpen:
        if err := cb.milvus.Ping(ctx); err != nil {
            cb.state = CircuitOpen
            cb.lastFailure = time.Now()
            return nil, ErrMilvusUnavailable
        }
        cb.state = CircuitClosed
        cb.failureCount = 0
    }
    results, err := cb.milvus.Search(ctx, req)
    if err != nil {
        cb.failureCount++
        if cb.failureCount >= 3 {
            cb.state = CircuitOpen
            cb.lastFailure = time.Now()
        }
        return nil, err
    }
    return results, nil
}
```

## 四、缺口 3：租户级限流与并发控制（P1）

**问题**: 主设计 §8 Layer 5 定义了用户级限流（30 次/分钟），但缺少：
- 租户级总配额（防止单租户耗尽所有 RAG 资源）
- 并发控制（防止单查询占满 LLM 推理）
- 优先级队列（故障排查场景应优先处理）

**修复方案**:

```go
// 租户级配额表
CREATE TABLE rag_tenant_quota (
    tenant_id           VARCHAR(255) PRIMARY KEY,
    max_queries_per_min INT DEFAULT 60,
    max_queries_per_hour INT DEFAULT 1000,
    max_concurrent      INT DEFAULT 5,
    max_context_tokens  INT DEFAULT 32000,
    tier                VARCHAR(20)  -- free / pro / enterprise
);

// 限流器实现（Redis，支持分布式）
func (rl *RateLimiter) Allow(ctx context.Context, tenantID, userID, tier string) (bool, int) {
    quota := GetQuota(tier)
    now := time.Now()

    // 租户级分钟限流
    minuteKey := fmt.Sprintf("rag:rate:tenant:%s:minute:%d", tenantID, now.Unix()/60)
    if rl.redis.Incr(ctx, minuteKey).Val() > int64(quota.MaxQueriesPerMin) {
        return false, 429
    }

    // 用户级并发限制
    concurrentKey := fmt.Sprintf("rag:concurrent:%s:%s", tenantID, userID)
    if rl.redis.SAdd(ctx, concurrentKey, time.Now().UnixNano()).Val() > int64(quota.MaxConcurrent) {
        return false, 503
    }
    return true, 200
}

// 优先级队列（故障排查优先）
type PriorityQueue struct {
    queues map[int]chan *RAGRequest  // 0=最高 → 3=最低
}

func roleToPriority(role string) int {
    switch role {
    case "admin":     return 0
    case "on-call":   return 1  // 值班中
    case "developer": return 2
    case "viewer":    return 3
    }
    return 2
}
```

## 五、缺口 4：模型热启动就绪探针（P1）

**问题**: 本地 ONNX 模型总计 ~2.6GB（bge-base-zh 700MB + Qwen2.5-3B 1.8GB + reranker 150MB），冷启动需 2-3 秒。服务启动后立即接收流量会导致前几秒的请求全部超时。

**修复方案**: ReadinessGates 顺序加载 + K8s 就绪探针。

```go
type ReadinessGates struct {
    embedding *Gate
    llm       *Gate
    reranker  *Gate
    milvus    *Gate
}

func (g *Gate) InitAndMarkReady() error {
    if err := g.loadFunc(); err != nil {
        return err
    }
    close(g.ready)  // 标记就绪
    return nil
}

// 启动顺序: embedding + reranker（并行）→ llm（串行）→ milvus（串行）
func (a *RAGAgent) Init(ctx context.Context) error {
    if err := a.gates.embedding.InitAndMarkReady(); err != nil { return err }
    if err := a.gates.reranker.InitAndMarkReady(); err != nil { return err }
    if err := a.gates.llm.InitAndMarkReady(); err != nil { return err }
    if err := a.gates.milvus.InitAndMarkReady(); err != nil { return err }
    a.ready = true
    return nil
}
```

K8s 配置:
```yaml
readinessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 10    # 给模型加载留 10s
  periodSeconds: 5
  failureThreshold: 6        # 10s + 30s = 40s 启动窗口
```

## 六、缺口 5：多轮对话上下文注入流程（P1）

**问题**: 主设计 §15.4 定义了多轮对话策略（5 轮上限 + 摘要），但未说明具体的上下文注入流程和 API 交互方式。

**修复方案**:

```go
func (a *RAGAgent) HandleQuery(ctx context.Context, req QueryRequest) (*QueryResponse, error) {
    // 1. 加载历史上下文
    var history []ConversationTurn
    if req.ConversationID != "" {
        history = a.conversationStore.GetHistory(ctx, req.ConversationID)
    }

    // 2. 执行检索（首轮和追问轮相同）
    retrieval := a.retriever.Search(ctx, req.Query, req.TenantID, 10)

    // 3. 构建 Prompt（首轮 vs 追问轮的区别）
    var prompt string
    if len(history) == 0 {
        // 首轮: 标准 prompt
        prompt = buildFirstTurnPrompt(req.Query, retrieval)
    } else {
        // 追问轮: 注入历史摘要 + 当前检索结果
        summary := a.summarizer.Summarize(ctx, history)  // 轻量模型, ~200 token
        prompt = buildFollowUpPrompt(req.Query, summary, retrieval)
        // 实体指代消解: "那个API" → "GET /pipeline/:id/run"
        resolved := a.entityResolver.Resolve(ctx, req.Query, history)
        prompt = injectResolvedEntities(prompt, resolved)
    }

    // 4. LLM 推理
    answer := a.llmRouter.Route(ctx, prompt)

    // 5. 保存到对话历史
    if req.ConversationID != "" {
        a.conversationStore.AppendTurn(ctx, ConversationTurn{
            ConversationID: req.ConversationID,
            Query:          req.Query,
            Answer:         answer,
            RetrievedNodes: retrieval.Nodes,
        })
    }
    return &QueryResponse{Answer: answer, ConversationID: req.ConversationID}, nil
}
```

```go
type ABRouter struct {
    redis *redis.Client
}

func (r *ABRouter) Route(ctx context.Context, userID string) ABGroup {
    key := "rag:ab:user:" + userID
    group, err := r.redis.Get(ctx, key).Result()
    if err == redis.Nil {
        group = "control"   // 对照组: 关闭反馈优化
        if rand.Intn(2) == 0 {
            group = "experiment"  // 实验组: 开启 Phase 1-4
        }
        r.redis.Set(ctx, key, group, 7*24*time.Hour)
    }
    return group
}

// RAG Agent 根据分组决定是否启用优化
func (a *RAGAgent) Query(ctx context.Context, req QueryRequest) *QueryResponse {
    group := a.abRouter.Route(ctx, req.UserID)

    retrieval := a.retriever.Search(ctx, req.Query, req.TenantID, 10)

    if group == "experiment" {
        retrieval = a.feedbackOptimizer.ApplyNodeWeights(ctx, retrieval)
    }

    answer := a.generate(ctx, retrieval)
    return &QueryResponse{Answer: answer, FeedbackToken: generateToken()}
}
```

## 八、Embedding 模型迁移策略（pgvector → Milvus）（P2）

**问题**: 主设计 §7.3 定义了模型版本管理，V2.7 切换 Milvus 后，从 pgvector 到 Milvus 的数据迁移方案缺失。

```go
func (m *Migrator) MigrateFromPgvector(ctx context.Context, pgDB *sql.DB, milvus *milvus.Client) error {
    // Step 1: 从 pgvector 读取所有向量
    rows, err := pgDB.QueryContext(ctx,
        `SELECT node_id, chunk_index, tenant_id, node_type,
                text, embedding::text, parent_id
         FROM rag_embeddings WHERE status = 'active'`)
    if err != nil { return err }
    defer rows.Close()

    // Step 2: 分批写入 Milvus
    var batch []milvus.UpsertRequest
    for rows.Next() {
        var row embeddingRow
        rows.Scan(&row.NodeID, &row.ChunkIndex, &row.TenantID,
            &row.NodeType, &row.Text, &row.EmbeddingText, &row.ParentID)

        embedding, _ := parseEmbeddingJSON(row.EmbeddingText)
        batch = append(batch, milvus.UpsertRequest{
            EntityID:  row.NodeID + "-" + strconv.Itoa(row.ChunkIndex),
            NodeType:  row.NodeType,
            TenantID:  row.TenantID,
            Embedding: embedding,
            Text:      row.Text,
            ParentID:  row.ParentID,
        })

        if len(batch) >= 1000 {
            milvus.UpsertBatch(ctx, batch)
            batch = nil
        }
    }
    if len(batch) > 0 {
        milvus.UpsertBatch(ctx, batch)
    }

    // Step 3: 标记 pgvector 表为 deprecated
    pgDB.ExecContext(ctx, `UPDATE rag_embeddings SET status = 'deprecated' WHERE status = 'active'`)
    return nil
}
```
