## 1. 概述

### 1.1 文档目的

本文档详细描述 Orion 平台引入 gRPC 作为服务间通信协议的整体设计方案。gRPC 作为高性能、开源的 RPC 框架，将为 Orion 平台提供低延迟、高吞吐的服务间通信能力，同时保持与现有 REST API 的兼容性。

### 1.2 适用范围

本文档适用于：
- 架构师：理解 gRPC 在整体架构中的定位
- 后端开发人员：实现 gRPC 服务和使用 gRPC 客户端
- 运维人员：配置和监控 gRPC 服务
- 测试人员：设计 gRPC 服务的测试策略

### 1.3 术语表

| 术语 | 定义 |
|------|------|
| gRPC | Google Remote Procedure Call，基于 HTTP/2 的高性能 RPC 框架 |
| Protocol Buffers | Google 开发的二进制序列化格式，gRPC 的默认消息格式 |
| mTLS | Mutual TLS，双向 TLS 认证 |
| Istio | 服务网格实现，提供服务发现、负载均衡、安全等功能 |
| 流式调用 | 客户端、服务端或双向持续发送消息的调用模式 |

## 2. 背景与用例

### 2.1 gRPC vs REST 对比

| 特性 | gRPC | REST/HTTP |
|------|------|-----------|
| 传输协议 | HTTP/2 | HTTP/1.1 或 HTTP/2 |
| 消息格式 | Protocol Buffers (二进制) | JSON/XML (文本) |
| 序列化效率 | 高 (3-10 倍于 JSON) | 较低 |
| 连接复用 | 原生支持 (多路复用) | 需要额外配置 |
| 流式支持 | 原生支持 (单向/双向) | 有限支持 (SSE/WebSocket) |
| 代码生成 | 自动生成客户端/服务端 | 通常手动编写 |
| 浏览器支持 | 需要 gRPC-Web 代理 | 原生支持 |
| 调试友好性 | 较低 (二进制) | 高 (可读文本) |
| 生态系统 | 成长中 | 成熟 |

### 2.2 gRPC 适用场景

#### 2.2.1 高频服务间调用

**场景描述**: Orion 平台内部服务之间存在大量高频调用，如配置中心查询、认证鉴权、元数据获取等。

**具体用例**:

| 调用方 | 被调用方 | 调用频率 | 延迟要求 | 选择 gRPC 理由 |
|--------|----------|----------|----------|----------------|
| API Gateway | Auth Service | 每次请求 | < 10ms | 减少认证开销 |
| 所有服务 | Config Service | 启动时 + 定期 | < 5ms | 配置热更新 |
| Scheduler | Worker Services | 任务触发时 | < 50ms | 任务快速分发 |
| Metrics Collector | 所有服务 | 每 15 秒 | < 100ms | 指标采集 |

**预期收益**:
- 序列化/反序列化开销降低 60-80%
- 连接复用减少 TCP 握手开销
- 整体 P99 延迟降低 40-60%

#### 2.2.2 流式用例

**场景一：实时日志流**

```
┌─────────────┐    日志流    ┌─────────────┐
│   Client    │◄─────────────│  Log Service│
│  (Browser)  │    HTTP/1.1  │  (Backend)  │
└─────────────┘              └─────────────┘
        ▲                          │
        │ gRPC-Web                 │ 采集
        │                          ▼
        │                  ┌─────────────┐
        └──────────────────│  Log Stream │
             双向流         │  Aggregator │
                           └─────────────┘
```

**场景描述**: 运维控制台需要实时展示服务日志，传统轮询方式延迟高、资源消耗大。

**gRPC 方案**:
- 客户端发起日志订阅请求
- 服务端持续推送匹配的日志条目
- 客户端可动态调整过滤条件 (双向流)

**场景二：指标监控流**

**场景描述**: 监控 dashboard 需要实时展示系统指标，如 CPU、内存、请求延迟等。

**gRPC 方案**:
- 指标采集服务建立到各服务的长连接
- 服务端按固定间隔推送指标数据
- 支持多个指标类型的多路复用

**场景三：配置变更通知**

**场景描述**: 配置变更需要实时通知到所有相关服务实例。

```
┌─────────────────────────────────────────────────────────┐
│                    Config Service                        │
│  ┌─────────────┐                                        │
│  │  Change     │──── 流式推送 ────►  Service A Instance 1│
│  │  Detector   │                  ►  Service A Instance 2│
│  └─────────────┘                  ►  Service B Instance 1│
│                                    ►  Service B Instance 2│
└─────────────────────────────────────────────────────────┘
```

#### 2.2.3 低延迟要求场景

| 场景 | 当前 REST 延迟 | gRPC 目标延迟 | 延迟组成优化 |
|------|---------------|---------------|--------------|
| 认证校验 | 15-25ms | 5-10ms | 序列化 + 连接复用 |
| 数据库路由查询 | 10-20ms | 3-5ms | 二进制协议 |
| 分布式锁获取 | 20-30ms | 8-12ms | HTTP/2 多路复用 |
| 跨服务事务协调 | 50-100ms | 20-40ms | 减少往返次数 |

### 2.3 REST 继续使用场景

**2.3.1 外部 API 暴露**

- **开放平台 API**: 第三方集成商使用的 API 保持 REST 风格
- **Webhook 回调**: 向外发送的事件通知使用 HTTP POST
- **公共文档**: OpenAPI/Swagger 文档面向外部开发者

**2.3.2 浏览器直接访问**

- **前端资源**: 静态资源、GraphQL (如使用) 保持 HTTP
- **文件上传/下载**: 大文件传输使用 REST + Range Requests
- **CORS 场景**: 跨域请求保持 REST 简化配置

**2.3.3 调试和运维接口**

- **健康检查**: `/health`, `/ready` 端点保持 REST
- **管理接口**: 简单的 CRUD 操作保持 REST
- **调试端点**: `/debug/*` 保持文本格式便于排查

### 2.4 决策矩阵

```
                          ┌──────────────────────────────────────┐
                          │        是否需要以下任一特性？         │
                          │  • 高频调用 (>1000 QPS)              │

                          └─────────────────┬────────────────────┘
                                            │
                    ┌───────────────────────┴───────────────────────┐
                    │                      │                        │
                   是                     不确定                    否
                    │                      │                        │
                    ▼                      ▼                        ▼
          ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
          │   优先使用 gRPC  │    │ 评估具体场景    │    │   继续使用 REST │
          │                 │    │ - 延迟敏感度    │    │                 │
```

## 3. 服务接口定义

### 3.1 认证服务 (AuthService)

#### 3.1.1 服务概述

**服务名称**: `AuthService`

**服务目的**: 提供统一的身份认证和令牌管理能力，供 API Gateway 和其他服务调用进行请求认证。

**调用模式**: 一元调用 (Unary)

#### 3.1.2 方法定义

**方法一：ValidateToken (令牌验证)**

| 属性 | 描述 |
|------|------|
| 方法名 | `ValidateToken` |
| 功能描述 | 验证传入的访问令牌是否有效，返回令牌关联的用户信息和权限 |
| 调用模式 | 一元 (客户端发送请求，服务端返回响应) |
| 超时设置 | 500ms |
| 幂等性 | 是 (只读操作) |

**请求消息字段说明**:

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| token | 字符串 | 是 | JWT 格式的访问令牌 |
| required_scopes | 字符串列表 | 否 | 需要验证的权限范围列表 |
| client_id | 字符串 | 否 | 调用方客户端标识，用于审计 |

**响应消息字段说明**:

| 字段名 | 类型 | 描述 |
|--------|------|------|
| valid | 布尔值 | 令牌是否有效 |
| user_id | 字符串 | 用户唯一标识 (仅当 valid=true) |
| tenant_id | 字符串 | 租户唯一标识 (仅当 valid=true) |
| scopes | 字符串列表 | 令牌拥有的权限范围 (仅当 valid=true) |
| expires_at | 时间戳 | 令牌过期时间 (仅当 valid=true) |
| error_code | 枚举 | 无效时的错误代码 |

**方法二：RefreshToken (令牌刷新)**

| 属性 | 描述 |
|------|------|
| 方法名 | `RefreshToken` |
| 功能描述 | 使用刷新令牌获取新的访问令牌 |
| 调用模式 | 一元 |
| 超时设置 | 1s |
| 幂等性 | 否 (每次调用生成新令牌) |

**请求消息字段说明**:

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| refresh_token | 字符串 | 是 | 刷新令牌 |
| grant_type | 字符串 | 是 | 授权类型，固定为 "refresh_token" |

**响应消息字段说明**:

| 字段名 | 类型 | 描述 |
|--------|------|------|
| access_token | 字符串 | 新的访问令牌 |
| refresh_token | 字符串 | 新的刷新令牌 (轮换策略) |
| expires_in | 整数 | 访问令牌有效期 (秒) |
| token_type | 字符串 | 令牌类型，固定为 "Bearer" |

#### 3.1.3 错误处理

| 错误代码 | HTTP 映射 | 描述 | 处理建议 |
|----------|-----------|------|----------|
| INVALID_TOKEN | UNAUTHENTICATED | 令牌格式无效或已过期 | 客户端应引导用户重新登录 |
| TOKEN_EXPIRED | UNAUTHENTICATED | 令牌已过期 | 客户端尝试刷新令牌 |
| INSUFFICIENT_SCOPE | PERMISSION_DENIED | 令牌权限不足 | 检查请求是否需要额外授权 |
| SERVICE_UNAVAILABLE | UNAVAILABLE | 认证服务不可用 | 实施降级策略或重试 |

### 3.2 配置服务 (ConfigService)

#### 3.2.1 服务概述

**服务名称**: `ConfigService`

**服务目的**: 提供配置项的读取、订阅和变更通知能力，支持配置热更新。

**调用模式**: 一元调用 + 服务端流式调用

#### 3.2.2 方法定义

**方法一：GetConfig (获取配置)**

| 属性 | 描述 |
|------|------|
| 方法名 | `GetConfig` |
| 功能描述 | 获取指定配置项的当前值 |
| 调用模式 | 一元 |
| 超时设置 | 200ms |
| 缓存建议 | 客户端可缓存 5 分钟 |

**请求消息字段说明**:

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| key | 字符串 | 是 | 配置项键名，支持层级路径如 "database.primary.host" |
| namespace | 字符串 | 否 | 配置命名空间，默认为 "default" |
| tenant_id | 字符串 | 否 | 租户标识，用于多租户配置隔离 |

**响应消息字段说明**:

| 字段名 | 类型 | 描述 |
|--------|------|------|
| value | 字符串 | 配置值 (JSON 格式) |
| version | 字符串 | 配置版本号，用于乐观锁 |
| last_modified | 时间戳 | 最后修改时间 |
| data_type | 枚举 | 配置值类型 (STRING, NUMBER, BOOLEAN, JSON) |

**方法二：WatchConfig (监听配置变更)**

| 属性 | 描述 |
|------|------|
| 方法名 | `WatchConfig` |
| 功能描述 | 建立长连接，服务端在配置变更时主动推送通知 |
| 调用模式 | 服务端流式 (Server Streaming) |
| 超时设置 | 无 (长连接) |
| 心跳间隔 | 30 秒 |

**请求消息字段说明**:

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| keys | 字符串列表 | 是 | 需要监听的配置项键名列表 |
| namespace | 字符串 | 否 | 配置命名空间 |
| tenant_id | 字符串 | 否 | 租户标识 |
| current_versions | 键值映射 | 否 | 当前各配置项的版本号 |

**响应消息字段说明** (每次推送):

| 字段名 | 类型 | 描述 |
|--------|------|------|
| key | 字符串 | 变更的配置项键名 |
| new_value | 字符串 | 变更后的配置值 |
| old_value | 字符串 | 变更前的配置值 (可选) |
| version | 字符串 | 新版本号 |
| change_type | 枚举 | 变更类型 (CREATED, UPDATED, DELETED) |

**方法三：BatchGetConfig (批量获取配置)**

| 属性 | 描述 |
|------|------|
| 方法名 | `BatchGetConfig` |
| 功能描述 | 一次性获取多个配置项，减少网络往返 |
| 调用模式 | 一元 |
| 超时设置 | 500ms |

**请求消息字段说明**:

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| keys | 字符串列表 | 是 | 配置项键名列表 |
| namespace | 字符串 | 否 | 配置命名空间 |

**响应消息字段说明**:

| 字段名 | 类型 | 描述 |
|--------|------|------|
| configs | 配置项列表 | 每个配置项包含键、值、版本等信息 |
| not_found_keys | 字符串列表 | 未找到的配置项键名 |

### 3.3 日志服务 (LogService)

#### 3.3.1 服务概述

**服务名称**: `LogService`

**服务目的**: 提供日志的采集、聚合、查询和实时流式推送能力。

**调用模式**: 客户端流式 + 服务端流式 + 双向流式

#### 3.3.2 方法定义

**方法一：IngestLogs (日志采集)**

| 属性 | 描述 |
|------|------|
| 方法名 | `IngestLogs` |
| 功能描述 | 接收服务实例发送的日志批次 |
| 调用模式 | 客户端流式 (Client Streaming) |
| 超时设置 | 5s |
| 批次建议 | 每批次 100-1000 条，或每 100ms 发送 |

**请求消息字段说明** (每条日志):

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| timestamp | 时间戳 | 是 | 日志产生时间 |
| level | 枚举 | 是 | 日志级别 (DEBUG, INFO, WARN, ERROR, FATAL) |
| service | 字符串 | 是 | 服务名称 |
| instance_id | 字符串 | 是 | 服务实例标识 |
| trace_id | 字符串 | 否 | 分布式追踪 ID |
| span_id | 字符串 | 否 | 追踪跨度 ID |
| message | 字符串 | 是 | 日志内容 |
| fields | 键值列表 | 否 | 结构化字段 |
| labels | 键值列表 | 否 | 标签用于过滤 |

**响应消息字段说明**:

| 字段名 | 类型 | 描述 |
|--------|------|------|
| accepted_count | 整数 | 成功接收的日志条数 |
| rejected_count | 整数 | 被拒绝的日志条数 |
| rejected_reasons | 字符串列表 | 拒绝原因列表 |

**方法二：StreamLogs (日志流)**

| 属性 | 描述 |
|------|------|
| 方法名 | `StreamLogs` |
| 功能描述 | 实时推送匹配的日志条目到客户端 |
| 调用模式 | 服务端流式 (Server Streaming) |
| 超时设置 | 无 (长连接) |
| 并发限制 | 每客户端最多 5 个流 |

**请求消息字段说明**:

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| query | 字符串 | 是 | 查询表达式，支持关键词、级别、时间范围 |
| services | 字符串列表 | 否 | 过滤的服务列表 |
| levels | 枚举列表 | 否 | 过滤的日志级别 |
| start_time | 时间戳 | 否 | 开始时间 (用于历史回溯) |
| tail | 整数 | 否 | 仅返回最近 N 条 (替代 start_time) |

**响应消息字段说明** (每条推送):

| 字段名 | 类型 | 描述 |
|--------|------|------|
| log_entry | 日志对象 | 完整的日志条目 |
| sequence | 整数 | 流内序列号，用于检测丢失 |

**方法三：QueryLogs (日志查询)**

| 属性 | 描述 |
|------|------|
| 方法名 | `QueryLogs` |
| 功能描述 | 执行日志查询，返回匹配的结果集 |
| 调用模式 | 一元 |
| 超时设置 | 10s (复杂查询可能更长) |

**请求消息字段说明**:

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|
| query | 字符串 | 是 | 查询表达式 |
| time_range | 时间范围 | 是 | 查询时间范围 |
| limit | 整数 | 否 | 返回数量上限，默认 100 |
| offset | 整数 | 否 | 偏移量，用于分页 |
| order | 枚举 | 否 | 排序方向 (ASC, DESC) |

**响应消息字段说明**:

| 字段名 | 类型 | 描述 |
|--------|------|------|
| entries | 日志列表 | 匹配的日志条目 |
| total_count | 整数 | 匹配总数 (用于分页) |
| has_more | 布尔值 | 是否还有更多结果 |
| scanned_bytes | 整数 | 扫描的数据量 (用于计费) |

### 3.4 指标服务 (MetricsService)

**服务名称**: `MetricsService`

#### 3.4.2 方法定义

**方法一：ReportMetrics (指标上报)**

|------|------|

**响应消息字段说明**:

| 字段名 | 类型 | 描述 |
|--------|------|------|
| status | 枚举 | 上报状态 (OK, PARTIAL, REJECTED) |

**方法二：StreamMetrics (指标流)**

| 属性 | 描述 |
|------|------|
| 方法名 | `StreamMetrics` |
| 功能描述 | 实时推送指定指标的最新值 |
| 调用模式 | 服务端流式 (Server Streaming) |
| 超时设置 | 无 (长连接) |
| 推送间隔 | 可配置，默认 1s |

**请求消息字段说明**:

| 字段名 | 类型 | 必填 | 描述 |
|--------|------|------|------|

| labels_filter | 键值列表 | 否 | 标签过滤条件 |

**响应消息字段说明** (每次推送):

| 字段名 | 类型 | 描述 |
|--------|------|------|
| metric_name | 字符串 | 指标名称 |
| value | 数值 | 指标值 |
| timestamp | 时间戳 | 数据时间 |
| labels | 键值列表 | 指标标签 |

**方法三：QueryMetrics (指标查询)**

| 属性 | 描述 |
|------|------|
| 方法名 | `QueryMetrics` |
| 功能描述 | 执行指标查询，支持 PromQL 类查询语言 |
| 调用模式 | 一元 |
| 超时设置 | 5s |

### 3.6 错误处理通用规范

#### 3.6.1 gRPC 状态码使用规范

| gRPC 状态码 | 使用场景 | 示例 |
|-------------|----------|------|

| PERMISSION_DENIED | 权限不足 | 令牌无权访问该资源 |
| UNAUTHENTICATED | 未认证 | 令牌无效或缺失 |
| RESOURCE_EXHAUSTED | 资源耗尽 | 配额用尽、连接数超限 |
| FAILED_PRECONDITION | 前置条件不满足 | 服务未初始化完成 |
| ABORTED | 操作中止 | 乐观锁冲突 |
| OUT_OF_RANGE | 超出范围 | 分页偏移量超出总数 |
| UNIMPLEMENTED | 未实现 | 调用了未实现的方法 |
| INTERNAL | 内部错误 | 服务端未知错误 |
| UNAVAILABLE | 服务不可用 | 服务过载、依赖不可用 |
| DATA_LOSS | 数据丢失 | 数据损坏 |

| 字段 | 类型 | 描述 |
|------|------|------|

| message | 字符串 | 人类可读的错误描述 |
| details | 键值列表 | 额外的调试信息 |
| retryable | 布尔值 | 是否可重试 |
| retry_after_ms | 整数 | 建议的重试延迟 (毫秒) |

| 步骤 | 执行方 | 动作 |

#### 5.1.1 认证方式

### 5.3 授权策略

#### 5.3.1 授权模型

```
┌─────────────────────────────────────────────────────────────────────┐
│                        授权决策流程                                  │
│                                                                     │
│   请求到达 ──► 认证 ──► 提取属性 ──► 匹配策略 ──► 允许/拒绝            │
│                │         │            │                             │
│                ▼         ▼            ▼                             │
│           身份验证    属性收集    策略评估                            │
│           • Token     • 来源服务   • 基于规则                         │
│           • mTLS      • 目标方法   • 基于属性                         │
│                       • 请求时间   • 基于角色                         │
│                       • 用户角色                                      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 5.3.2 授权策略示例

| 策略名称 | 适用服务 | 规则描述 |
|----------|----------|----------|
| allow-auth-service | 所有服务 | 允许 Auth Service 调用任何方法 |
| allow-internal-only | Config Service | 仅允许集群内服务调用 |
| deny-external | Admin Service | 拒绝所有外部来源 |
| require-admin-role | Admin Service | 需要 admin 角色 |

#### 5.3.3 AuthorizationPolicy 配置要素

```
策略配置包含:
- selector: 适用的工作负载
- action: ALLOW / DENY / AUDIT / CUSTOM
- rules:
  - from: 来源条件 (principals, namespaces)
  - to: 目标条件 (methods, paths)
  - when: 附加条件 (时间、请求属性)
```

### 5.4 安全最佳实践

| 实践 | 描述 | 优先级 |
|------|------|--------|
| 始终启用 mTLS | 服务间通信强制加密 | 高 |
| 最小权限原则 | 服务只拥有必要的权限 | 高 |
| 定期轮换凭证 | Token 和证书定期更新 | 高 |
| 审计日志 | 记录所有授权决策 | 中 |
| 速率限制 | 防止暴力破解和 DDoS | 中 |
| 输入验证 | 服务端验证所有输入 | 高 |

### 6.4 版本管理策略

#### 6.4.1 版本控制原则

| 原则 | 描述 |
|------|------|
| 向后兼容 | 新服务端必须兼容旧客户端 |
| 渐进发布 | 支持多版本并存，逐步迁移 |
| 明确弃用 | 弃用字段/方法明确标记，提供迁移期 |
| 版本协商 | 支持客户端和服务端协商版本 |

#### 6.4.2 兼容性规则

| 变更类型 | 兼容性 | 处理方式 |
|----------|--------|----------|
| 添加新字段 | 向后兼容 | 新字段设为可选，有默认值 |
| 删除字段 | 不兼容 | 先标记 deprecated，下一版本删除 |
| 重命名字段 | 不兼容 | 等同于删除 + 新增 |
| 修改字段类型 | 不兼容 | 需要版本升级 |
| 添加新方法 | 向后兼容 | 不影响现有客户端 |
| 删除方法 | 不兼容 | 先标记 deprecated |
| 修改方法签名 | 不兼容 | 创建新方法，弃用旧方法 |

#### 6.4.3 版本迁移流程

```
Phase 1: 准备
  - 新版本 proto 定义完成
  - 客户端和服务端代码生成
  - 测试验证通过

Phase 2: 部署 (向后兼容)
  - 部署新版本服务端
  - 旧客户端继续工作
  - 监控错误率

Phase 3: 迁移
  - 逐步升级客户端
  - 验证新功能
  - 监控性能指标

Phase 4: 清理
  - 所有客户端升级完成
  - 移除 deprecated 代码
  - 更新文档
```

```
健康状态枚举:
```

### 7.1 迁移优先级评估

#### 7.1.1 候选服务评估矩阵

| 服务/端点 | 当前 QPS | 平均延迟 | gRPC 收益 | 迁移复杂度 | 优先级 |
|-----------|----------|----------|-----------|------------|--------|

| Log.Ingest | 10000+ | 20ms | 高 | 中 | P0 |

#### 7.1.2 迁移标准

```
P0 (首批迁移):
  - QPS > 1000
  - 延迟敏感 (< 20ms 要求)
  - 服务内部调用
  - 迁移复杂度低

P1 (第二批):
  - QPS > 500
  - 有流式需求
  - 迁移复杂度中

P2 (后续批次):
  - QPS < 500
  - REST 已满足需求
  - 迁移复杂度高
```

#### 7.2.2 流量切换策略

```
Phase 1: 双写 (100% REST, 0% gRPC)
  - gRPC 服务部署完成
  - 仅内部测试流量
  - 监控 gRPC 错误率

Phase 2: 金丝雀 (95% REST, 5% gRPC)
  - 选择特定用户/服务
  - 对比 REST 和 gRPC 指标
  - 验证功能正确性

Phase 3: 逐步迁移 (50% REST, 50% gRPC)
  - 扩大 gRPC 流量比例
  - 持续监控
  - 准备回滚

Phase 4: 主要流量 (5% REST, 95% gRPC)
  - 仅遗留客户端使用 REST
  - gRPC 成为主要协议
  - 准备下线 REST

Phase 5: REST 下线 (0% REST, 100% gRPC)
  - 确认无 REST 流量
  - 移除 REST 端点
  - 清理相关代码
```

### A.2 流式通信模式

```
一元调用 (Unary):
  Client ────Request────► Server
  Client ◄───Response──── Server

服务端流式 (Server Streaming):
  Client ────Request────► Server
  Client ◄───Response 1── Server
  Client ◄───Response 2── Server
  Client ◄───Response 3── Server
  Client ◄───Response N── Server

客户端流式 (Client Streaming):
  Client ────Request 1──► Server
  Client ────Request 2──► Server
  Client ────Request 3──► Server
  Client ────Request N──► Server
  Client ◄───Response──── Server

双向流式 (Bidirectional Streaming):
  Client ────Request 1──► Server
  Client ◄───Response 1── Server
  Client ────Request 2──► Server
  Client ◄───Response 2── Server
  Client ────Request 3──► Server
  Client ◄───Response 3── Server
```
