# Orion 微服务拆分 + 微前端架构设计

---

## 一、核心原则

```
不是所有模块都需要独立微服务。拆分标准:

✅ 拆为独立微服务:
   - 独立扩展需求 (AI 推理 vs 流水线)
   - 独立技术栈 (Python AI vs Java 业务)
   - 独立部署频率 (CMDB 月更 vs 流水线日更)
   - 独立团队负责 (SRE 管 CMDB vs 平台管流水线)

❌ 合并为同一服务:
   - 数据强耦合 (工具管理 + 插件扩展)
   - 调用频繁 (流水线 + 构建环境)
   - 同一团队维护 (工单 + 排单)
   - 规模较小 (通知协作 + 多租户)
```

    ai-service → insight: "AI 建议事件"

## 三、前端微服务架构 (微前端)

### 3.1 架构选型

```
推荐: vite-plugin-federation (Module Federation)
理由:
  - 与 Vue3 + Vite 技术栈原生兼容
  - 子应用可独立运行和部署
  - 性能优于 qiankun (无沙箱开销)
  - 模块级共享，减少重复依赖
```

### 3.5 子应用独立运行

```typescript
// 每个子应用的 main.ts 都支持独立运行
const isStandalone = !window.__POWERED_BY_ORION_BASE__

if (isStandalone) {
  // 独立运行: 挂载完整应用 (带导航和登录)
  const app = createApp(App)
  app.use(ArcoVue)
  app.use(router)
  app.use(store)
  app.mount('#app')
} else {
  // 作为子应用: 暴露生命周期钩子
  export async function bootstrap() { ... }
  export async function mount(props: any) {
    const app = createApp(App)
    app.config.globalProperties.$user = props.user
    app.config.globalProperties.$permissions = props.permissions
    app.mount('#sub-app-container')
  }
  export async function unmount() { ... }
}
```

| 维度 | 拆分前 | 拆分后 |
|------|--------|--------|
| 后端服务 | 单体应用 | 8 个微服务 |
| 前端应用 | 单体前端 | 1 基座 + 7 子应用 |
| 独立部署 | ❌ 全量部署 | ✅ 每个服务/子应用独立部署 |
| 独立开发 | ❌ 代码冲突 | ✅ Monorepo 独立开发 |
| 独立运行 | ❌ 必须全量启动 | ✅ 每个子应用可独立运行 |

| 团队并行 | ❌ 串行开发 | ✅ 7 个团队并行开发 |
| 故障隔离 | ❌ 一个模块挂了全挂 | ✅ 服务级故障隔离 |
| 技术栈 | ❌ 统一 | ✅ AI 用 Python，业务用 Java |

**核心理念: 每个子应用是一个完整的应用程序，可以独立开发、独立运行、独立部署。基座只负责导航和加载，不关心子应用的内部实现。**

## 七、P0 架构修复更新（2026-04-10）

### 7.1 核心域与支撑域划分

**原 8 微服务重构为核心域 + 支撑域**：

**核心域服务**（高频迭代、直接面向研发）：
- orion-pipeline-service（流水线服务）
- orion-build-env-service（构建环境）
- orion-toolchain-service（多工具链）
- orion-code-management-service（代码管理）
- orion-config-management-service（配置管理）

**支撑域服务**（按需迭代、能力增强）：
- orion-ai-service（AI 增强域）
- orion-insight-service（效能洞察域）
- orion-finops-service（成本优化域）
- orion-cmdb-service（基础设施域）
- orion-workflow-service（运维治理域）
- orion-ticket-service（工单协同域）
- orion-knowledge-service（知识管理域）

### 7.2 调用规则更新

| 调用方向 | 原架构 | 重构后 |
|---------|--------|--------|
| 服务间通信 | REST/gRPC 网状调用 | 核心域→支撑域允许同步 |
| 支撑域→核心域 | 允许 | 仅事件订阅，禁止同步 |
| 支撑域↔支撑域 | 允许 | 禁止直接调用 |

### 7.3 部署独立性

**重构前**：8 个微服务需同时部署，发布周期长

**重构后**：
- 最小部署：5 分钟（仅核心域）
- 增量部署：单域部署不影响其他域

### 7.4 技术栈解耦

|---|---|---|
| 核心域 | Java/Spring Boot | 是 |
| AI 增强域 | Python/FastAPI | 是（GPU） |
| 效能洞察域 | Java/React | 否 |
| CMDB | Java/Spring Boot | 否 |
