## 一、服务拆分与依赖关系矩阵

### 1.1 服务依赖图

```

│                                                                 │
│  orion-api-gateway (网关)                                        │
│  ├── 无后端服务依赖                                              │
│  └── 依赖: Redis (会话缓存)                                      │
│                                                                 │
│  orion-platform-service (平台服务)                               │
│  ├── 无后端服务依赖                                              │
│  └── 依赖: PostgreSQL, Redis                                    │
│                                                                 │
│  orion-ai-service (AI 服务)                                     │

│  ├── 服务依赖: orion-platform-service (获取团队/标签)            │

│  orion-pipeline-service (流水线服务)                             │

│  │                    orion-ai-service (诊断)                    │

│  orion-ticket-service (工单服务)                                 │
│  ├── 服务依赖: orion-ai-service (NLP 理解)                       │

│  └── 数据依赖: PostgreSQL, Redis                                │
│                                                                 │
│  orion-insight-service (效能洞察服务)                            │

│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 依赖层级

```
层级 0: 无服务依赖 (可最先启动)
├── orion-api-gateway
└── orion-platform-service

层级 1: 依赖层级 0 的服务
├── orion-ai-service      (依赖 platform)
└── orion-cmdb-service    (依赖 platform)

层级 2: 依赖层级 0-1 的服务
├── orion-pipeline-service  (依赖 cmdb + ai + platform)
└── orion-insight-service   (依赖 platform)

层级 3: 依赖层级 0-2 的服务
├── orion-workflow-service  (依赖 cmdb + ai + ticket)
└── orion-ticket-service    (依赖 ai + workflow)
```

## 二、数据库表划分

### 2.1 数据库分配策略

```
数据隔离原则:
├── 每个服务拥有自己的数据库/Schema
├── 禁止跨服务直接访问数据库
├── 服务间数据通过 API 或事件获取
├── 共享数据通过 orion-platform-service 统一管理
└── Orion-Knowledge 使用独立 PostgreSQL，与主系统物理隔离
```

### 2.2 各服务数据库表详细划分

-- 变更历史
CREATE TABLE change_history (
    id BIGINT PRIMARY KEY,
    entity_type VARCHAR(50),  -- server/application/script

## 六、总结

| 维度 | 详情 |
|------|------|
| 后端服务 | 8 个微服务 + 1 可插拔模块 (Orion-Knowledge) |
| 前端应用 | 1 基座 + 7 子应用 + 2 知识库前端 |
| 数据库 | 7 个独立数据库 + 1 知识库独立 PostgreSQL |
| Redis | 按服务前缀隔离 (orion:{service}:) |
| 最小部署 | 2 服务 + 2 数据库 (~5 分钟) |
| 标准部署 | 5 服务 + 4 数据库 (~15 分钟) |
| 全量部署 | 8 服务 + 7 数据库 + 8 前端 (~25 分钟) |
| 知识库部署 | 独立 docker-compose，可与主系统并行或后部署 |
| 增量部署 | 1 服务 + 1 前端 (~3 分钟, 零停机) |
| 表分区 | audit_logs/cost_records/alert_records/pipeline_runs 按月分区 |

**核心原则: 每个服务拥有独立数据库, 通过 API 而非直接访问数据库进行服务间通信, 部署按依赖层级顺序进行。**
