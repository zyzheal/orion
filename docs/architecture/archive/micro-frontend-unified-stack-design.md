## 1. 现状分析

### 1.1 当前各子应用技术栈清单

Orion 平台当前采用微前端架构，包含多个独立子应用。经调研，各子应用技术栈情况如下：

```
+------------------+------------+---------------+------------------+------------------+
| 子应用名称       | 框架版本   | UI 组件库      | 状态管理          | 构建工具         |
+------------------+------------+---------------+------------------+------------------+
| 控制台           | Vue 3.3    | Ant Design Vue| Pinia            | Vite 5.x         |
| 监控中心         | React 18   | Ant Design    | Redux Toolkit    | Webpack 5        |
| 配置管理         | Vue 3.2    | Element Plus  | Vuex 4           | Vite 4.x         |
| 自动化运维       | React 17   | MUI 5         | Zustand          | Webpack 4        |
| 事件中心         | Vue 2.7    | Arco Design   | Vuex 3           | Webpack 5        |
| 知识库           | React 18   | Arco Design   | Jotai            | Vite 5.x         |
| 协作中心         | Vue 3.3    | 自研组件       | Pinia            | Vite 5.x         |
| 报表中心         | React 18   | Ant Design    | Recoil           | Webpack 5        |
+------------------+------------+---------------+------------------+------------------+
```

### 1.2 技术栈分布统计

```
框架分布:
  Vue 系列 (Vue 2.7 + Vue 3.x): 50% (4/8)
  React 系列 (React 17 + React 18): 50% (4/8)

UI 组件库分布:
  Ant Design / Ant Design Vue: 37.5% (3/8)
  Arco Design: 25% (2/8)
  Element Plus: 12.5% (1/8)
  MUI: 12.5% (1/8)
  自研组件: 12.5% (1/8)

状态管理分布:
  Pinia/Vuex: 50% (4/8)
  Redux/Zustand/Jotai/Recoil: 50% (4/8)

构建工具分布:
  Vite: 50% (4/8)
  Webpack: 50% (4/8)
```

### 1.3 核心问题与风险

#### 1.3.1 组件无法复用

```
问题描述:
  由于 Vue 和 React 组件模型完全不同，相同的业务组件需要在两个框架中
  分别实现，导致:
  
  - 重复开发成本：每个通用组件开发工作量 x2
  - 维护成本翻倍：bug 修复、功能更新需要双份工作
  - 行为不一致风险：同一组件在两个框架中可能出现细微差异
  
影响范围:
  - 当前已识别的重复组件：Table、Form、Modal、Select、Tree 等 20+ 个基础组件
  - 业务组件重复率：约 60%
```

#### 1.3.2 视觉风格不一致

```
问题描述:
  各 UI 库的 Design Tokens 体系独立，导致:
  
  - 色彩系统：各库主色调、辅助色定义不一致
  - 间距系统：4px/8px 基准不统一
  - 圆角规范：2px/4px/8px 混用
  - 字体规范：字号、行高、字重存在差异
  
视觉问题示例:
  [控制台] 按钮圆角 4px    [监控中心] 按钮圆角 6px
  [配置管理] 主色 #1890ff  [自动化运维] 主色 #1677ff
  [事件中心] 行高 1.5      [知识库] 行高 1.57
```

#### 1.3.3 学习成本高

```
问题描述:
  开发人员需要在不同子应用间切换技术栈:
  
  - 新成员 onboarding 时间：从 2 周延长至 4-6 周
  - 跨子应用协作：需要同时理解 Vue 和 React 生态
  - 代码审查： reviewer 需要熟悉两种技术栈
```

#### 1.3.4 技术债务累积

```
问题描述:
  - Vue 2.7 已停止官方支持，存在安全风险
  - React 17 部分 API 已标记为 Legacy
  - Webpack 4 构建速度慢，不支持新特性
  - Vuex 3/4 与 Pinia API 不兼容
```

#### 1.3.5 微前端集成复杂

```
问题描述:
  不同技术栈的微前端集成方案复杂:
  
  - 样式隔离：Vue 和 React 的样式处理方式不同
  - 状态共享：跨框架状态同步困难
  - 路由冲突：Vue Router 和 React Router 机制不同
  - 公共依赖：无法有效共享 node_modules
```

## 3. 统一 UI 组件库

### 3.1 Design Tokens 体系

Design Tokens 是设计系统的最小单位，用于存储设计决策值。Orion 将建立统一的 Design Tokens 体系，确保所有子应用视觉一致性。

#### 3.1.1 Token 分类体系

```
Design Tokens
│
├── Global Tokens (原始值)
│   ├── colors.primitive.blue.500: #1890ff
│   ├── colors.primitive.gray.100: #f5f5f5
│   ├── spacing.unit: 4px
│   └── font.size.base: 14px
│
├── Alias Tokens (语义化命名)
│   ├── colors.background.primary: {colors.primitive.white}
│   ├── colors.text.primary: {colors.primitive.gray.900}
│   ├── colors.brand.primary: {colors.primitive.blue.600}
│   └── spacing.small: {spacing.unit * 2}
│
└── Component Tokens (组件特定)
    ├── button.borderRadius: {borderRadius.md}
    ├── button.paddingX: {spacing.medium}
    ├── input.height: {spacing.xl * 8}
    └── table.rowHoverBg: {colors.background.secondary}
```

## 5. 迁移策略

### 5.1 迁移原则

```
1. 渐进式迁移
   - 不推翻重来，保留现有业务功能
   - 分阶段、分批次迁移，降低风险
   - 新旧并存，逐步切换

2. 业务优先
   - 优先迁移低频、低风险子应用
   - 核心业务应用最后迁移
   - 每次迁移必须通过完整测试

3. 可回滚
   - 每个阶段保留回滚方案
   - 灰度发布，小流量验证
   - 监控告警，快速发现问题

4. 并行开发
   - 迁移期间新功能正常迭代
   - 建立迁移专用分支
   - 定期合并主分支变更
```

#### 6.1.3 组件开发规范

```

   - 组件导出：与文件名一致
   - Hook 函数：use 前缀 (useUserList)
   - 工具函数：camelCase (formatDate)
   - 类型定义：PascalCase + T 后缀 (UserT, UserListParamsT)

   - 必须定义 Props 类型接口
   - 必填属性不加问号，选填加问号
   - 使用 children 属性需谨慎
   - 事件回调统一 on 前缀 + 动词

3. 代码结构:
   - 优先使用函数组件
   - 逻辑抽取为自定义 Hooks
   - 大组件拆分小组件
   - 单一职责原则

4. 样式规范:
   - 使用 CSS Modules 或 Emotion
   - 禁止行内样式
   - 使用 Design Tokens
   - 支持主题切换
```
