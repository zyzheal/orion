# Orion 开放平台基座能力规则设计

> 版本：v1.0 | 创建日期：2026-04-10 | 状态：设计完成
> 适用范围：所有希望接入 Orion 平台的外部开源系统
> 目标：按规则改造 → 即插即用 → 生态共赢

---

## 一、设计愿景与原则

### 1.1 愿景

**让 Orion 成为研发效能领域的"Android"——建立开放生态，让优秀工具即插即用。**

### 1.2 设计原则

| 原则 | 说明 | 实现方式 |
|------|------|---------|
| **零侵入** | Orion 核心不修改，外部系统通过适配层接入 | Adapter 模式 |
| **标准化** | 统一接口、协议、数据模型 | OpenAPI + Protocol Buffers |
| **可插拔** | 插件化部署，独立升级回滚 | Kubernetes Operator + Helm |
| **自描述** | 插件自动注册能力、权限、路由 | plugin.yaml 声明式配置 |
| **可观测** | 统一指标、日志、追踪 | OpenTelemetry 集成 |
| **安全隔离** | 多租户、权限、审计 | RBAC + RLS + 审计日志 |

## 二、接入能力分级

### 2.1 接入等级定义

Orion 定义 4 级接入能力，外部系统按需选择：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Orion 接入能力金字塔                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│                              ┌───────┐                                     │
│                             /   L4    \                                    │
│                            / 深度集成  \                                   │
│                           /  (AI 增强)   \                                  │
│                          ├───────────────┤                                 │
│                         /       L3        \                                 │
│                        /    双向集成       \                                │
│                       /  (事件 + API 双向)   \                               │
│                      ├───────────────────────┤                              │
│                     /           L2            \                             │
│                    /        单向集成            \                           │
│                   /      (Webhook 推送)          \                          │
│                  ├─────────────────────────────────┤                        │
│                 /               L1                  \                       │
│                /            基础认证                 \                      │
│               /          (SSO + 用户同步)             \                     │
│              └───────────────────────────────────────┘                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 等级 | 名称 | 集成内容 | 改造工作量 | 适用场景 |
|------|------|---------|-----------|---------|
| **L1** | 基础认证 | SSO 登录、用户同步 | 1-2 人日 | 简单工具接入 |
| **L2** | 单向集成 | Webhook 事件推送 | 3-5 人日 | 监控/通知类工具 |
| **L3** | 双向集成 | 事件 + API 双向调用 | 1-2 人周 | CI/CD/代码平台 |
| **L4** | 深度集成 | AI 增强 + 自愈闭环 | 2-4 人周 | 核心业务系统 |

### 2.2 各等级能力矩阵

|------|----|----|----|----|
| 统一认证 (SSO) | ✅ | ✅ | ✅ | ✅ |

## 三、L1 基础认证接入规范

### 3.1 SSO 集成（OIDC 协议）

外部系统需支持 OIDC (OAuth 2.0) 协议，与 Orion 统一认证集成。

```yaml
# 外部系统配置示例 (以 SonarQube 为例)
sso:
  provider: orion
  oidc:
    issuer: "https://orion.company.com/.well-known/openid-configuration"
    client_id: "sonarqube"
    client_secret: "${SSO_CLIENT_SECRET}"  # 从 Vault 获取
    redirect_uri: "https://sonarqube.company.com/oauth2/callback"
    scopes: ["openid", "profile", "email", "groups"]

  # 用户属性映射
  user_mapping:
    username: preferred_username
    email: email
    name: name
    groups: groups  # Orion 角色同步到外部系统

  # 自动创建用户
  auto_create_user: true
  
  # 默认角色
  default_groups: ["sonar-user"]
```

### 3.2 用户同步 API

外部系统需实现用户同步 API，支持 Orion 推送用户/角色变更。

```openapi
openapi: 3.0.0
info:
  title: Orion User Sync API
  version: 1.0.0

paths:
  /api/v1/sync/users:
    post:
      summary: 同步用户信息
      requestBody:
        content:
          application/json:
            schema:
              type: object
              properties:
                action:
                  type: string
                  enum: [create, update, delete, disable]
                user:
                  $ref: '#/components/schemas/User'
      responses:
        '200':
          description: 同步成功

  /api/v1/sync/groups:
    post:
      summary: 同步角色信息
      requestBody:
        content:
          application/json:
            schema:
              type: object
              properties:
                action:
                  type: string
                  enum: [create, update, delete]
                group:
                  $ref: '#/components/schemas/Group'

components:
  schemas:
    User:
      type: object
      required: [id, username, email]
      properties:
        id:
          type: string
          description: 用户唯一标识 (Orion user_id)
        username:
          type: string
        email:
          type: string
        name:
          type: string
        groups:
          type: array
          items:
            type: string
        status:
          type: string
          enum: [active, disabled]
        metadata:
          type: object
          description: 扩展字段

    Group:
      type: object
      required: [id, name]
      properties:
        id:
          type: string
        name:
          type: string
        permissions:
          type: array
          items:
            type: string
```

## 四、L2 单向集成规范

### 4.1 Webhook 事件推送

外部系统需支持配置 Webhook，将事件推送到 Orion 事件总线。

```yaml
# 外部系统 Webhook 配置示例 (以 Prometheus 为例)
webhook:
  enabled: true
  endpoints:
    - name: orion_event_bus
      url: "https://orion.company.com/api/v1/events/ingest"
      events:
        - alert_fired
        - alert_resolved
      headers:
        X-Event-Source: "prometheus"
        X-Auth-Token: "${WEBHOOK_TOKEN}"
      
      # 事件格式转换
      transform:
        type: jinja2
        template: |
          {
            "source": "prometheus",
            "type": "{{ event_type }}",
            "timestamp": "{{ timestamp }}",
            "data": {
              "alert_name": "{{ alert_name }}",
              "severity": "{{ severity }}",
              "description": "{{ description }}",
              "labels": {{ labels | to_json }}
            }
          }
      
      # 重试配置
      retry:
        max_attempts: 3
        backoff: exponential
        initial_delay: 1s
      
      # 死信队列
      dead_letter:
        enabled: true
        storage: s3
        bucket: orion-webhook-dlq
```

### 4.2 CloudEvents 标准

Orion 采用 [CloudEvents 1.0](https://cloudevents.io/) 作为事件格式标准。

```json
{
  "specversion": "1.0",
  "type": "com.prometheus.alert_fired",
  "source": "https://prometheus.company.com",
  "id": "A1B2C3D4-E5F6-7890",
  "time": "2026-04-10T10:00:00Z",
  "datacontenttype": "application/json",
  "data": {
    "alert_name": "HighCPUUsage",
    "severity": "warning",
    "instance": "server-01",
    "value": 95.5
  },
  "orion:tenant_id": "team-001",
  "orion:correlation_id": "corr-123456"
}
```

## 五、L3 双向集成规范

### 5.1 API 网关集成

外部系统需通过 Orion API 网关暴露服务，实现统一认证、限流、审计。

```yaml
# 外部系统 API 网关配置
api_gateway:
  # 服务注册
  service:
    name: sonarqube
    version: 10.4.0
    base_url: "http://sonarqube-service:9000"
  
  # 路由配置
  routes:
    - path: /api/v1/sonar/projects
      upstream: /api/projects
      methods: [GET, POST]
      auth: true
      rate_limit: 100/min
    
    - path: /api/v1/sonar/quality-gates
      upstream: /api/qualitygates
      methods: [GET]
      auth: true
  
  # 认证配置
  authentication:
    type: jwt
    jwks_uri: "https://orion.company.com/.well-known/jwks.json"
    audience: "orion-api"
  
  # 限流配置
  rate_limiting:
    enabled: true
    default_limit: 100/min
    per_user_limit: 20/min
  
  # 审计日志
  audit:
    enabled: true
    log_request_body: true
    log_response_body: false
    sensitive_fields: ["password", "token", "secret"]
  
  # 转换规则
  transformation:
    request:
      - type: add_header
        header: X-Tenant-ID
        value: "${jwt.tenant_id}"
      - type: remove_header
        header: Authorization
    response:
      - type: add_field
        field: _source
        value: sonarqube
```

### 5.2 事件订阅

外部系统可订阅 Orion 事件，实现双向联动。

```yaml
# 外部系统事件订阅配置
event_subscription:
  # 订阅主题
  subscriptions:
    - topic: pipeline.completed
      filter:
        tenant_id: "team-001"
        status: "success"
      sink:
        type: webhook
        url: "http://external-system/events/pipeline-completed"
    
    - topic: deployment.started
      filter:
        environment: "production"
      sink:
        type: nats
        server: "nats://external-system:4222"
        subject: "deployment.production"
  
  # 认证配置
  authentication:
    type: mTLS
    client_cert: "/etc/certs/client.crt"
    client_key: "/etc/certs/client.key"
    ca_cert: "/etc/certs/ca.crt"
  
  # 重试配置
  retry:
    max_attempts: 3
    backoff: exponential
```

### 5.3 数据模型映射

外部系统需定义数据模型与 Orion 标准模型的映射关系。

```yaml
# 数据模型映射配置 (以 SonarQube 为例)
data_mapping:
  # 项目映射
  project:
    source_schema:
      name: string
      key: string
      organization: string
      created_at: timestamp
    
    target_schema:  # Orion 标准模型
      id: string
      name: string
      key: string
      tenant_id: string
      created_at: timestamp
      updated_at: timestamp
      metadata: object
    
    mapping_rules:
      - source: name
        target: name
        transform: none
      
      - source: key
        target: key
        transform: none
      
      - source: organization
        target: tenant_id
        transform: org_to_tenant
      
      - source: created_at
        target: created_at
        transform: timestamp_to_iso8601
      
      - target: updated_at
        value: "${now()}"
      
      - target: metadata
        value:
          source_system: sonarqube
          source_url: "${source.base_url}/projects/${source.key}"

  # 质量问题映射
  issue:
    source_schema:
      key: string
      rule: string
      severity: string
      status: string
      message: string
      line: integer
      component: string
    
    target_schema:  # Orion 标准模型
      id: string
      type: string
      severity: string
      status: string
      description: string
      location: object
      source: string
    
    mapping_rules:
      - source: key
        target: id
        transform: none
      
      - source: rule
        target: type
        transform: rule_to_type
      
      - source: severity
        target: severity
        transform: none
      
      - source: message
        target: description
        transform: none
      
      - source: component
        target: location.file
        transform: none
      
      - target: location.source
        value: sonarqube
```

## 六、L4 深度集成规范

### 6.1 AI 增强接入

外部系统可接入 Orion AI 能力，实现智能审查、智能诊断等。

```yaml
# AI 增强配置示例 (以 SQL 审核系统为例)
ai_enhancement:
  # AI 能力注册
  capabilities:
    - name: sql_review
      type: llm
      model: qwen3-235b
      prompt_template: |
        你是一位资深 DBA，请审查以下 SQL:
        
        ```sql
        {{ sql }}
        ```
        
        请从以下维度审查:
        1. 性能风险 (索引、全表扫描)
        2. 安全风险 (SQL 注入)
        3. 规范风险 (命名、格式)
        
        输出 JSON 格式:
        {
          "issues": [
            {"type": "performance", "severity": "high", "description": "..."}
          ],
          "suggestions": ["..."]
        }
      
      input_mapping:
        sql: "${request.body.sql}"
      
      output_mapping:
        issues: "${response.issues}"
        suggestions: "${response.suggestions}"
      
      # 降级配置
      fallback:
        enabled: true
        type: rule_engine
        rules:
          - pattern: "SELECT \\*"
            severity: warning
            message: "避免使用 SELECT *"
          - pattern: "WHERE.*=.*'"
            severity: info
            message: "注意 SQL 注入风险"
  
  # AI 调用配置
  llm_config:
    provider: orion-ai-service
    endpoint: "https://orion.company.com/api/v1/ai/inference"
    timeout: 30s
    max_tokens: 2048
    temperature: 0.3
  
  # 数据隐私
  data_privacy:
    pii_detection: true
    masking_before_send: true
    use_local_model_for_sensitive: true
```

### 6.2 自愈闭环接入

外部系统可接入 Orion 自愈引擎，实现自动修复。

```yaml
# 自愈闭环配置示例 (以监控系统为例)
self_healing:
  # 诊断能力注册
  diagnosis:
    provider: external-system
    endpoint: "http://external-system/api/v1/diagnose"
    input_mapping:
      alert_name: "${event.alert_name}"
      metrics: "${event.metrics}"
      logs: "${event.logs}"
    output_mapping:
      root_cause: "${response.root_cause}"
      confidence: "${response.confidence}"
      evidence: "${response.evidence}"
  
  # 修复能力注册
  remediation:
    actions:
      - name: restart_service
        description: "重启服务"
        endpoint: "http://external-system/api/v1/actions/restart"
        parameters:
          service_name: "${diagnosis.root_cause.service}"
        validation:
          type: health_check
          endpoint: "http://external-system/health"
          timeout: 60s
      
      - name: scale_up
        description: "扩容"
        endpoint: "http://external-system/api/v1/actions/scale"
        parameters:
          replicas: "${diagnosis.suggested_replicas}"
        validation:
          type: metric_check
          metric: cpu_usage
          threshold: "< 70%"
          timeout: 300s
  
  # 安全门禁
  safety_gates:
    - type: approval_required
      condition: "${risk_score > 50}"
      approvers: ["tech_lead", "sre"]
    
    - type: sandbox_validation
      enabled: true
      timeout: 300s
    
    - type: canary_execution
      enabled: true
      canary_percentage: 10
```

metrics_reporting:

        value: "${result.avg_duration}"

      source: external-system
      query: "count(failed_deployments) / count(total_deployments)"

        value: "${result.rate}"
        unit: percentage
    
    mean_time_to_recovery:
      source: external-system
      query: "avg(incident_resolution_duration)"

## 七、插件化部署规范

### 7.1 plugin.yaml 标准

外部系统需定义 `plugin.yaml` 描述文件，实现自描述、自注册。

```yaml
# plugin.yaml 标准格式
apiVersion: plugin.orion.dev/v1alpha1
kind: Plugin

metadata:
  name: sonarqube              # 插件名称 (唯一标识)
  version: 10.4.0-1.0.0        # 版本 (外部版本 - 适配层版本)
  displayName: "SonarQube"     # 显示名称
  description: "代码质量管理平台"  # 描述
  icon: "/plugins/sonarqube/icon.svg"  # 图标路径
  author: "SonarSource"        # 作者
  homepage: "https://www.sonarqube.org"
  license: "LGPL-3.0"

spec:
  # ========== 服务配置 ==========
  services:
    backend:
      image: registry.company.com/plugins/sonarqube-adapter:1.0.0
      port: 8090
      replicas: 2
      resources:
        cpu: "2"
        memory: "4Gi"
      health_check:
        path: /health
        interval: 30s
        timeout: 5s

    frontend:
      image: registry.company.com/plugins/sonarqube-app:1.0.0
      port: 3010
      entry: "http://{host}/plugins/sonarqube/app.js"
      # 或使用远程 CDN
      # entry: "https://cdn.sonarqube.org/orion-app/1.0.0/app.js"

  # ========== 路由配置 ==========
  routes:
    - path: "/sonar"
      name: "代码质量"
      icon: "CodeQuality"
      permission: "sonar:access"
      children:
        - path: "/sonar/projects"
          name: "项目列表"
          permission: "sonar:projects:view"
        - path: "/sonar/issues"
          name: "问题列表"
          permission: "sonar:issues:view"
        - path: "/sonar/quality-gates"
          name: "质量门禁"
          permission: "sonar:gates:view"

  # ========== 依赖配置 ==========
  dependencies:
    services:
      - name: orion-api-gateway
        version: ">=1.0.0"
      - name: orion-platform-service
        version: ">=1.0.0"
    
    databases:
      - name: postgresql
        version: ">=14"
    
    external:
      - name: sonarqube
        version: ">=10.0"
        url: "${SONARQUBE_URL}"

  # ========== 权限配置 ==========
  permissions:
    - resource: "sonar"
      actions: ["access", "projects:view", "issues:view", "gates:view", "gates:edit"]
      description: "SonarQube 管理权限"
    
    - resource: "sonar-webhook"
      actions: ["receive", "process"]
      description: "SonarQube Webhook 处理权限"

  # ========== API 网关配置 ==========
  api_gateway:
    routes:
      - path: "/api/v1/sonar/"
        service: "sonarqube-adapter"
        strip_prefix: true
        auth: true
        rate_limit: 100/min

  # ========== 配置项 ==========
  config:
    - name: sonarqube.url
      type: string
      required: true
      description: "SonarQube 服务地址"
      sensitive: false
    
    - name: sonarqube.token
      type: string
      required: true
      description: "SonarQube API Token"
      sensitive: true
      secret_ref: sonarqube-token
    
    - name: ai.enabled
      type: boolean
      default: false
      description: "启用 AI 辅助审查"

  # ========== 生命周期钩子 ==========
  hooks:
    pre_install:
      - script: "scripts/pre-install.sh"
        description: "创建数据库表"
        timeout: 300s
    
    post_install:
      - script: "scripts/post-install.sh"
        description: "初始化默认配置"
        timeout: 300s
    
    pre_upgrade:
      - script: "scripts/pre-upgrade.sh"
        description: "备份数据"
        timeout: 600s
    
    post_upgrade:
      - script: "scripts/post-upgrade.sh"
        description: "数据迁移"
        timeout: 600s
    
    pre_uninstall:
      - script: "scripts/pre-uninstall.sh"
        description: "清理资源"
        timeout: 300s

  # ========== 可观测性配置 ==========
  observability:
    metrics:
      enabled: true
      endpoint: "/metrics"
      port: 9090
    
    logging:
      level: info
      format: json
    
    tracing:
      enabled: true
      sampling_rate: 0.1

  # ========== 多租户配置 ==========
  multi_tenancy:
    isolation_level: schema  # none | schema | database
    rls_enabled: true
    quota:
      max_projects: 100
      max_analyses_per_day: 1000
```

### 8.1 安全基线

所有接入 Orion 的外部系统必须满足以下安全基线：

```yaml
security_baseline:

  authentication:
    - sso_required: true
    - mfa_support: optional
    - service_account_support: true
  
  # 数据安全
  data_security:
    - encryption_at_rest: required
    - encryption_in_transit: required
    - secret_management: vault_integration
  
  # 网络安全
  network_security:
    - network_policy: required
    - ingress_tls: required
    - egress_filtering: required
  
  # 审计合规
  audit:
    - audit_logging: required
    - log_retention: ">=90d"
    - tamper_proof: required
  
  # 漏洞管理
  vulnerability:
    - image_scanning: required
    - dependency_scanning: required
    - sla_critical: "24h"
    - sla_high: "72h"
