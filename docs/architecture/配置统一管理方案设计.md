# 配置统一管理方案设计

> 版本：v1.0 | 日期：2026-05-06

---

## 一、背景

当前 Orion 系统存在**配置散落**问题：
- 硬编码常量遍布各模块
- 无统一配置管理入口  
- 配置变更无审计追溯
- 新模块配置无规范

### 2.3 问题

1. **修改困难** - 需定位每个文件修改
2. **不可观测** - 无全局配置视图
3. **无版本管理** - 配置变更无记录
4. **风险高** - 误改影响不确定

### 4.4 API 设计

```yaml
# 读取配置
GET /api/v1/system-config          # 获取所有配置(脱敏)
GET /api/v1/system-config/:module  # 获取模块配置
GET /api/v1/system-config/:module/:key  # 获取具体配置

# 更新配置
PUT /api/v1/system-config/:module/:key  # 更新(需admin)
POST /api/v1/system-config/batch        # 批量更新
POST /api/v1/system-config/:module/:key/reset  # 重置为默认值

# 管理
GET /api/v1/system-config/history       # 配置变更历史
POST /api/v1/system-config/export       # 导出配置
POST /api/v1/system-config/import       # 导入配置
```

### 4.5 散落配置迁移流程

```typescript
// 旧代码 (散落)
const DEFAULT_TIMEOUT_MS = 3_600_000;

// 新代码 (统一)
import { config } from '../../config/UnifiedConfigService';

// 使用统一配置
const timeout = config.pipeline.defaultTimeoutMinutes * 60 * 1000;

// 或带默认值
const retryConfig = config.pipeline.retryPolicy ?? {
  maxRetries: 3,
  baseDelayMs: 1000
};
```

### 4.5 跨模块配置同步策略

由于 Orion 是多语言多服务架构，配置管理采用**分布式配置中心**模式：

```
┌─────────────────────────────────────────────────────────────────┐
│                    跨模块配置同步架构                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌─────────────────┐                                          │
│   │  配置中心 (Node.js) │ ← 统一配置入口                         │
│   │ UnifiedConfig   │                                          │
│   └────────┬────────┘                                          │
│            │                                                    │
│    ┌───────┼───────┬──────────────┐                           │
│    │       │       │              │                            │
│    ▼       ▼       ▼              ▼                            │
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────────────┐                  │
│ │Node.js│ │Golang│ │Java  │ │ 前端 (React) │                  │
│ │服务   │ │DBA   │ │Visor │ │              │                  │
│ └──────┘ └──────┘ └──────┘ └──────────────┘                  │
│    │           │       │           │                           │
│    │    ┌──────┴──┐    │      ┌────┴────┐                      │
│    │    │配置拉取  │    │      │ 环境变量 │                     │
│    │    │(HTTP)   │    │      │ (.env)   │                     │
│    │    └─────────┘    │      └──────────┘                     │
│    │                   │                                       │
│    └───────────────────┴──────────────────────────────────────┘
```

#### 4.5.1 各模块配置获取方式

| 模块 | 技术栈 | 配置获取方式 |
|------|--------|-------------|
| `orion-platform-service` | Node.js | 直接引用 |
| `orion-dba` | Golang | HTTP 拉取 / 环境变量 |
| `orion-visor` | Java | Spring Config / 环境变量 |
| `orion-knowledge` | Golang | HTTP 拉取 / 环境变量 |
| `orion-frontend` | React | 环境变量 .env |

#### 4.5.2 配置命名规范

```yaml
# 统一配置命名空间
orion.core.database.poolSize
orion.escalation.enabled
orion.dba.sql.timeout
orion.visor.datasource.maxActive
orion.knowledge.rag.chunkSize
```

#### 4.5.3 各模块适配示例

```yaml
# orion-dba .env
ORION_CONFIG_URL=http://orion-platform:3000/api/v1/system-config
```

```yaml
# orion-visor application.yml

  config:
    endpoint: ${ORION_CONFIG_URL:http://orion-platform:3000}
```

```typescript

```
