# Orion 工具管理中心设计

---

## 1. 工具管理现状与缺口

### 1.1 已有内容

| 维度 | 已设计 | 深度 |
|------|--------|------|
| 多工具链管理 | ✅ Plugin SPI 插件接口 | 有接口定义，无管理能力 |
| 工具矩阵 | ✅ 工具分类列表 | 只列了工具名，无生命周期 |
| AI 工具注册 | ✅ MCP 协议注册 | 有注册，无管理 |
| CI 引擎适配 | ✅ Tekton/GitHub/GitLab 适配 | 有抽象层 |

### 1.2 缺失能力

| 缺失能力 | 说明 | 优先级 |
|---------|------|--------|
| 工具生命周期管理 | 安装、升级、卸载、回滚 | P0 |
| 工具版本管理 | 多版本共存、版本兼容性矩阵 | P0 |
| 工具配置管理 | 每个工具的独立配置、模板化、版本化 | P0 |
| 工具可用性监控 | 健康检查、响应时间、错误率 | P0 |
| 工具使用统计 | 调用次数、成功率、耗时统计 | P1 |
| 工具依赖管理 | 工具间依赖关系、冲突检测 | P1 |
| 工具权限控制 | 团队/角色对工具的使用权限 | P1 |
| 工具市场/商店 | 工具的发现、安装、评分 | P2 |

## 2. 工具生命周期管理

```yaml
tool_lifecycle:
  # ── 安装 ──
  install:
    methods:
      - plugin      # 插件形式安装
      - binary      # 二进制直接安装
      - container   # 容器化部署
      - api         # 外部 API 集成
    
    process:
      1. 兼容性检查 (Orion 版本、依赖工具)
      2. 自动解决依赖 (拓扑排序安装顺序)
      3. 安装工具 (下载/拉取/部署)
      4. 健康验证 (启动后健康检查)
      5. 注册到工具注册表
      6. 通知相关团队
  
  # ── 升级 ──
  upgrade:
    strategies:
      - rolling      # 滚动升级 (推荐)
      - blue-green   # 蓝绿升级 (零停机)
      - canary       # 金丝雀升级 (小流量验证)
    
    process:
      1. 检查新版本可用性
      2. 检查与已安装工具的兼容性
      3. 升级前通知 (提前 24h)
      4. 执行升级 (按策略)
      5. 健康验证
      6. 失败自动回滚
      7. 更新工具注册表
  
  # ── 卸载 ──
  uninstall:
    options:
      keep_config: true       # 默认保留配置
      keep_data: true         # 默认保留数据
      force: false            # 默认不强制
      check_dependencies: true # 检查是否有其他工具依赖
  
  # ── 回滚 ──
  rollback:
    auto_rollback: true        # 升级失败自动回滚
    keep_versions: 3           # 保留最近 3 个版本
    rollback_time_limit: "5m"  # 回滚时间不超过 5 分钟
```

## 3. 工具版本管理

### 3.1 多版本共存

```
Orion 允许同一工具的多个版本共存:

semgrep:
  ├── v1.30.0 (已停止维护，标记 deprecated)
  ├── v1.31.0 ✅ (当前稳定版本，推荐使用)
  └── v1.32.0-beta (测试中，仅开发环境可用)

规则:
• 每个工具最多保留 5 个版本
• 生产环境只能使用稳定版本
• 新版本发布后旧版本保留 90 天过渡期
```

### 3.2 版本兼容性矩阵

```yaml
compatibility_matrix:
  semgrep:
    "1.30":
      compatible_with:
        - sonarqube: ">=9.9"
        - trivy: ">=0.45"
        - orion: ">=1.0"
      incompatible_with:
        - trivy: "<0.45"  # 旧版 trivy 不兼容
    
    "1.31":
      compatible_with:
        - sonarqube: ">=9.9"
        - trivy: ">=0.46"
        - orion: ">=1.1"
      breaking_changes:
        - "配置文件格式变更，需要迁移"
        - "新增 p/cwe-top-25 规则集"
  
  trivy:
    "0.45":
      compatible_with:
        - harbor: ">=2.8"
        - cosign: ">=2.0"
    "0.46":
      compatible_with:
        - harbor: ">=2.8"
        - cosign: ">=2.1"
      new_features:
        - "支持 SBOM 导出为 CycloneDX 格式"
```

## 4. 工具配置管理

### 4.1 配置模板

```yaml
tool_configs:
  semgrep:
    templates:
      - name: default
        description: "默认安全扫描配置"
        config:
          rules: [p/security-audit, p/owasp-top-ten]
          exclude: ["*.test.ts", "test-fixtures/"]
          severity_threshold: ERROR
      
      - name: strict
        description: "严格安全扫描 (生产发布前)"
        config:
          rules: [p/security-audit, p/owasp-top-ten, p/cwe-top-25]
          exclude: []
          severity_threshold: WARNING
      
      - name: fast
        description: "快速扫描 (开发时)"
        config:
          rules: [p/security-audit]
          exclude: ["*.test.ts", "test-fixtures/", "docs/"]
          severity_threshold: CRITICAL
  
  sonarqube:
    templates:
      - name: default
        config:
          quality_gate: default
          coverage_threshold: 70
          duplication_threshold: 5
      
      - name: enterprise
        config:
          quality_gate: strict
          coverage_threshold: 85
          duplication_threshold: 3
          security_rating: A
```

### 4.2 配置版本化

```
所有工具配置存储在 Git 中，可追溯、可回滚:

orion-tools-config/
├── semgrep/
│   ├── v1/
│   │   └── config.yaml      # 初始配置
│   ├── v2/
│   │   └── config.yaml      # 添加新规则集
│   └── current -> v2        # 当前生效版本
├── sonarqube/
│   ├── v1/
│   │   └── config.yaml
│   └── current -> v1
└── trivy/
    ├── v1/
    │   └── config.yaml
    └── current -> v1

每次配置变更 = 一次 Git commit
• 谁改的 (author)
• 什么时候改的 (timestamp)
• 为什么改 (commit message)
• 可以回滚到任意历史版本
```

## 5. 工具可用性监控

### 5.1 健康检查

```yaml
health_checks:
  schedule: "*/5m"  # 每 5 分钟
  
  methods:
    - type: http
      endpoint: "/healthz"
      timeout: "5s"
      expected_status: 200
    
    - type: grpc
      service: "tool.Service"
      method: "Ping"
      timeout: "3s"
    
    - type: command
      command: "tool --version"
      timeout: "2s"
      expected_exit_code: 0
  
  status:
    - 🟢 healthy:   所有检查通过
    - 🟡 degraded:  部分检查失败或响应慢
    - 🔴 unhealthy: 所有检查失败
    - ⚪ unknown:   从未检查过
```

### 5.2 监控指标

| 指标 | 类型 | 标签 | 告警规则 |
|------|------|------|---------|
| tool_response_time | histogram | tool_name, version, operation | P95 > 5s → WARNING |
| tool_error_rate | counter | tool_name, version, error_type | > 5% in 5m → WARNING |
| tool_usage_count | counter | tool_name, version, team | - |
| tool_health_status | gauge | tool_name, version | unhealthy > 3 checks → CRITICAL |
| tool_resource_usage | gauge | tool_name, cpu, memory | CPU > 80% → WARNING |

### 5.3 告警与自愈

```yaml
alerting:
  rules:
    - name: tool_unavailable
      condition: "health_check_failed > 3 consecutive"
      severity: CRITICAL
      actions:
        - alert: [slack, email, pagerduty]
        - auto_restart: true
        - fallback_to: alternative_tool_if_available
    
    - name: tool_slow_response
      condition: "p95_response_time > 5s for 10m"
      severity: WARNING
      actions:
        - alert: [slack]
        - increase_timeout: true  # 临时增加超时
    
    - name: tool_high_error_rate
      condition: "error_rate > 5% for 5m"
      severity: WARNING
      actions:
        - alert: [slack]
        - enable_degraded_mode: true  # 启用降级模式
  
  degraded_modes:
    ai-code-review:
      - fallback_to: rule_engine  # LLM 不可用时降级到规则引擎
    semgrep:
      - fallback_to: cached_results  # 使用上次扫描缓存结果
```

## 7. 工具依赖管理

### 7.1 依赖关系图

```
工具依赖关系:

semgrep ──┐
          ├──→ ai-code-review ──→ Pipeline
sonarqube─┤
          ├──→ security-scan ──→ Pipeline
trivy ────┘

postgres ──→ sonarqube
harbor ────→ trivy

安装顺序 (拓扑排序):
1. postgres (基础依赖)
2. harbor (基础依赖)
3. semgrep (无依赖)
4. trivy (依赖 harbor)
5. sonarqube (依赖 postgres)
6. ai-code-review (依赖 semgrep, sonarqube)
7. security-scan (依赖 semgrep, trivy)
8. Pipeline (依赖 ai-code-review, security-scan)
```

### 7.2 冲突检测

```yaml
conflict_rules:
  - tools: [trivy:v0.45, trivy:v0.46]
    type: version_conflict
    message: "不能同时安装同一工具的多个主版本"
    resolution: "卸载旧版本或切换到单一版本"
  
  - tools: [semgrep, codeql]
    type: resource_contention
    message: "两个工具同时运行可能资源争用"
```

## 11. 工具管理 API

```yaml
# 工具管理 REST API
api:
  base_path: /api/v1/tools
  
  endpoints:
    # 工具列表
    - GET    /tools                          # 获取所有工具
    - GET    /tools/{tool_name}              # 获取工具详情
    - GET    /tools/{tool_name}/versions     # 获取工具版本列表
    - GET    /tools/{tool_name}/health       # 获取工具健康状态
    - GET    /tools/{tool_name}/metrics      # 获取工具使用指标
    - GET    /tools/{tool_name}/config       # 获取工具配置
    - GET    /tools/{tool_name}/config/history # 配置历史
    
    # 工具操作
    - POST   /tools/{tool_name}/install      # 安装工具
    - POST   /tools/{tool_name}/upgrade      # 升级工具
    - POST   /tools/{tool_name}/uninstall    # 卸载工具
    - POST   /tools/{tool_name}/rollback     # 回滚工具版本
    - POST   /tools/{tool_name}/health-check # 手动触发健康检查
    - POST   /tools/{tool_name}/restart      # 重启工具
    
    # 工具配置
    - PUT    /tools/{tool_name}/config       # 更新工具配置
    - POST   /tools/{tool_name}/config/validate # 验证配置
    
    # 工具市场
    - GET    /marketplace                    # 获取可用工具列表
    - GET    /marketplace/{tool_name}        # 获取工具详情
    - POST   /marketplace/{tool_name}/rate   # 评分工具
    - POST   /marketplace/{tool_name}/review # 评论工具
    
    # 依赖管理
    - GET    /tools/{tool_name}/dependencies  # 获取工具依赖
    - GET    /tools/{tool_name}/dependents    # 获取依赖此工具的工具
    - GET    /tools/dependency-graph          # 获取完整依赖图
    
    # 权限管理
    - GET    /tools/{tool_name}/permissions  # 获取工具权限配置
    - PUT    /tools/{tool_name}/permissions  # 更新工具权限
```
