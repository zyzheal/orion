## 1. 核心域 + 支撑域架构（P0 修复后）

**重构背景**：原 5 层分层架构存在循环依赖（L2↔L3↔L4 网状调用），导致无法独立部署。

**重构目标**：消除循环依赖、支持独立部署、清晰边界、事件驱动解耦。

```
┌─────────────────────────────────────────────────────────────────┐
│                    核心域 (Core Domain)                          │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐               │
│  │ Pipeline    │ │ 构建环境    │ │ 多工具链    │               │
│  │ 引擎        │ │             │ │             │               │
│  └─────────────┘ └─────────────┘ └─────────────┘               │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐               │
│  │ 代码管理    │ │ 配置管理    │ │ 智能部署    │               │
│  └─────────────┘ └─────────────┘ └─────────────┘               │
│                                                                   
│  特征：高频迭代（周级）、直接面向研发、强一致性、Java/Spring     │
└─────────────────────────────────────────────────────────────────┘
                            │
                            ▼ (事件驱动，单向依赖)
┌─────────────────────────────────────────────────────────────────┐
│                   支撑域 (Supporting Domain)                     │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐               │
│  │ AI 增强域   │ │ 效能洞察域  │ │ FinOps      │               │
│  └─────────────┘ └─────────────┘ └─────────────┘               │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐               │
│  │ CMDB        │ │ 运维治理    │ │ 工单协同    │               │
│  └─────────────┘ └─────────────┘ └─────────────┘               │
│                                                                   
│  特征：按需迭代、能力增强、最终一致、多技术栈                    │
└─────────────────────────────────────────────────────────────────┘
```

**调用规则**：
| 调用方向 | 规则 | 说明 |
|---------|------|------|
| 核心域 → 支撑域 | 允许同步调用 | 核心域可读取支撑域能力 |
| 支撑域 → 核心域 | 仅事件订阅 | 支撑域通过事件消费，禁止同步调用 |
| 支撑域 ↔ 支撑域 | 禁止直接调用 | 必须通过核心域中转 |

**部署独立性**：
- 最小部署：5 分钟（仅核心域）
- 增量部署：单域部署不影响其他域

详见：`docs/architecture/架构重构设计.md`

## 3. P0 架构修复汇总

### 3.1 循环依赖消除（A01）

**问题**：5 层分层架构存在循环依赖（L2↔L3↔L4 网状调用）

**修复**：核心域 + 支撑域重构，事件驱动解耦

**结果**：可独立部署，单域部署时间 < 5 分钟

---

### 3.2 数据库分片（A03/A04/B02）

**问题**：42 张表无分片策略，MySQL→ClickHouse 同步缺失

**修复**：
- 分片表：audit_log、event_log、cicd_pipeline_run、ai_inference_log、k8s_sync_log
- CDC 同步：MySQL Binlog → Flink CDC → Kafka → ClickHouse
- 延迟容忍：5-10 秒最终一致

---

### 3.3 AI 降级（A07）

**问题**：15+ 处 LLM 调用无具体降级实现

**修复**：
- P0 核心场景（3 个）：必须降级且可验证
- P1 重要场景（7 个）：可以降级但允许功能缺失
- P2 锦上添花（6 个）：不降级直接禁用

---

### 3.4 CMDB 集成（A05）

**问题**：CMDB 42 表与 26 模块集成方案缺失

**修复**：
- CMDB Read API：主机资源/ K8s 资源/CI-CD 资源/拓扑关系
- K8s 同步双机制：Watch + 定时对账（5m）

---

### 3.5 NATS 高可用（A06/S01）

**问题**：NATS 成为新的单点故障

**修复**：
- 3 节点 JetStream 集群，R=3 副本
- 故障切换：< 15 秒恢复

---

### 3.6 多租户隔离（A08/E03）

**问题**：1000 团队=1000 Namespace 不可行

**修复**：
- 网络隔离：10 团队/Namespace 分组 → 共 100 个 Namespace
- 数据隔离：单 Schema + tenant_id 列 + RLS
- 性能改善：etcd 内存↓90%，API Server QPS↓89%，PostgreSQL 表数↓99.9%

---

### 3.7 自愈引擎权限治理（A09）

**问题**：Kintsugi 可执行 DDL/回滚/流量切换，权限风险未治理

**修复**：
- 高危操作分类：P0/P1 双签 + 沙箱验证
- 自毁开关：6 类异常检测

---

### 3.8 AI 安全加固（E04/E05/E06）

**问题**：Prompt 注入可绕过、AI Skill 无沙箱、输出无 DLP

**修复**：四层防护架构（输入清洗、隔离执行、输出验证、审计日志）

---

### 3.9 JWT 并发刷新保护（E01）

**问题**：Refresh Token 并发刷新可被劫持

**修复**：设备指纹绑定 + 并发刷新检测（Redis Lua 原子操作）

---

### 3.10 API 分页与错误码规范（B01/B06/B07）

**问题**：分页策略混用、错误码笼统、N+1 查询

**修复**：
- 分页策略分离：Offset（静态数据）/ Cursor（实时数据）
- 错误码二级分类：XYYZZ 格式
- N+1 查询解决方案：JOIN/批量查询/缓存

---

### 3.11 前端性能优化（F01-F05）

**问题**：WebSocket 内存泄漏、图表卡顿、虚拟滚动缺失

**修复**：
- WebSocket 生命周期管理：心跳 30s，指数退避重连
- 虚拟滚动：DOM 节点↓99%，首屏渲染↓94%
- 图表库选型：ECharts（大数据量）+ Recharts（小数据量）

---

### 3.12 SRE 运维加固（S02-S07）

**问题**：故障切换无 runbook、告警风暴、备份缺失

**修复**：
- MySQL 主从延迟分级降级：Level 1(>10s) → Level 3(>60s)
- 告警抑制规则：7 条规则（维护窗口、节点故障、级联故障等）
- ClickHouse 备份：clickhouse-backup（全量每天 + 增量每小时）
- DR 演练：月度 Light Drill（RTO < 15 分钟）、季度 Full Drill（RTO < 30 分钟）
