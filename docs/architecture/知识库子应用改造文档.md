> **改造时间**: 2026-05-22
> **涉及项目**: `orion-knowledge` (PandaWiki fork) → `orion-frontend` (主应用) → `orion-api-gateway` (网关)

## 一、改造背景与目标

### 1.1 业务背景

Orion 平台需要将 PandaWiki（开源知识库系统）作为子应用集成到主应用中，为用户提供统一的知识管理能力。集成后用户无需单独登录，在主应用内即可无缝访问知识库功能。

### 1.2 集成目标

| 目标 | 说明 |
|------|------|
| 统一登录态 | 主应用 Token → 子应用免登录，共享用户信息 |
| 统一导航 | 主应用 8 大菜单包含"知识库"入口 |
| 样式隔离 | Shadow DOM 防止 PandaWiki MUI 样式与主应用 Ant Design 冲突 |
| 路由前缀 | 所有子应用路由以 `/knowledge/*` 为前缀 |
| 独立部署 | 子应用保持独立开发、独立构建、独立部署能力 |

| 方案 | 优点 | 缺点 | 结论 |

### Phase 1: 子应用入口改造

**文件**: `orion-knowledge/web/admin/src/main.tsx`（完整 221 行）

#### 1.1 双模式支持

知识库子应用需要同时支持两种运行模式：

1. **独立运行模式**: 直接 `npm run dev` 访问 `localhost:5173`
2. **微前端模式**: 被主应用通过 Module Federation 加载

```typescript
// 独立运行模式 - 延迟检查，给微前端 mount 调用留出时间
let knowledgeRoot: Root | null = null;
let autoRenderTimer: ReturnType<typeof setTimeout> | null = null;

function tryAutoRender() {
  // 同时检查 wujie 和 Orion-MF 的标志位，避免在微前端模式下自动渲染
  if (!(window as any).__POWERED_BY_WUJIE__ && !(window as any).__POWERED_BY_ORION__) {
    // 动态加载 CSS
    const loadCSS = (href: string) => {
      const link = document.createElement('link');
      link.rel = 'stylesheet';
      link.href = href;
      document.head.appendChild(link);
    };
    loadCSS(`${window.__BASENAME__ || ''}/orion-knowledge.css`);

    wrapWindowOpen(window.__BASENAME__ || '');
    dayjs.extend(duration);
    dayjs.extend(relativeTime);
    dayjs.locale('zh-cn');

    knowledgeRoot = render();
    console.log('[orion-knowledge] Running in standalone mode');
  }
}

// 100ms 延迟是关键值：给 MF 的 mount 调用足够时间窗口
autoRenderTimer = setTimeout(tryAutoRender, 100);
```

**为什么是 100ms？**
- 太短（< 50ms）：MF 的 `loadSubApp` 可能还未执行到 mount 阶段
- 太长（> 200ms）：独立运行模式下用户感知到明显的白屏延迟
- 100ms 是经过实际测试的平衡值

#### 1.2 微前端生命周期导出

```typescript
// ES module 生命周期导出（Module Federation 构建后产物使用）
export { doBootstrap as bootstrap, doMount as mount, doUnmount as unmount };

// 全局挂载（Vite dev 模式，MF 从 window 读取）
(window as any).bootstrap = doBootstrap;
(window as any).mount = doMount;
(window as any).unmount = doUnmount;
```

**为什么同时导出两种形式？**
- 生产环境：MF 构建后的 ESM 产物通过 `import` 加载生命周期
- 开发环境：Vite dev server 下，MF 通过 `window.bootstrap/mount/unmount` 读取

#### 1.3 doMount 实现（核心挂载逻辑）

```typescript
async function doMount(container: any, props?: Record<string, unknown>) {
  // 关键：取消自动渲染定时器，避免双重渲染
  if (autoRenderTimer) {
    clearTimeout(autoRenderTimer);
    autoRenderTimer = null;
  }

  // 兼容 wujie 和 MF 两种调用方式：
  // - wujie: doMount(wujieProps) - 只有一个参数
  // - MF: doMount(containerElement, { basename, ... }) - 两个参数
  const isWujieStyle = !container?.nodeType && !container?.host;
  const effectiveProps = isWujieStyle ? container : props;
  const effectiveContainer = isWujieStyle ? document : container;

  // 从 props 获取 basename（MF 模式下传入）
  const propsBasename = (effectiveProps as any)?.basename;
  if (propsBasename) {
    window.__BASENAME__ = propsBasename;
  }

  // 包装 window.open，确保子应用内部的 window.open 调用自动添加 basename
  wrapWindowOpen(propsBasename || '');

  // 设置微前端标志位
  window.__POWERED_BY_WUJIE__ = true;
  window.__POWERED_BY_ORION__ = true;

  // 在有效容器内创建 #root 元素
  // 注意：当使用 Shadow DOM 时，#root 必须在 ShadowRoot 内部
  let rootEl = effectiveContainer.querySelector('#root');
  if (!rootEl) {
    rootEl = document.createElement('div');
    rootEl.id = 'root';
    effectiveContainer.appendChild(rootEl);
  }

  // 执行渲染，传入 container 和 basename
  knowledgeRoot = render({
    ...effectiveProps,
    container: effectiveContainer,
    basename: propsBasename,
  });
}
```

#### 1.4 React Root 复用（防止重复渲染）

```typescript
function render(props: any = {}) {
  const { container, basename } = props;

  const containerEl = container
    ? container.querySelector('#root')
    : document.querySelector('#root');

  if (!containerEl) {
    console.error('[orion-knowledge] No #root element found!');
    return null;
  }

  // 复用已存在的 React root（HMR 场景）
  let existingRoot: Root | null = null;
  try {
    existingRoot = (containerEl as any).__reactRoot || null;
  } catch { /* ignore */ }

  let root: Root;
  if (existingRoot) {
    console.log('[orion-knowledge] Reusing existing React root');
    root = existingRoot;
    // 微前端模式下复用 root 时，检查是否已挂载过，避免重复渲染
    if ((window as any).__POWERED_BY_ORION__ && (containerEl as any).__orionRendered) {
      console.log('[orion-knowledge] Already rendered, skipping re-render');
      return root;
    }
    (containerEl as any).__orionRendered = true;
  } else {
    console.log('[orion-knowledge] Creating new React root');
    root = createRoot(containerEl);
    (containerEl as any).__reactRoot = root;
  }

  root.render(
    <React.StrictMode>
      <Provider store={store}>
        <BrowserRouter basename={basename || window.__BASENAME__ || '/'}>
          <OrionContext.Provider value={props}>
            <App />
          </OrionContext.Provider>
        </BrowserRouter>
      </Provider>
    </React.StrictMode>
  );

  return root;
}
```

#### 3.2 wrapWindowOpen 实现

**文件**: `orion-knowledge/web/admin/src/utils/getBasename.ts`

```typescript
export function wrapWindowOpen(basename: string) {
  if (!basename) return;

  const originalOpen = window.open;
  window.open = function(url, ...args) {
    // 相对路径自动添加 basename 前缀
    if (url && typeof url === 'string' && url.startsWith('/')) {
      url = basename + url;
    }
    return originalOpen.call(window, url, ...args);
  };
}
```

**影响范围**:
- 子应用内所有 `window.open('/doc/editor/xxx')` 自动变为 `window.open('/knowledge/doc/editor/xxx')`
- 确保子应用内打开的新窗口/标签页仍然带有正确的路由前缀

#### 4.2 API 请求链路详解

```

    │
    ▼

  匹配 Token Exchange 规则:
    - 请求路径: /api/v1/knowledge_base/**
```

#### 4.3 Gateway Token Exchange 原理

## 三、微前端容器双重渲染问题（重点）

### 3.1 问题现象

访问 `http://localhost:3000/knowledge` 时，页面内容区出现 **两套完整的 UI**：
- 两套侧边栏（Sidebar）
- 两套内容区（Header + 文档列表）
- 两套底部按钮

### 3.2 根因分析

经过排查，问题出在两层：

#### 第一层：MFSandboxBridge 缺少重复挂载防护

**文件**: `packages/orion-mf/src/core/MFSandboxBridge.ts`

```typescript
// mountToShadowDOM - 原始实现（有问题）
private mountToShadowDOM(key, lifecycle, cssIsolation, props): ShadowRoot {
  // 每次调用都创建新的容器
  const container = document.createElement('div');
  container.id = `orion-mf-container-${key}`;
  document.body.appendChild(container);

  // 每次调用都创建新的 Shadow Root
  const shadowRoot = container.attachShadow({ mode: 'open' });

  // 每次调用都执行 mount
  lifecycle.mount(shadowRoot, props);
}
```

当 `React.StrictMode` 导致 `useEffect` 执行两次时（mount → unmount → remount），虽然 `startedRef` 能阻止 `SubAppRoute` 的重复启动，但在某些边界情况下（如路由快速切换、HMR 触发），`loadSubApp` 仍可能被调用多次。

#### 第二层：知识库子应用 React Root 复用不彻底

**文件**: `orion-knowledge/web/admin/src/main.tsx`

```typescript
// 原始实现 - 复用 root 但仍会调用 root.render()
if (existingRoot) {
  root = existingRoot;  // 复用了 root 引用
} else {
  root = createRoot(containerEl);
}

root.render(<App />);  // 问题：即使 root 已存在，仍会调用 render
```

即使复用了 `existingRoot`，`root.render()` 仍然会被调用。在 React 18 中，对同一个 root 重复调用 `render` 不会报错，但会导致组件重新挂载，如果配合 Shadow DOM 的重复创建，就会出现两套 UI。

### 3.3 修复方案

#### 修复 1: MFSandboxBridge 添加容器复用

```typescript
private mountToShadowDOM(key, lifecycle, cssIsolation, props): ShadowRoot {
  // 防御性检查：如果已存在同名容器和 Shadow Root，直接返回
  const existingContainer = document.getElementById(`orion-mf-container-${key}`);
  if (existingContainer?.shadowRoot) {
    console.warn(`[orion-mf] Shadow DOM already exists for "${key}", reusing`);
    return existingContainer.shadowRoot;
  }

  // ... 原有创建逻辑
}

private mountToDOM(key, lifecycle, props): HTMLElement {
  // 同样添加防御性检查
  const existingContainer = document.getElementById(`orion-mf-container-${key}`);
  if (existingContainer) {
    console.warn(`[orion-mf] DOM container already exists for "${key}", reusing`);
    return existingContainer;
  }

  // ... 原有创建逻辑
}
```

#### 修复 2: 子应用添加渲染标记

```typescript
if (existingRoot) {
  root = existingRoot;
  // 微前端模式下防止重复渲染
  if ((window as any).__POWERED_BY_ORION__ && (containerEl as any).__orionRendered) {
    console.log('[orion-knowledge] Already rendered, skipping re-render');
    return root;  // 直接返回，不调用 render
  }
  (containerEl as any).__orionRendered = true;
} else {
  root = createRoot(containerEl);
  (containerEl as any).__reactRoot = root;
}
```

### 3.4 验证方法

```javascript

// 预期: 1

document.querySelectorAll('#app-knowledge').length
// 预期: 1

container?.shadowRoot?.innerHTML?.length
// 预期: 有内容且只有一份
```

## 四、对接问题详细记录

### 问题 1: API 返回 500 Internal Server Error

**发生时间**: 首次对接

**现象**:
```
GET /api/v1/knowledge_base/list
Response: 500 Internal Server Error
Body: {"error": "Internal Server Error"}
```

**排查过程**:
1. 检查 Gateway 日志 → 请求已到达 9000 端口
2. 检查 Gateway 转发 → 尝试连接 `localhost:9000` 返回 `ECONNREFUSED`
3. 发现 `localhost` 解析为 `::1`（IPv6），但 Gateway 只监听 `127.0.0.1`（IPv4）

**根本原因**: macOS 上 `localhost` 默认解析为 IPv6 `::1`，而 Node.js 服务默认只监听 IPv4。

**修复**:
```typescript
// orion-frontend/vite.config.ts
// 修复前
const PANDAWIKI_API = process.env.PANDAWIKI_API_TARGET || 'http://localhost:9000';
// 修复后
const PANDAWIKI_API = process.env.PANDAWIKI_API_TARGET || 'http://127.0.0.1:9000';
```

**教训**: 在 macOS 开发环境中，使用 `127.0.0.1` 而非 `localhost` 可避免 IPv6 解析问题。

### 问题 2: API 返回 401 Unauthorized

**发生时间**: 修复 500 后

**现象**:
```
GET /api/v1/knowledge_base/list
Response: 401 Unauthorized
Headers: x-knowledge-status-code: 401
```

**排查过程**:
1. Gateway 日志显示 → 请求转发到 8090 端口
2. 知识库后端日志 → 收到请求但缺少 Session Token
3. Gateway 代码分析 → Token Exchange 被跳过

**根本原因**: Gateway 的 Token Exchange 逻辑需要 `PANDAWIKI_PASSWORD` 环境变量，未配置时跳过 Token Exchange，直接转发原始请求（不带 PandaWiki Session Token）。

**修复**:
```bash
# orion-api-gateway/.env
PANDAWIKI_PASSWORD=admin123
```

同时需要在知识库数据库中设置 admin 密码：
```python
import bcrypt
hashed = bcrypt.hashpw(b'admin123', bcrypt.gensalt())
# 更新数据库中的密码哈希
```

### 问题 3: 端口冲突

**发生时间**: 初始配置

**现象**:
```
Error: listen EADDRINUSE: address already in use :::3000
```

**排查**:
```bash
$ lsof -i :3000
COMMAND   PID  USER  FD   TYPE  DEVICE  SIZE/OFF  NODE  NAME
node     1234  heal  22u  IPv6  ...     0t0       TCP   *:3000 (LISTEN)
```

发现 Vite dev server (3000) 和 Gateway (3000) 冲突。

**修复**:
```bash
# orion-api-gateway/.env
PORT=9000
```

### 问题 4: 返回按钮导致布局错乱

**发生时间**: 首次集成 Sidebar

**现象**: 点击 "← Orion" 后，主应用侧边栏消失，内容区变形。

**原因**: 使用 `pushState` + `popstate` 在 Shadow DOM 环境下行为不可预测，React Router 的 basename 机制与手动 history 操作冲突。

**修复**: 改用 `window.location.href` 硬跳转。

### 问题 5: Docker 容器 DNS 解析失败

**发生时间**: 启动知识库后端

**现象**:
```
container error: dial tcp: lookup nats-server on 127.0.0.11:53: no such host
```

**原因**: 使用了错误的 Docker Network 名称 `orion-knowledge-net`，实际名称为 `orion-knowledge_orion-knowledge-net`（Docker Compose 自动添加项目前缀）。

**修复**:
```bash
$ docker network ls | grep knowledge
orion-knowledge_orion-knowledge-net

# docker-compose.yml 中使用正确的网络名称
networks:
  default:
    external: true
    name: orion-knowledge_orion-knowledge-net
```

### 问题 6: Go 编译依赖下载超时

**发生时间**: 构建知识库后端 Docker 镜像

**现象**:
```
=> ERROR [build 4/5] RUN go mod download                              30.1s
=> => dial tcp 142.251.33.209:443: i/o timeout
```

**原因**: Docker build 环境无法访问 Google 服务（Go 默认模块代理 sum.golang.org）。

**修复**: 改为本地编译 + 最小 Docker 镜像。

```bash
# 本地编译
cd orion-knowledge/backend
GOOS=linux GOARCH=amd64 go build -o orion-knowledge-api ./cmd/orion-knowledge-api

# 最小 Dockerfile
FROM alpine:3.21
RUN apk add --no-cache ca-certificates tzdata \
    && update-ca-certificates 2>/dev/null || true
WORKDIR /app
COPY orion-knowledge-api /app/orion-knowledge-api
CMD ["/app/orion-knowledge-api"]
```

**优势**:
- 镜像体积从 ~500MB 降到 ~30MB
- 避免网络问题导致的构建失败
- 编译速度更快（利用本地 CPU）

### 问题 7: 迁移文件找不到

**发生时间**: 启动最小 Docker 镜像

**现象**:
```
panic: failed to run migrations: open ./migrations: no such file or directory
```

**原因**: 知识库后端启动时会执行 PostgreSQL 迁移，但最小 Docker 镜像只 copy 了二进制文件。

**修复**:
```dockerfile
FROM alpine:3.21
RUN apk add --no-cache ca-certificates tzdata
WORKDIR /app
COPY orion-knowledge-api /app/orion-knowledge-api
COPY store/pg/migration /app/store/pg/migration  ← 新增
CMD ["/app/orion-knowledge-api"]
```

#### 3.1 入口文件添加微前端生命周期

**文件**: `<子应用>/src/main.tsx`（或 `main.ts`）

这是子应用改造的**核心文件**，需要实现以下功能：

```typescript
import { createRoot, Root } from 'react-dom/client';
import { BrowserRouter } from 'react-router-dom';
import App from './App';

let appRoot: Root | null = null;
let autoRenderTimer: ReturnType<typeof setTimeout> | null = null;

// ============================================
// 1. render 函数：创建 React 应用
// ============================================
function render(props: any = {}) {
  const { container, basename } = props;

  const containerEl = container
    ? container.querySelector('#root')
    : document.querySelector('#root');

  if (!containerEl) {
    console.error('[sub-app] No #root element found!');
    return null;
  }

  // 复用已存在的 React root（HMR 场景）
  let existingRoot: Root | null = null;
  try {
    existingRoot = (containerEl as any).__reactRoot || null;
  } catch { /* ignore */ }

  let root: Root;
  if (existingRoot) {
    root = existingRoot;
    // 微前端模式下防止重复渲染
    if ((window as any).__POWERED_BY_ORION__ && (containerEl as any).__orionRendered) {
      return root;
    }
    (containerEl as any).__orionRendered = true;
  } else {
    root = createRoot(containerEl);
    (containerEl as any).__reactRoot = root;
  }

  root.render(
    <BrowserRouter basename={basename || window.__BASENAME__ || '/'}>
      <App />
    </BrowserRouter>
  );

  return root;
}

// ============================================
// 2. 独立运行模式：延迟检查
// ============================================
function tryAutoRender() {
  if (!(window as any).__POWERED_BY_WUJIE__ && !(window as any).__POWERED_BY_ORION__) {
    appRoot = render();
    console.log('[sub-app] Running in standalone mode');
  }
}
autoRenderTimer = setTimeout(tryAutoRender, 100);

// ============================================
// 3. 微前端生命周期
// ============================================
async function doBootstrap() {
  console.log('[sub-app] bootstrap');
}

async function doMount(container: any, props?: Record<string, unknown>) {
  // 取消自动渲染定时器
  if (autoRenderTimer) {
    clearTimeout(autoRenderTimer);
    autoRenderTimer = null;
  }

  // 兼容 wujie 和 MF 两种调用方式
  const isWujieStyle = !container?.nodeType && !container?.host;
  const effectiveProps = isWujieStyle ? container : props;
  const effectiveContainer = isWujieStyle ? document : container;

  // 设置 basename
  const propsBasename = (effectiveProps as any)?.basename;
  if (propsBasename) {
    window.__BASENAME__ = propsBasename;
  }

  // 包装 window.open
  wrapWindowOpen(propsBasename || '');

  // 设置微前端标志位
  window.__POWERED_BY_WUJIE__ = true;
  window.__POWERED_BY_ORION__ = true;

  // 创建 #root 元素
  let rootEl = effectiveContainer.querySelector('#root');
  if (!rootEl) {
    rootEl = document.createElement('div');
    rootEl.id = 'root';
    effectiveContainer.appendChild(rootEl);
  }

  appRoot = render({ ...effectiveProps, container: effectiveContainer, basename: propsBasename });
}

async function doUnmount() {
  console.log('[sub-app] unmount');
  if (appRoot) {
    appRoot.unmount();
    appRoot = null;
  }
  window.__POWERED_BY_WUJIE__ = false;
}

// ============================================
// 4. 导出
// ============================================
export { doBootstrap as bootstrap, doMount as mount, doUnmount as unmount };

(window as any).bootstrap = doBootstrap;
(window as any).mount = doMount;
(window as any).unmount = doUnmount;
```

#### 3.6 window.open 包装

```typescript
export function wrapWindowOpen(basename: string) {
  if (!basename) return;

  const originalOpen = window.open;
  window.open = function(url, ...args) {
    if (url && typeof url === 'string' && url.startsWith('/')) {
      url = basename + url;
    }
    return originalOpen.call(window, url, ...args);
  };
}
```

**调用时机**: 在 `doMount` 中调用（见 3.1 节）。

### 10.5 Nginx 反向代理配置

生产环境推荐使用一个统一的 Nginx 实例处理所有路由：

```nginx
# /etc/nginx/conf.d/orion.conf
upstream main_app {
    server 127.0.0.1:3000;  # 主应用静态资源
}

upstream gateway {
    server 127.0.0.1:9000;
}

upstream knowledge_admin {
    server 127.0.0.1:3020;  # 知识库前端
}

upstream knowledge_api {
    server 127.0.0.1:8090;  # 知识库后端
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;

    # ── 主应用静态资源 ──
    location / {
        proxy_pass http://main_app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ── 知识库子应用静态资源 + remoteEntry.js ──
    location /orion-knowledge/ {
        proxy_pass http://knowledge_admin;
        proxy_set_header Host $host;
        proxy_cache_valid 200 30d;

        # remoteEntry.js 不缓存
        location = /orion-knowledge/remoteEntry.js {
            proxy_pass http://knowledge_admin;
            add_header Cache-Control "no-cache, no-store, must-revalidate";
        }
    }

    # ── 所有 API 请求 → Gateway ──
    location /api/ {
        proxy_pass http://gateway;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 支持（Pipeline 日志等）
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }

    # ── 知识库 API 直接转发（可选，不经过 Gateway） ──
    # 如果知识库 API 走 Gateway 的 Token Exchange，则不需要此块
    # location /api/v1/knowledge_base/ {
    #     proxy_pass http://knowledge_api;
    #     proxy_set_header Host $host;
    # }

    # ── WebSocket 支持 ──
    location /ws {
        proxy_pass http://gateway;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

## 十二、能力补全记录（2026-05-22）

> 对标大厂微前端治理方案（蚂蚁 qiankun、腾讯 Wujie、美团 Bifrost），补全 Orion-MF 在子应用独立访问认证、标准化通信、智能预加载三个维度的能力。

### 12.1 P0: 子应用独立访问认证 (SSO)

**对标方案**: qiankun SSO 重定向 + Token 回调

**问题**: 知识库子应用只能通过主应用注入 Token，独立访问时无认证入口。

**实现**:

```
用户直接访问 knowledge.example.com/doc
  → App.tsx 检测无 Token 且非微前端模式
  → 重定向到 /login?redirect=/doc
  → 登录成功后携带 sso_token 参数回调
  → App.tsx 提取 sso_token 并存储到 localStorage
  → 清除 URL 参数，正常渲染页面
```

**修改文件**:
- `orion-knowledge/web/admin/src/App.tsx` — 添加 SSO 认证策略、Token 多级回退、SSO 回调处理
- `orion-knowledge/web/admin/src/pages/login/index.tsx` — 添加 SSO 回调逻辑

**认证流程**:
| 模式 | Token 来源 | 无 Token 行为 |
|------|-----------|--------------|
| 微前端模式 | `window.$orion.token` | 由主应用注入，不跳转 |
| 独立访问 | `localStorage.orion_knowledge_token` | 重定向到 SSO 登录页 |
| SSO 回调 | URL 参数 `?sso_token=xxx` | 提取存储后正常渲染 |

### 12.2 P1: 标准化 OrionBus 通信

**对标方案**: qiankun `initGlobalState` + Wujie `wujie.props`/`wujie.bus`

**问题**: 当前通过 `window.$orion` 手动注入，缺乏标准化的事件通信和 owner 清理机制。

**实现**: 新建 `OrionBus` 标准化通信层，支持类型安全的事件通信。
