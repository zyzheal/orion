## 1. SSO 登录流程

```
浏览器访问 Orion Dashboard
    │
    ▼
1. 未登录 → 302 重定向到 SSO
   GET https://sso.company.com/authorize
     ?client_id=orion-platform
     &redirect_uri=https://orion.internal/auth/callback
     &response_type=code
     &scope=openid profile email groups
     &state=random_csrf_token

    │
    ▼
2. 用户在 SSO 登录
   • 已登录公司 SSO → 静默授权，无需再次登录
   • 未登录 → 钉钉/企微扫码 或 输入公司账号密码

    │
    ▼
3. SSO 回调 → Orion 换取 Token
   GET /auth/callback?code=AUTH_CODE&state=random_csrf_token
   
   Orion 后端:
   a. 验证 state 防 CSRF
   b. POST /token 换取 Access Token
   c. GET /userinfo 获取用户信息
   d. 查询用户是否存在 → 不存在则自动创建
   e. 从 HR 系统同步用户角色和部门
   f. 生成 Orion Session Token (JWT)
   g. 设置 HttpOnly Cookie

    │
    ▼
4. 登录成功 → 进入 Dashboard
   Set-Cookie: orion_session=eyJ...; HttpOnly; Secure; SameSite=Strict
   302 → /dashboard
```

## 2. HR 系统自动同步

```python
class HRSyncEngine:
    """
    每天凌晨 2 点从 HR 系统同步组织架构
    • 新入职 → 自动创建账号 + 分配默认角色
    • 转岗 → 更新部门和权限
    • 离职 → 自动禁用账号 + 转移待审批
    """
    
    async def sync(self):
        hr_users = await self.hr_api.get_all_employees()
        orion_users = await self.user_store.get_all()
        
        # 新员工 → 自动创建
        for hr_user in hr_users:
            if hr_user.email not in orion_users:
                await self._create_user(hr_user)
        
        # 离职员工 → 自动禁用
        for orion_user in orion_users.values():
            if orion_user.email not in {u.email for u in hr_users}:
                await self._disable_user(orion_user)
    
    def _map_title_to_role(self, title: str) -> str:
        """职级映射到默认角色"""
        if title in ("P9", "P10", "总监", "VP"):
            return "org_admin"
        elif title in ("P7", "P8", "Tech Lead", "架构师"):
            return "tech_lead"
        elif title in ("P5", "P6", "工程师"):
            return "developer"
        elif title in ("DBA", "数据库管理员"):
            return "dba"
        elif title in ("运维", "SRE"):
            return "sre"
        else:
            return "viewer"
```

## 4. RBAC + ABAC 权限引擎

```python
class PermissionEngine:
    """
    混合权限引擎: RBAC (基于角色) + ABAC (基于属性)
    
    权限格式: "{resource}:{action}:{scope}"
    例: "pipeline:run", "deployment:approve:prod"
    """
    
    def check(self, user, action, resource, context=None):
        # 1. 系统管理员直接通过
        if "orion_admin" in user.roles:
            return ALLOWED
        
        # 2. 禁用用户拒绝所有
        if user.status == DISABLED:
            return DENIED("账号已禁用")
        
        # 3. Deny 规则优先
        if self._check_deny(user, action, resource):
            return DENIED("明确拒绝")
        
        # 4. 角色权限检查 (RBAC)
        if not self._check_role(user, action, resource):
            return DENIED("角色无权限")
        
        # 5. 属性条件检查 (ABAC)
        abac_result = self._check_abac(user, action, resource, context)
        if not abac_result.passed:
            return DENIED(abac_result.reason)
        
        return ALLOWED
    
    def _check_abac(self, user, action, resource, context):
        """ABAC 细粒度条件检查"""
        rules = {
            "deployment:approve:prod": [
                {
                    "condition": "requires_dual_sign",
                    "check": lambda ctx: (
                        ctx.get("approver_1_role") == "tech_lead" and
                        ctx.get("approver_2_role") == "sre"
                    ),
                    "message": "生产部署需 Tech Lead + SRE 双签"
                }
            ],
            "sql:execute:prod": [
                {
                    "condition": "env == prod",
                    "check": lambda ctx: ctx.get("approval_ticket_id") is not None,
                    "message": "生产 SQL 执行需审批工单"
                }
            ],
            "pipeline:run": [
                {
                    "condition": "always",
                    "check": lambda ctx: ctx.get("team_id") in user.team_ids,
                    "message": "只能操作本团队的流水线"
                }
            ],
        }
        # ... 检查规则
```

## 5. 审计日志防篡改

```
防篡改三重保障:

1. 链式 Hash
   ┌──────┐    ┌──────┐    ┌──────┐
   │ Log 1│───→│ Log 2│───→│ Log 3│
   │hash=A│    │hash=B│    │hash=C│
   │prev=∅│    │prev=A│    │prev=B│
   └──────┘    └──────┘    └──────┘
   
   修改任意一条 → 后续所有 hash 不匹配

2. 定期签名
   每小时用私钥对日志块签名
   → 验证签名即可确认未被篡改

3. 三重存储
   • 主存储: Elasticsearch (可搜索)
   • WORM: S3 Object Lock (写入后不可删改)
   • 外部: 实时同步到独立日志服务器
```

## 6. UEBA 异常行为检测

| 规则 | 条件 | 严重级别 | 动作 |
|------|------|---------|------|
| 大量数据导出 | 1h 内导出 > 10 次 | HIGH | 告警 + 拦截 |
| 越权尝试 | 30min 内权限拒绝 > 20 次 | CRITICAL | 告警 + 锁账号 |
| 非工作时间访问敏感资源 | 非 9-18 点 + 访问 prod/secrets | MEDIUM | 告警 |
| API 调用模式异常 | ML 异常分数 > 0.8 | MEDIUM | 告警 |
| 多地同时登录 | 同一账号 > 3 个不同 IP | MEDIUM | 告警 |
| 服务账号滥用 | 服务账号被人类直接使用 | HIGH | 告警 + 吊销 |

## 七、P0 安全修复（2026-04-10）

### 7.1 JWT 并发刷新保护

**问题**：Refresh Token 并发刷新可被劫持（同一 Token 多处同时使用）

**修复方案**：

1. **设备指纹绑定**：Refresh Token 写入时绑定设备指纹
2. **并发刷新检测**：Redis Lua 原子操作检测并发刷新
3. **异常处理**：并发刷新 → 全部吊销 + 告警

```lua
-- Redis Lua 脚本：并发刷新检测
local current = redis.call('GET', key)
if current == token then
    return redis.call('SET', key, new_token)
else
    -- 并发刷新检测，全部吊销
    redis.call('DEL', key)
    return 'REVOKED'
end
```

**关键指标**：
- Access Token 有效期：15 分钟 → 5 分钟
- 并发刷新检测：原子操作
- 异地登录：短信确认 + 告警

详见：`docs/services/security/JWT 并发刷新保护设计.md`

### 7.2 AI 安全加固

**问题**：Prompt 注入可绕过、AI Skill 无沙箱、输出无 DLP

**修复方案**：四层防护架构

1. **L1 输入清洗**：敏感模式检测 + 长度限制 + 特殊字符转义
2. **L2 隔离执行**：系统 Prompt 隔离 + XML 标签封装 + 租户上下文隔离
3. **L3 输出验证**：JSON Schema 校验 + 敏感信息过滤 + 异常响应检测
4. **L4 审计日志**：全量日志 + 异常行为检测 + 实时告警

**检测规则**：12 条内置规则（英文 10 条 + 中文 2 条）

**验收标准**：
- 检测通过率 > 95%
- 误报率 < 1%
- 平均检测延迟 < 50ms

详见：`docs/services/security/ADR-010-Prompt 注入防护设计.md`、`docs/services/security/AI 安全加固设计.md`

### 7.3 自愈引擎权限治理

**问题**：Kintsugi 可执行 DDL/回滚/流量切换，权限风险未治理

**修复方案**：

**高危操作分类**：
| 级别 | 操作 | 审批要求 |
|------|------|---------|
| P0 | 流量切换、回滚部署 | 双签 + 沙箱验证 |
| P1 | 添加索引 (DDL) | 双签 + 沙箱验证 |
| P2 | 限流熔断 | 单人审批 |
| P3 | 重启服务 | 自动执行 + 审计 |
| P4 | 配置变更 | 自动执行 + 审计 |

**自毁开关**：6 类异常检测（错误率>50%、连续失败 3 次等）

详见：`docs/services/security/自愈引擎权限治理设计.md`
