## 执行摘要 (Executive Summary)

本设计文档详细描述 Orion 平台的代码管理与构建环境架构方案。代码管理模块负责统一管理 GitLab/Gerrit 代码源、分支策略、代码质量门禁；构建环境模块负责提供弹性、高效、安全的构建能力，支持多语言、多版本、增量构建场景。

### 设计范围

| 模块 | 核心职责 | 关键组件 |
|------|---------|---------|
| **代码管理** | GitLab/Gerrit 集成、分支策略、质量门禁 | Webhook 适配器、MR 流程引擎、质量扫描器 |
| **构建环境** | Builder 镜像、Runner 管理、缓存策略 | 镜像仓库、K8s Runner、分布式缓存 |
| **构建监控** | 构建时长、成功率、资源使用 | Prometheus 指标、Grafana Dashboard |
| **构建优化** | 并行构建、增量构建、预测性缓存 | 构建图分析、缓存预热、智能调度 |
| **安全构建** | 沙箱隔离、依赖扫描、镜像签名 | 容器沙箱、SCA 扫描、Cosign 签名 |

### 预期收益量化

| 指标 | 当前状态 | 目标状态 | 改善幅度 |
|------|---------|---------|---------|
| 构建平均时长 | 15 分钟 | 8 分钟 | 47% |
| 构建成功率 | 85% | 95% | 12% |
| 缓存命中率 | 40% | 85% | 112% |
| Runner 利用率 | 35% | 70% | 100% |
| 代码审查覆盖率 | 60% | 95% | 58% |
| 安全漏洞检出率 | 70% | 99% | 41% |

### 1.2 多代码源集成架构

Orion 平台需要支持多种代码源，通过适配器模式实现统一抽象：

| 代码源 | 适用场景 | 集成方式 | 优先级 |
|--------|---------|---------|--------|
| **GitLab** | 主代码源，90% 项目 | Webhook + REST API + SSH | P0 |
| **Gerrit** | 遗留项目，特定团队 | Stream Events + SSH API | P1 |
| **GitHub** | 开源项目、外部依赖 | Webhook + REST API | P2 |
| **Gitee** | 国内镜像、合规要求 | Webhook + REST API | P3 |

| `Merge Request Hook (open)` | `mr.opened` | AIReviewTrigger | P0 |
| `Merge Request Hook (update)` | `mr.updated` | AIReviewRefresh | P1 |
| `Merge Request Hook (merge)` | `mr.merged` | MergeHandler | P0 |

| `Pipeline Hook` | `pipeline.completed` | StatusWriter | P1 |

| `Note Hook` | `comment.created` | ChatOpsHandler | P2 |

## 二、分支策略 (Branch Strategy)

### 2.1 分支模型总览

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                           Git Flow Branching Model                               │
└─────────────────────────────────────────────────────────────────────────────────┘

                                    ┌──────────────────────────┐
                                    │      main (生产)          │
                                    │  (保护分支，需 MR 合并)     │
                                    └────────────┬─────────────┘
                                                 │
              ┌──────────────────────────────────┼──────────────────────────────────┐
              │                                  │                                  │
              ▼                                  ▼                                  ▼
    ┌─────────────────┐               ┌─────────────────┐              ┌─────────────────┐
    │   develop       │               │   release/v*    │              │   hotfix/*      │
    │   (集成分支)     │               │   (发布分支)     │              │   (热修复)       │
    └────────┬────────┘               └────────┬────────┘              └────────┬────────┘
             │                                  │                                │
             │  feature/*                       │                                │
             │  (功能分支)                      │                                │
             │                                  │                                │
    ┌────────▼────────┐                        │                                │
    │ feature/login   │◀────── 开发者日常开发 ────┘                                │
    │ feature/payment │                                                           │
    │ feature/order   │                                                           │
    └─────────────────┘                                                           │
                                                                                  │
    分支命名规范:                                                                   │
    ├── main              # 生产分支，永远指向最新稳定版本                           │
    ├── develop           # 开发集成分支，指向最新待发布代码                         │
    ├── feature/*         # 功能分支，从 develop 切出，合并回 develop                  │
    ├── release/*         # 发布分支，从 develop 切出，合并到 main 和 develop           │
    └── hotfix/*          # 热修复分支，从 main 切出，合并到 main 和 develop            │

┌─────────────────────────────────────────────────────────────────────────────────┐
│                           Trunk Based Branching Model                            │
└─────────────────────────────────────────────────────────────────────────────────┘

                                    ┌──────────────────────────┐
                                    │      main (主干)          │
                                    │  (保护分支，短生命周期分支) │
                                    └────────────┬─────────────┘
                                                 │
              ┌──────────────────────────────────┼──────────────────────────────────┐
              │                                  │                                  │
              ▼                                  ▼                                  ▼
    ┌─────────────────┐               ┌─────────────────┐              ┌─────────────────┐
    │ feature/login   │               │ feature/payment │              │ feature/order   │
    │ (≤3 天生命周期)  │               │ (≤3 天生命周期)  │               │ (≤3 天生命周期)  │
    └─────────────────┘               └─────────────────┘              └─────────────────┘

    适用场景：
    ├── 高频发布团队（日级发布）
    ├── 小型功能快速迭代
    └── Feature Flag 控制功能可见性

    分支命名规范:
    ├── main              # 主干分支，随时可部署
    ├── feature/{jira-id}-{description}  # 功能分支，短生命周期
    ├── fix/{jira-id}-{description}    # 修复分支
    └── experiment/{description}        # 实验分支，可能不合并
```

### 3.4 重复率控制

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                         Code Duplication Control                                 │
└─────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────────┐
│  重复代码检测规则 (Code Duplication Detection)                                   │
└─────────────────────────────────────────────────────────────────────────────────┘

    检测粒度:
    ├── 精确重复 (Exact Duplicate)
    │   └── 完全相同的代码块（忽略空白和注释）
    │
    ├── 语义重复 (Semantic Duplicate)
    │   └── 逻辑相同但变量名/结构略有差异
    │
    └── 模板重复 (Template Duplicate)
        └── 相似模式重复出现（如相似的 if-else 链）

    阈值配置:
    ├── 重复块最小行数：5 行
    ├── 文件重复率上限：5%
    ├── 项目重复率上限：3%
    └── 单个重复块最大允许：100 行

    重复率计算:
    ┌─────────────────────────────────────────────────────────────────────────────┐
    │  重复率 = (重复代码行数 / 总有效代码行数) × 100%                             │
    │                                                                              │
    │  判定规则:                                                                    │
    │  ├── 重复率 ≤ 5%    → ✅ 通过                                                 │
    │  ├── 5% < 重复率 ≤ 10% → ⚠️  警告 (需解释)                                    │
    │  └── 重复率 > 10%   → ❌ 失败 (必须重构)                                      │
    └─────────────────────────────────────────────────────────────────────────────┘

    例外情况 (需审批):
    ├── 自动生成的样板代码
    ├── 性能优化需要的内联代码
    ├── 测试数据/ Fixture 代码
    └── 接口实现的必需方法 (如 toString, equals)
```

                       │ • 访问审计                   │

    环境              验证严格度                    违规处理

    │
    └── 开发环境
        (Development)  │ • 建议验证                   │ 仅警告
                       │ • 允许跳过                   │
