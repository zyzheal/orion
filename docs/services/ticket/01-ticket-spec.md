# 工单与 ITSM 详细规格 (Phase 1)

> **日期**: 2026-07-02
> **状态**: 已验证
> **能力域**: 8. 工单与 ITSM
> **目标成熟度**: L2 → L3
> **关键交付**: 工单生命周期、智能排单、SLA、自助门户

## 一、功能描述

### 1.1 现状评估 (L2)

Orion 当前已实现：
- 工单 CRUD（TicketingService + TicketRepository + ticketing-routes）
- 工单状态流转（open/in_progress/resolved/closed）
- 工单分类（incident/request/problem/change）
- 智能派单基础（基于规则的自动分配）
- 工单详情页面（TicketDetail 前端页面）
- 工单关系管理（relations API）

**不足**：
- 自助服务门户缺失（用户无法自行提交/跟踪工单）
- SLA 管理不完整（SLA 定义存在但未在工单中强制执行）
- 自动化规则缺失（无自动分类/分配/升级）
- 工单模板缺失（无预定义模板）
- SLA 可视化缺失（无 SLA 计时器/预警）
- 知识库关联不完整

### 1.2 Phase 1 目标 (L3)

| 功能模块 | 描述 | 验收等级 |
|----------|------|:--------:|
| 自助门户 | 工单提交/跟踪/历史 | L3 |
| SLA 管理 | SLA 定义、计时、预警、升级 | L3 |
| 自动化规则 | 自动分类/分配/升级/关闭 | L3 |
| 工单模板 | 预定义模板、自定义模板 | L3 |

## 二、验收标准

### 2.1 自助门户

| # | 标准 | 验证方式 |
|---|------|----------|
| T1 | 用户可通过门户提交工单（选择分类/描述/优先级） | 前端验证 |
| T2 | 用户可查看自己提交的工单列表 | 前端验证 |
| T3 | 用户可查看工单详情（状态/处理人/时间线） | 前端验证 |
| T4 | 门户页面支持空状态引导 | 前端验证 |

### 2.2 SLA 管理

| # | 标准 | 验证方式 |
|---|------|----------|
| S1 | SLA 按工单分类/优先级定义响应时间和解决时间 | API 测试 |
| S2 | 工单创建后自动启动 SLA 计时器 | 集成测试 |
| S3 | SLA 即将超时（>80%）发送预警通知 | 集成测试 |
| S4 | SLA 超时后自动升级（通知上级/变更优先级） | 集成测试 |
| S5 | SLA 仪表盘展示达标率 | 前端验证 |

### 2.3 自动化规则

| # | 标准 | 验证方式 |
|---|------|----------|
| A1 | 根据工单标题/描述自动分类 | 集成测试 |
| A2 | 根据历史分配数据自动推荐处理人 | 集成测试 |
| A3 | 工单超过 7 天无更新自动提醒 | 集成测试 |
| A4 | 工单满足解决条件自动关闭 | 集成测试 |

### 2.4 工单模板

| # | 标准 | 验证方式 |
|---|------|----------|
| P1 | 预置 5+ 模板：故障报告/服务请求/变更申请/问题报告/权限申请 | 前端验证 |
| P2 | 模板包含预填字段和引导说明 | 前端验证 |
| P3 | 管理员可自定义工单模板 | API 测试 |

## 三、API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/tickets` | 工单列表 |
| POST | `/api/v1/tickets` | 创建工单 |
| GET | `/api/v1/tickets/:id` | 工单详情 |
| PUT | `/api/v1/tickets/:id` | 更新工单 |
| GET | `/api/v1/sla/definitions` | SLA 定义列表 |
| POST | `/api/v1/sla/definitions` | 创建 SLA 定义 |
| GET | `/api/v1/tickets/templates` | 工单模板列表 |
| POST | `/api/v1/tickets/templates` | 创建模板 |
