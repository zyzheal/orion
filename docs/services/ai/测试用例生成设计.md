# 测试用例生成设计

> 版本：v1.0 | 创建日期：2026-04-11 | 状态：草案

---

## 1. 概述

### 1.1 设计目标

基于 AI 的代码变更分析，智能推荐和生成测试用例，提高测试覆盖率，减少人工编写测试的时间。

**对应需求**: US-3.4 — 作为开发者，我想要 AI 推荐新增测试用例，以便提高覆盖率

### 1.2 核心能力

| 能力 | 说明 | 优先级 |
|------|------|--------|
| 代码变更分析 | AST 解析、影响面分析 | P0 |
| 覆盖率缺口识别 | 识别未覆盖的分支/路径 | P0 |
| 测试推荐算法 | 基于历史模式推荐测试 | P0 |
| 测试用例生成 | 自动生成测试代码框架 | P1 |
| 测试数据生成 | 生成边界值/异常数据 | P1 |
| 测试效果评估 | 预估覆盖率提升 | P1 |

## 4. 覆盖率缺口识别

### 4.1 覆盖率数据模型

```json
{
  "file": "UserService.java",
  "method_coverage": {
    "calculateDiscount": {
      "line_coverage": 0.75,
      "branch_coverage": 0.50,
      "covered_lines": [10, 11, 12, 15],
      "uncovered_lines": [13, 14],
      "branches": [
        {"id": 1, "covered": true, "condition": "vipLevel > 0"},
        {"id": 2, "covered": false, "condition": "vipLevel > 5"}
      ]
    }
  },
  "class_coverage": 0.68,
  "last_updated": "2026-04-11T10:00:00Z"
}
```

### 4.2 缺口识别算法

```python
def identify_coverage_gaps(change_analysis, coverage_data):
    """
    识别覆盖率缺口
    
    Args:
        change_analysis: 代码变更分析结果
        coverage_data: 当前覆盖率数据
    
    Returns:
        覆盖率缺口列表
    """
    gaps = []
    
    for changed_method in change_analysis['changed_methods']:
        method_name = changed_method['name']
        coverage = coverage_data['method_coverage'].get(method_name)
        
        if not coverage:
            # 新增方法，无覆盖率
            gaps.append({
                'type': 'new_method',
                'method': method_name,
                'priority': 'high',
                'suggestion': f'为新增方法 {method_name} 编写单元测试'
            })
            continue
        
        # 检查分支覆盖
        for branch in coverage.get('branches', []):
            if not branch['covered']:
                gaps.append({
                    'type': 'uncovered_branch',
                    'method': method_name,
                    'branch': branch['condition'],
                    'priority': 'medium',
                    'suggestion': f'测试 {branch["condition"]} 分支'
                })
        
        # 检查行覆盖
        if coverage['line_coverage'] < 0.8:
            gaps.append({
                'type': 'low_line_coverage',
                'method': method_name,
                'coverage': coverage['line_coverage'],
                'uncovered_lines': coverage['uncovered_lines'],
                'priority': 'low',
                'suggestion': f'提高 {method_name} 的行覆盖率 (当前 {coverage["line_coverage"]*100:.0f}%)'
            })
    
    return sorted(gaps, key=lambda x: priority_order(x['priority']))
```

## 5. 测试推荐算法

### 5.1 基于历史模式的推荐

```
┌─────────────────────────────────────────────────────────────────────────┐
│  基于历史模式的测试推荐                                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  历史数据：                                                             │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  代码变更模式 → 测试用例模式                                     │   │
│  ├─────────────────────────────────────────────────────────────────┤   │
│  │  新增参数 → 测试参数边界值 (null, 最小值，最大值，异常值)         │   │
│  │  新增分支 → 测试每个分支的真/假情况                              │   │
│  │  新增异常处理 → 测试异常触发条件                                 │   │
│  │  修改循环 → 测试空集合/单元素/多元素                             │   │
│  │  修改计算逻辑 → 测试精度/溢出/边界                               │   │
│  └─────────────────────────────────────────────────────────────────┘   │
│                                                                         │
│  推荐流程：                                                             │
│  1. 识别当前代码变更模式                                               │
│  2. 匹配历史相似变更                                                   │
│  3. 复用历史测试模式                                                   │
│  4. 生成定制化测试建议                                                 │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 5.2 推荐优先级矩阵

| 变更类型 | 影响范围 | 测试优先级 | 推荐测试数 |
|---------|---------|-----------|-----------|
| 新增方法 | 无调用方 | P0 | 3-5 个 |
| 新增方法 | 有调用方 | P0 | 5-8 个 |
| 修改方法 | 低风险 | P1 | 2-3 个 |
| 修改方法 | 中风险 | P0 | 4-6 个 |
| 修改方法 | 高风险 | P0 | 6-10 个 |
| 删除方法 | 无调用方 | P2 | 0 个 |
| 删除方法 | 有调用方 | P0 | 回归测试调用方 |

### 7.2 Tekton Task 定义

```yaml
apiVersion: tekton.dev/v1beta1
kind: Task
metadata:
  name: test-recommendation
spec:
  params:
    - name: PR_NUMBER
      type: string
    - name: REPO_URL
      type: string
    - name: COVERAGE_THRESHOLD
      type: string
      default: "80"
  
  steps:
    - name: analyze-coverage
      image: orion/test-analyzer:latest
      script: |
        analyze_coverage \
          --repo $(params.REPO_URL) \
          --pr $(params.PR_NUMBER) \
          --output coverage-report.json
    
    - name: generate-recommendations
      image: orion/test-analyzer:latest
      script: |
        generate_recommendations \
          --coverage coverage-report.json \
          --threshold $(params.COVERAGE_THRESHOLD) \
          --output recommendations.json
    
    - name: post-comment
      image: orion/gitlab-commenter:latest
      script: |
        post_comment \
          --repo $(params.REPO_URL) \
          --pr $(params.PR_NUMBER) \
          --file recommendations.json
```

## 8. 推荐准确率评估

### 8.1 评估指标

| 指标 | 计算公式 | 目标值 |
|------|---------|--------|
| **采纳率** | 开发者采纳的推荐数 / 总推荐数 | >40% |
| **准确率** | 有效的推荐数 / 总推荐数 | >70% |
| **覆盖率提升** | 使用推荐后的覆盖率提升 | +5-10% |
| **生成代码可用率** | 生成代码无需修改直接可用 | >50% |

### 8.2 反馈收集

```yaml
反馈机制:
  显式反馈:
    - 👍 有用的推荐
    - 👎 无用的推荐
    - 评论：具体原因
  
  隐式反馈:
    - 推荐被采纳 (自动检测)
    - 生成代码被提交 (自动检测)
    - 推荐被忽略 (自动检测)
  
  反馈应用:
    - 优化推荐算法
    - 调整模板库
    - 改进 Prompt 设计
```
