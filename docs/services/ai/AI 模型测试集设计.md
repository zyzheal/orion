## 一、概述

### 1.1 设计目的

本文档定义 Orion 平台 AI 模型测试集的功能设计，包括测试集来源、采集流程、分类标注、版本管理、基线管理、模型评估、偏差检测及 A/B 测试等核心功能。

### 1.2 术语定义

| 术语 | 定义 |
|------|------|
| 测试集 (Test Set) | 用于模型最终评估的独立数据集，不参与训练或调参 |
| 验证集 (Validation Set) | 用于模型调参和早停的数据集 |
| 训练集 (Training Set) | 用于模型训练的数据集 |
| 基线 (Baseline) | 模型性能的最低可接受标准 |
| 黄金集 (Golden Set) | 经过人工严格标注的高质量测试样本集合 |

### 1.3 测试集总览

| 测试集名称 | 对应模型 | 样本量 | 来源 | 更新频率 |
|-----------|---------|--------|------|---------|
| CodeReview-Test-500 | CodeReview-v2 | 500 条 | 生产 PR + 人工构造 | 月度 |
| RiskAssess-Test-1000 | RiskAssess-v1 | 1000 条 | 历史发布记录 | 月度 |
| LogAnalysis-Test-300 | LogAnalysis-v1 | 300 条 | 故障工单 + 日志归档 | 季度 |
| SQLReview-Test-200 | SQLReview-v1 | 200 条 | 生产 SQL + 人工构造 | 月度 |
| LLM-Output-Golden-1000 | 所有 LLM Skill | 1000 条 | 多场景构造 | 周度 |

## 二、测试集来源与采集流程

### 2.1 数据来源分类

#### 2.1.1 生产数据 (Production Data)

从生产环境中采集真实业务数据，具有最高的代表性和可信度。

| 数据源 | 采集内容 | 采集方式 | 频率 |
|-------|---------|---------|------|
| Git 仓库 | PR Diff、Code Review 评论 | Webhook + API 轮询 | 实时 |
| 发布系统 | 发布记录、回滚事件、故障报告 | 数据库同步 | 实时 |
| 日志系统 | 异常日志、根因分析结果 | ELK API | 每日 |
| 工单系统 | 故障工单、问题描述、解决方案 | ServiceNow API | 每日 |
| SQL 审计 | SQL 语句、执行计划、性能问题 | 数据库审计日志 | 每日 |

#### 2.1.2 人工构造数据 (Synthetic Data)

针对特定场景和边界条件，由算法团队人工构造的测试样本。

| 构造类型 | 用途 | 负责人 | 审核要求 |
|---------|------|--------|---------|
| 边界案例 | 测试模型在极端条件下的表现 | 算法工程师 | Tech Lead |
| 对抗样本 | 测试模型鲁棒性 | 算法工程师 | 架构师 |
| 多语言样本 | 测试多语言支持能力 | 算法工程师 | Tech Lead |
| 复杂场景 | 测试多问题并发处理能力 | 资深算法工程师 | 架构师 |

#### 2.1.3 公开数据集 (Public Datasets)

引入业界公开的标准数据集用于横向对比。

| 数据集 | 用途 | 适配方式 |
|-------|------|---------|
| BigCodeBench | 代码审查能力基准 | 格式转换 + 采样 |
| HumanEval | 代码生成能力基准 | 格式转换 |
| Defects4J | 缺陷检测能力基准 | 格式转换 + 标注 |

### 2.3 数据采集详细步骤

#### 步骤 1：数据源接入

| 步骤 | 操作 | 输出 | 验收标准 |
|-----|------|------|---------|
| 1.1 | 配置数据源连接 | 连接配置 | 连接成功，权限验证通过 |
| 1.2 | 定义数据采集规则 | 采集配置 | 规则覆盖所有目标数据 |
| 1.3 | 执行初始全量采集 | 原始数据 | 数据完整，无大量缺失 |
| 1.4 | 配置增量采集任务 | 定时任务 | 按预期频率执行 |

#### 步骤 2：数据预处理

| 步骤 | 操作 | 输出 | 验收标准 |
|-----|------|------|---------|
| 2.1 | 敏感信息脱敏 | 脱敏数据 | 无敏感信息泄露 |
| 2.2 | 数据格式标准化 | 标准格式数据 | 符合 Schema 定义 |
| 2.3 | 噪声数据过滤 | 清洗后数据 | 无效数据已移除 |
| 2.4 | 数据去重 | 去重后数据 | 重复率 < 1% |

#### 步骤 3：质量校验

| 步骤 | 操作 | 输出 | 验收标准 |
|-----|------|------|---------|
| 3.1 | 完整性检查 | 完整性报告 | 关键字段完整率 > 99% |
| 3.2 | 一致性检查 | 一致性报告 | 数据逻辑一致 |
| 3.3 | 标注抽样验证 | 质量评分 | 抽样准确率 > 95% |

### 2.4 数据脱敏规范

| 数据类型 | 脱敏方式 | 示例 |
|---------|---------|------|
| 用户 ID | 哈希脱敏 | `user_abc123` → `user_xxx` |
| 数据库连接串 | 完全替换 | `jdbc:mysql://prod-db:3306/pay_db` → `jdbc:mysql://<REDACTED>` |
| API Key/Token | 完全替换 | `sk-xxxxx` → `<API_KEY>` |
| 内部 IP 地址 | 网段保留 | `10.1.2.3` → `10.x.x.x` |
| 业务金额 | 范围化 | `12345.67` → `[10000-50000]` |

### 3.1 测试集分类体系

#### 3.1.1 按难度分级

| 级别 | 定义 | 占比 | 用途 |
|-----|------|------|------|
| L1 - 基础 | 单一问题，明确答案 | 40% | 基础能力验证 |
| L2 - 中等 | 多问题并发，需要推理 | 35% | 综合能力验证 |
| L3 - 困难 | 复杂场景，边界条件 | 20% | 高级能力验证 |
| L4 - 专家 | 对抗样本，极端场景 | 5% | 鲁棒性验证 |

| 类别 | 子类别 | 样本量 | 说明 |

## 五、基线管理与阈值设定

### 5.1 基线定义

基线是模型性能的最低可接受标准，用于判断模型是否可以上线或需要回滚。

#### 5.1.1 基线指标体系

| 指标类型 | 指标名称 | 定义 | 计算方式 |
|---------|---------|------|---------|
| 准确率 | Precision | 预测为正中实际为正的比例 | TP / (TP + FP) |
| 召回率 | Recall | 实际为正中被正确预测的比例 | TP / (TP + FN) |
| 综合指标 | F1-Score | 准确率和召回率的调和平均 | 2PR / (P + R) |
| 误报率 | FPR | 实际为负被错误预测为正的比例 | FP / (FP + TN) |
| 延迟指标 | P50/P95/P99 | 不同百分位的响应延迟 | 延迟分布统计 |
| 稳定性 | 降级率 | 触发降级的请求比例 | 降级次数 / 总请求数 |

### 6.3 评估指标计算

#### 6.3.1 二分类指标计算

```
评估指标计算流程：

1. 构建混淆矩阵：
   
                    预测正例    预测负例
   实际正例           TP          FN
   实际负例           FP          TN

2. 计算指标：
   - Precision = TP / (TP + FP)
   - Recall = TP / (TP + FN)
   - F1-Score = 2 * Precision * Recall / (Precision + Recall)
   - FPR = FP / (FP + TN)
   - Accuracy = (TP + TN) / (TP + TN + FP + FN)

3. 多分类扩展：
   - Macro Average: 各类别指标简单平均
   - Weighted Average: 各类别指标按样本数加权平均
```

#### 6.3.2 回归指标计算

| 指标 | 公式 | 说明 |
|-----|------|------|
| MAE | (1/n) * Σ|y - ŷ| | 平均绝对误差 |
| MSE | (1/n) * Σ(y - ŷ)² | 均方误差 |
| RMSE | √MSE | 均方根误差 |
| MAPE | (1/n) * Σ|(y - ŷ) / y| | 平均绝对百分比误差 |
| R² | 1 - SSE/SST | 决定系数 |

## 七、测试集偏差检测

### 7.1 偏差类型定义

| 偏差类型 | 定义 | 影响 |
|---------|------|------|
| 样本选择偏差 | 测试样本不能代表真实分布 | 评估结果失真 |
| 标注偏差 | 标注员主观倾向导致 | 模型学习错误模式 |
| 时间偏差 | 数据过时，不能反映当前情况 | 模型表现下降 |
| 语言偏差 | 某些语言/框架样本过多或过少 | 模型能力不均衡 |
| 难度偏差 | 难度分布不合理 | 评估过于乐观或悲观 |

### 7.2 偏差检测方法

#### 7.2.1 分布对比检测

```
偏差检测流程：

1. 收集参考分布：
   - 生产环境的真实数据分布
   - 历史数据的统计分布

2. 计算测试集分布：
   - 类别分布
   - 难度分布
   - 语言/技术栈分布
   - 时间分布

3. 分布对比：
   - KL 散度计算
   - 卡方检验
   - 可视化对比

4. 偏差判定：
   - 偏差阈值设定
   - 偏差等级划分
   - 告警触发
```

#### 7.2.2 偏差检测指标

| 检测方法 | 指标 | 阈值 | 说明 |
|---------|------|------|------|
| KL 散度 | D_KL(P||Q) | < 0.1 | 测试集与生产分布差异 |
| 卡方检验 | χ² p-value | > 0.05 | 类别分布显著性 |
| 多样性指数 | Shannon Entropy | > 2.0 | 样本多样性 |
| 代表性评分 | Coverage Score | > 0.85 | 覆盖生产场景比例 |

### 7.3 偏差处理策略

| 偏差类型 | 处理策略 |
|---------|---------|
| 样本选择偏差 | 重新采样，增加缺失类别样本 |
| 标注偏差 | 多人标注 + 专家仲裁，计算标注一致性 |
| 时间偏差 | 定期更新测试集，淘汰过时样本 |
| 语言偏差 | 按生产分布调整各类别样本比例 |
| 难度偏差 | 调整难度分布，确保合理梯度 |

|  inconclusive | 样本量不足/数据异常 | 重新设计实验 |

## 九、模型回归测试策略

### 9.1 回归测试定义

回归测试确保模型更新不会导致性能下降，是模型上线前的必要步骤。

### 9.2 回归测试范围

| 测试类型 | 测试内容 | 频率 |
|---------|---------|------|
| 功能回归 | 核心功能是否正确 | 每次模型更新 |
| 性能回归 | 延迟、吞吐量是否正常 | 每次模型更新 |
| 基线回归 | 是否满足基线要求 | 每次模型更新 |
| 边界回归 | 边界条件是否正确处理 | 重大更新 |

### 9.3 回归测试策略

#### 9.3.1 测试优先级

```

```

#### 9.3.2 回归测试用例选择

| 选择策略 | 说明 | 覆盖率 |
|---------|------|--------|
| 全量回归 | 运行所有测试用例 | 100% |
| 智能回归 | 基于变更影响分析选择用例 | 60-80% |
| 核心回归 | 只运行 P0 级别用例 | 20-30% |
| 增量回归 | 只测试变更相关功能 | 10-20% |

### 9.5 回归判定标准

| 回归类型 | 通过标准 | 不通过处理 |
|---------|---------|-----------|
| 基线回归 | 所有核心指标 >= 基线 | 分析原因，必要时回滚 |
| 功能回归 | 100% P0 用例通过 | 修复后重新测试 |
| 性能回归 | P95 延迟 <= 基线 * 1.1 | 性能优化或回滚 |
| 对比回归 | 相比上一版本无显著下降 | 分析差异原因 |
