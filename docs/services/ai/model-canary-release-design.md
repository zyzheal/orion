## 1. 背景与问题

### 1.1 现状分析

Orion AI 平台当前模型发布流程采用"全量切换"模式，新模型训练完成后直接替换线上服务。这种发布方式存在以下核心问题：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    当前模型发布流程                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  模型训练 ──► 离线评估 ──► 人工审核 ──► 全量切换 ──► 用户反馈        │
│                              │                                      │
│                              ▼                                      │
│                        高风险点：无缓冲                              │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.2 历史故障案例

| 时间 | 事件 | 影响 | 根因 |
|------|------|------|------|
| 2025-11 | 意图识别模型 v2.3 直接上线 | 15% 用户请求误分类，持续 2 小时 | 训练数据分布与线上差异未检出 |
| 2025-12 | 代码生成模型 v1.8 更新 | API 错误率从 0.5% 飙升至 8% | 边缘 case 处理逻辑缺陷 |
| 2026-01 | 推荐模型 v3.0 发布 | 用户点击率下降 22%，4 小时后回滚 | 冷启动场景性能退化 |

### 1.3 核心问题总结

1. **缺乏渐进式验证**：模型从训练环境直接进入生产环境，无中间验证阶段
2. **监控指标单一**：仅依赖准确率，忽视延迟、吞吐量等业务指标
3. **回滚成本高**：全量切换后发现问题，回滚需要重新部署，耗时 15-30 分钟
4. **无 A/B 测试能力**：无法科学对比新旧模型效果

### 2.2 版本命名规范

采用语义化版本控制 (SemVer) 扩展规范：

```
格式：<主版本>.<次版本>.<修订版本>[-<预发布标识>][+<元数据>]

示例：
  2.3.1          - 生产环境稳定版本
  2.4.0-rc1      - 发布候选版本 1
  2.4.0-beta2    - 测试版本 2
  2.4.0-alpha3   - 内部预览版本 3
  2.3.1+hotfix1  - 热修复版本

版本语义：
┌─────────┬──────────────────────────────────────────────────────────┐
│ 主版本  │ 不兼容的 API 变更或模型架构重大调整                        │
│ 次版本  │ 向后兼容的功能增强，性能提升≥10%                         │
│ 修订版  │ 向后兼容的问题修复，热更新                               │
└─────────┴──────────────────────────────────────────────────────────┘
```

### 2.3 兼容性保证矩阵

| 变更类型 | 版本升级规则 | 兼容性要求 | 审批级别 |
|----------|-------------|-----------|---------|
| 模型架构变更 | 主版本++ | 不保证兼容，需迁移方案 | P0 评审 |
| 输入/输出 Schema 变更 | 主版本++ | 不保证兼容 | P0 评审 |
| 性能优化 (≥10%) | 次版本++ | 输出结果差异<1% | P1 评审 |
| 准确率提升 | 次版本++ | 无回归 | P1 评审 |
| Bug 修复 | 修订版本++ | 完全兼容 | P2 评审 |
| 配置调整 | 修订版本++ | 完全兼容 | P2 评审 |

**影子模式执行要点：**

| 项目 | 说明 |
|------|------|
| 流量处理 | 100% 请求同时发送给生产模型和影子模型 |
| 响应策略 | 仅返回生产模型结果，影子模型结果丢弃 |
| 数据采集 | 记录影子模型预测结果、延迟、置信度 |
| 持续时间 | 最少 7 天，覆盖完整业务周期 |
| 通过标准 | 核心指标偏差<5%，无严重异常 |

### 6.2 哈希一致性路由算法

```
算法：基于用户 ID 的一致性哈希

输入：
  - user_id: 用户唯一标识
  - experiment_config: 实验配置（包含各版本流量占比）
  - salt: 随机种子（用于实验重新分片）

输出：
  - target_version: 目标模型版本

伪代码：
  function route_by_hash(user_id, experiment_config, salt):
    hash_input = md5(user_id + salt + experiment_id)
    hash_value = hex_to_int(hash_input[0:8])
    normalized = hash_value / 0xFFFFFFFF  # 归一化到 [0, 1]

    cumulative = 0
    for version, weight in experiment_config.versions:
      cumulative += weight
      if normalized < cumulative:
        return version

    return experiment_config.default_version

特性：
  - 同一用户始终路由到同一版本（实验期间）
  - 调整流量占比时，影响最小化
  - 支持动态添加/移除实验版本
```

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      统计显著性计算流程                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  输入数据：                                                                 │
│    Control 组: n1=15234, mean1=0.9234, std1=0.0123                         │
│    Treatment 组：n2=15187, mean2=0.9387, std2=0.0118                       │
│                                                                             │
│  计算步骤：                                                                 │
│                                                                             │
│  1. 计算 t 统计量：                                                          │
│                mean2 - mean1                                                 │
│     t = ───────────────────────────────────── = 10.23                      │
│         √(std1²/n1 + std2²/n2)                                              │
│                                                                             │
│  2. 计算自由度 (Welch-Satterthwaite):                                       │
│     df ≈ 28456                                                              │
│                                                                             │
│  3. 计算 p-value：                                                           │
│     p-value = 2 × P(T > |t|) = 1.23e-24  << 0.05                           │
│                                                                             │
│  4. 计算效应量 (Cohen's d):                                                  │
│     d = (mean2 - mean1) / pooled_std = 0.0127 (小效应)                      │
│                                                                             │
│  5. 计算置信区间：                                                           │
│     95% CI: [0.0123, 0.0183]                                                │
│                                                                             │
│  结论：                                                                     │
│    ✓ p-value < 0.05，差异统计显著                                           │
│    ✓ 置信区间不包含 0，结果可靠                                               │
│    ⚠ 效应量较小，需结合业务判断实际价值                                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 7.4 多重检验校正

```
当同时检验多个指标时，需要进行多重检验校正：

┌─────────────────────────────────────────────────────────────────────────────┐
│                         校正方法对比                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  方法              │ 适用场景          │ 保守程度 │ 本系统选择              │
│  ─────────────────│──────────────────│─────────│────────────────────────  │
│  Bonferroni       │ 独立或少量指标     │ 最保守  │ ✓ 默认方法               │
│  Holm-Bonferroni  │ 相关指标          │ 较保守  │ 备选                     │
│  Benjamini-Hochberg│ 探索性分析       │ 较宽松  │ 高级配置                 │
│  No Correction    │ 单一主要指标      │ 无校正  │ 不推荐                   │
│                                                                             │
│  Bonferroni 校正规则：                                                       │
│    校正后阈值 α' = α / n (n 为检验次数)                                       │
│    例如：α=0.05, n=5 个指标 → α'=0.01                                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 附录 B：术语表

| 术语 | 定义 |
|------|------|
| 影子模式 (Shadow Mode) | 新模型接收生产流量但不返回结果，仅用于观察和对比 |
| 金丝雀发布 (Canary) | 将少量流量导向新版本，逐步验证稳定性 |
| A/B 测试 | 同时运行两个版本，通过统计检验对比效果 |
| 统计显著性 | 观察到的差异由随机因素导致的概率 (p-value) |
| 效应量 (Effect Size) | 差异的实际大小，独立于样本量 |
| Guardrail 指标 | 必须维持的底线指标，恶化即触发回滚 |
| 流量路由 | 根据策略将请求分发到不同模型版本 |
