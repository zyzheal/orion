## 二、成本数据采集流程

### 2.1 K8s 资源成本采集

```
┌─────────────────────────────────────────────────────────────────┐
│              K8s 资源成本采集流程                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  步骤 1: 采集 Pod 资源用量                                       │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • 从 Prometheus 获取 Pod CPU/Memory 实际用量               │   │
│  │ • 从 K8s API 获取 Pod Request/Limit 配置                  │   │
│  │ • 关联 Namespace → 团队/项目                              │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  步骤 2: 计算资源成本                                           │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • CPU 成本 = CPU 用量 (Core) × CPU 单价 (元/Core/小时)     │   │
│  │ • Memory 成本 = Memory 用量 (GB) × Memory 单价 (元/GB/小时) │   │
│  │ • 存储成本 = PVC 容量 (GB) × 存储单价 (元/GB/月)          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  步骤 3: 成本分摊                                               │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • 按 Namespace 分摊到团队                                  │   │
│  │ • 按 Label 分摊到项目                                      │   │
│  │ • 共享资源按用量比例分摊                                   │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  采集频率：每 5 分钟                                             │
│  存储：ClickHouse (历史数据) + Redis (实时数据)                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 三、成本分摊模型

### 3.1 三级分摊架构

```
┌─────────────────────────────────────────────────────────────────┐
│              成本三级分摊架构                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Level 1: 组织级分摊                                             │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 总成本 → 各事业部/部门                                     │   │
│  │ 分摊依据：团队 Namespace 资源用量                          │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  Level 2: 团队级分摊                                             │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 团队成本 → 各项目/产品线                                   │   │
│  │ 分摊依据：项目 Label 标记的资源用量                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  Level 3: 项目级分摊                                             │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 项目成本 → 各环境/分支                                     │   │
│  │ 分摊依据：环境/分支的资源用量                              │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  分摊示例：                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 总成本：100 万元/月                                        │   │
│  │                                                         │   │
│  │ → 研发事业部：60 万 (60%)                                 │   │
│  │   → 支付团队：20 万                                       │   │
│  │     → payment-service: 15 万                              │   │
│  │       → production: 10 万                                │   │
│  │       → staging: 3 万                                   │   │
│  │       → development: 2 万                               │   │
│  │     → order-service: 5 万                               │   │
│  │                                                         │   │
│  │ → 运维事业部：30 万 (30%)                                 │   │
│  │ → 数据事业部：10 万 (10%)                                 │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 共享资源分摊

```
┌─────────────────────────────────────────────────────────────────┐
│              共享资源成本分摊规则                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  共享资源类型：                                                  │
│  • 共享 Runner 池：多个团队共用                                  │
│  • 共享集群：多租户 K8s 集群                                     │
│  • 公共服务：监控/日志/配置中心                                  │
│                                                                 │
│  分摊规则：                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 1. 按用量比例分摊                                         │   │
│  │    团队 A 分摊 = 团队 A 用量 / 总用量 × 总成本               │   │
│  │                                                         │   │
│  │ 2. 按配额比例分摊（用量无法精确计量时）                    │   │
│  │    团队 A 分摊 = 团队 A 配额 / 总配额 × 总成本               │   │
│  │                                                         │   │
│  │ 3. 按固定比例分摊（约定比例）                              │   │
│  │    团队 A 分摊 = 总成本 × 约定比例                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  分摊示例 - 共享 Runner 池：                                      │
│  ┌──────────────┬──────────┬──────────┬────────────┐          │
│  │ 团队          │ 使用时长  │ 占比      │ 分摊成本    │          │
│  ├──────────────┼──────────┼──────────┼────────────┤          │
│  │ 支付团队      │ 500 分钟   │ 50%      │ 500 元      │          │
│  │ 订单团队      │ 300 分钟   │ 30%      │ 300 元      │          │
│  │ 用户团队      │ 200 分钟   │ 20%      │ 200 元      │          │
│  ├──────────────┼──────────┼──────────┼────────────┤          │
│  │ 合计          │ 1000 分钟  │ 100%     │ 1000 元     │          │
│  └──────────────┴──────────┴──────────┴────────────┘          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 四、预算与告警

### 4.1 预算管理流程

```
┌─────────────────────────────────────────────────────────────────┐
│              预算管理流程                                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  步骤 1: 预算设定                                                │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • 按团队设定月度预算                                      │   │
│  │ • 按项目设定月度预算                                      │   │
│  │ • 按环境设定月度预算                                      │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  步骤 2: 预算执行监控                                            │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • 实时计算预算使用率：已用/预算 × 100%                    │   │
│  │ • 每日汇总成本数据                                        │   │
│  │ • 预测月底成本：当前日均 × 剩余天数                        │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  步骤 3: 预算告警                                                │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • 使用率 > 50% → 提醒通知                                 │   │
│  │ • 使用率 > 80% → 警告通知                                 │   │
│  │ • 使用率 > 100% → 严重告警 + 限制非关键操作                │   │
│  │ • 预测超支 → 提前预警                                     │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  告警渠道：钉钉/企微/邮件/短信                                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 告警规则配置

```yaml
# 预算告警规则配置示例

告警规则:
  - 名称：预算使用率 50%
    条件：预算使用率 > 50%
    频率：每日 9:00
    渠道：钉钉
    内容："{team} 本月预算已使用 50%，当前花费{amount}元"
  
  - 名称：预算使用率 80%
    条件：预算使用率 > 80%
    频率：实时
    渠道：钉钉 + 邮件
    内容："{team} 本月预算已使用 80%，请尽快审查支出"
  
  - 名称：预算超支
    条件：预算使用率 > 100%
    频率：实时
    渠道：钉钉 + 邮件 + 短信
    内容："{team} 本月预算已超支，当前花费{amount}元，预算{budget}元"
  
  - 名称：预测超支
    条件：预测月底成本 > 预算
    频率：每周一 9:00
    渠道：邮件
    内容："{team} 预计月底花费{predicted}元，超出预算{budget}元"
```

```

│  │    • 检测到零散请求 → 建议批量处理                         │   │
│  │    • 示例："测试生成请求可批量处理，预计节省 20% 成本"      │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  输出：优化建议报告（含预计节省金额）                             │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 成本优化建议示例

| 优化项 | 当前状态 | 建议 | 预计节省 |
|--------|---------|------|---------|
| **Runner 规格** | 全部使用 4C8G | 非关键任务使用 2C4G | 30%/月 |
| **构建缓存** | 未启用缓存 | 启用依赖缓存 | 40%/月 |
| **镜像清理** | 保留所有版本 | 只保留最近 10 个 | 25%/月 |
| **AI 模型** | 全部使用 GPT-4 | 简单任务用 Qwen-3 | 50%/月 |
| **闲时资源** | 夜间不缩容 | 夜间缩容到 50% | 20%/月 |
