## 三、监控指标体系

### 3.1 指标分层

```
L1 - 基础设施指标 (Infrastructure)
├── Node CPU/Memory/Disk/Network
├── Kubernetes Pod/Container 资源
├── MySQL 数据库指标
├── Redis 指标
└── NATS 消息队列指标

L2 - 应用服务指标 (Application)
├── API 服务 (QPS, 延迟，错误率)
├── WebSocket 连接数
└── 后台任务队列

L3 - 业务指标 (Business)
├── 流水线执行量/成功率
├── 审批处理时长
├── 部署频率/成功率
└── AI Skill 调用量/准确率

L4 - 用户体验指标 (Experience)
├── 页面加载时间
├── API P95/P99 延迟
└── 用户操作成功率
```

### 3.3 SLO 定义

| 指标 | SLO 目标 | 计算方式 | 告警阈值 |
|------|---------|---------|---------|
| API 可用性 | 99.9% | (总请求 - 5xx)/总请求 | < 99.5% |
| API P95 延迟 | < 200ms | histogram_quantile(0.95) | > 300ms |
| API P99 延迟 | < 500ms | histogram_quantile(0.99) | > 800ms |
| 流水线成功率 | > 95% | success/(success+failed) | < 90% |
| 审批处理时长 P90 | < 4 小时 | histogram_quantile(0.90) | > 8 小时 |
| 部署成功率 | > 98% | success/(success+rollback) | < 95% |
| WebSocket 连接成功率 | > 99% | success/(success+failed) | < 98% |

## 四、告警配置

### 4.1 告警级别

| 级别 | 名称 | 响应时间 | 通知渠道 | 示例 |
|------|------|---------|---------|------|
| P0 | Critical | 5 分钟 | 电话 + 短信 + IM | 服务不可用、数据丢失 |
| P1 | High | 15 分钟 | 短信 + IM | 核心功能受损 |
| P2 | Medium | 1 小时 | IM | 性能下降、非核心功能异常 |
| P3 | Low | 4 小时 | IM | 轻微问题、可自愈 |

### 4.2 Prometheus AlertManager 规则

```yaml
# 核心服务告警
groups:
- name: orion-core
  interval: 30s
  rules:
  # P0 - API 服务不可用
  - alert: OrionAPIUnavailable
    expr: |
      sum(up{job="orion-api"}) == 0
    for: 1m
    labels:
      severity: critical
      team: platform
    annotations:
      summary: "Orion API 服务完全不可用"
      description: "所有 API 副本都已下线，立即介入"
      runbook_url: "https://wiki.internal/runbooks/orion-api-unavailable"
      
  # P0 - MySQL 连接完全失败
  - alert: MySQLConnectionFailure
    expr: |
      mysql_up == 0
    for: 1m
    labels:
      severity: critical
      team: platform
    annotations:
      summary: "MySQL 数据库完全不可用"
      description: "MySQL 数据库已宕机，立即介入"
      
  # P0 - 数据库连接失败
  - alert: MySQLConnectionFailure
    expr: |
      mysql_global_status_threads_connected == 0
    for: 2m
    labels:
      severity: critical
      team: platform
    annotations:
      summary: "MySQL 连接完全失败"
      description: "数据库可能已宕机"
      
  # P0 - MySQL 复制中断
  - alert: MySQLReplicationBroken
    expr: |
      mysql_slave_status_slave_sql_running == 0
      or
      mysql_slave_status_slave_io_running == 0
    for: 2m
    labels:
      severity: critical
      team: platform
    annotations:
      summary: "MySQL 复制中断"
      description: "从库复制线程已停止，检查主从状态"
      
  # P1 - MySQL 复制延迟过高
  - alert: MySQLReplicationLag
    expr: |
      mysql_slave_status_seconds_behind_master > 60
    for: 5m
    labels:
      severity: high
      team: platform
    annotations:
      summary: "MySQL 复制延迟超过 60 秒"
      description: "当前复制延迟 {{ $value }} 秒"
      
  # P1 - MySQL 连接池接近上限
  - alert: MySQLConnectionsHigh
    expr: |
      mysql_global_status_threads_connected 
      / 
      mysql_global_variables_max_connections 
      > 0.8
    for: 5m
    labels:
      severity: high
      team: platform
    annotations:
      summary: "MySQL 连接池使用率超过 80%"
      description: "当前连接池使用率 {{ $value | humanizePercentage }}"
      
  # P2 - MySQL 慢查询增多
  - alert: MySQLSlowQueries
    expr: |
      rate(mysql_global_status_slow_queries[5m]) > 10
    for: 10m
    labels:
      severity: medium
      team: platform
    annotations:
      summary: "MySQL 慢查询速率超过 10 次/秒"
      description: "当前慢查询速率 {{ $value }} 次/秒"
      
  # P1 - API 错误率升高
  - alert: OrionAPIHighErrorRate
    expr: |
      sum(rate(http_requests_total{service="orion-api", status=~"5.."}[5m])) 
      / 
      sum(rate(http_requests_total{service="orion-api"}[5m])) 
      > 0.05
    for: 5m
    labels:
      severity: high
      team: platform
    annotations:
      summary: "API 错误率超过 5%"
      description: "当前错误率 {{ $value | humanizePercentage }}"
      
  # P1 - API 延迟升高
  - alert: OrionAPIHighLatency
    expr: |
      histogram_quantile(0.95, 
        sum(rate(http_request_duration_seconds_bucket{service="orion-api"}[5m])) 
        by (le)) 
      > 0.3
    for: 5m
    labels:
      severity: high
      team: platform
    annotations:
      summary: "API P95 延迟超过 300ms"
      description: "当前 P95 延迟 {{ $value | humanizeDuration }}"
      
  # P2 - 流水线失败率升高
  - alert: PipelineHighFailureRate
    expr: |
      sum(rate(pipeline_runs_total{status="failed"}[1h])) 
      / 
      sum(rate(pipeline_runs_total[1h])) 
      > 0.1
    for: 10m
    labels:
      severity: medium
      team: platform
    annotations:
      summary: "流水线失败率超过 10%"
      description: "当前失败率 {{ $value | humanizePercentage }}"
      
  # P2 - 待处理审批堆积
  - alert: ApprovalBacklog
    expr: |
      approvals_pending_count > 100
    for: 30m
    labels:
      severity: medium
      team: platform
    annotations:
```

### 6.3 DR 切换流程

```
1. 检测故障
   └── 监控系统触发告警
   └── 确认主站点不可用

2. DNS 切换
   └── 更新 GSLB 配置，将流量导向 DR 站点
   └── TTL: 60 秒，预计 2-5 分钟生效

3. 数据库提升
   └── 确认 DR 数据库已应用最新 WAL
   └── 提升 DR 数据库为可写主库

4. 服务启动
   └── 启动 DR 站点 Orion 服务
   └── 验证服务健康状态

5. 验证
   └── 运行冒烟测试
   └── 确认核心功能正常

6. 通知
   └── 发送故障切换完成通知
   └── 持续监控 DR 站点负载
```

## 九、P0 SRE 运维修复（2026-04-10）

### 9.1 MySQL 主从延迟分级降级

**问题**：主从延迟无降级策略，可能导致读旧数据

**修复方案**：详见 [SRE 运维加固设计](./SRE 运维加固设计.md)

| 级别 | 延迟阈值 | 告警级别 | 降级动作 |
|------|---------|---------|---------|
| Level 1 | >10s | P2 | 暂停从库分析查询 |
| Level 2 | >30s | P1 | 从库读请求降至 20% |
| Level 3 | >60s | P0 | 从库读请求 100% 切断 |

### 9.2 Redis 哨兵脑裂处理

**问题**：脑裂时可能出现多 Master

**修复方案**：
```
检测多 Master → 冻结写入 → 投票选择保留 Master
                                    ↓
                              重建主从关系
                                    ↓
                              数据冲突解决 (时间戳优先)
```

### 9.3 ClickHouse 备份方案

**问题**：ClickHouse 无备份策略

**修复方案**：
```yaml
工具：clickhouse-backup
全量备份：每天 2:00 AM
增量备份：每小时
PITR 恢复：任意时间点
保留策略：全量 30 天，增量 7 天
```

### 9.4 告警抑制规则

**问题**：告警风暴风险

**修复方案**：7 条告警抑制规则

1. **维护窗口静默**：计划内维护不触发告警
2. **节点故障抑制**：节点故障抑制所有相关告警
3. **数据库故障抑制**：数据库故障抑制应用层告警
4. **网络故障抑制**：网络故障抑制下游告警
5. **级联故障只报根因**：只报根因告警
6. **重复告警 4 小时内不重复通知**
7. **已知问题静默**：关联 Issue 自动静默
