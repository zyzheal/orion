## 一、灾备架构总览

### 1.1 灾备等级与目标

```
┌─────────────────────────────────────────────────────────────────┐
│              Orion 灾备等级定义                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  灾备等级：同城双活 + 异地灾备                                   │

│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                         │   │
│  │  主中心：北京机房 (承载 100% 生产流量)                       │   │

│  │  • PostgreSQL 主库 + 从库                                 │   │

│  │  • PostgreSQL 从库 (异步复制)                             │   │
│  │  • NATS 集群 (3 节点，消息复制)                            │   │

│  │                                                         │   │

│                                                                 │
│  RTO (恢复时间目标) 与 RPO (恢复点目标)                           │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                         │   │
│  │  核心服务 (API/Pipeline/AI):                              │   │
│  │  • RTO: < 5 分钟  (5 分钟内恢复服务)                        │   │
│  │  • RPO: < 30 秒  (最多丢失 30 秒数据)                       │   │
│  │                                                         │   │
│  │  非核心服务 (看板/报表/通知):                              │   │
│  │  • RTO: < 30 分钟                                        │   │
│  │  • RPO: < 5 分钟                                         │   │
│  │                                                         │   │
│  │  数据归档服务 (审计日志/备份):                             │   │
│  │  • RTO: < 4 小时                                         │   │
│  │  • RPO: < 1 小时                                         │   │
│  │                                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 二、故障切换流程

### 2.1 故障检测与确认

```
┌─────────────────────────────────────────────────────────────────┐
│              故障检测与确认流程                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  步骤 1: 故障检测                                                │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                         │   │
│  │  检测方式：                                              │   │
│  │  • 健康检查：每 10 秒检测核心服务健康状态                   │   │
│  │  • 指标监控：错误率、延迟、可用性实时监测                 │   │
│  │  • 拨测：从外部定期发起请求验证服务可用性                 │   │
│  │  • 日志监控：错误日志激增检测                            │   │
│  │                                                         │   │
│  │  触发条件 (满足任一即触发):                               │   │
│  │  • 健康检查连续失败 3 次                                  │   │
│  │  • API 错误率 > 50% 持续 1 分钟                            │   │
│  │  • 所有节点不可达                                        │   │
│  │  • 机房网络中断                                          │   │
│  │                                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  步骤 2: 故障确认                                                │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                         │   │
│  │  确认流程 (避免误判):                                    │   │
│  │  1. 多检测源确认 (至少 2 个独立检测源报告故障)             │   │
│  │  2. 跨网络确认 (从不同网络区域检测)                       │   │
│  │  3. 人工确认 (P0 故障需 On-Call 人员确认)                  │   │
│  │                                                         │   │
│  │  确认超时：                                              │   │
│  │  • P0 故障：30 秒内确认                                   │   │
│  │  • P1 故障：1 分钟内确认                                  │   │
│  │  • 超时自动确认：5 分钟后自动确认                         │   │
│  │                                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  步骤 3: 故障通告                                                │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                                                         │   │
│  │  通知对象：                                              │   │
│  │  • On-Call 工程师 (电话 + 短信)                           │   │
│  │  • SRE 团队 (钉钉群)                                     │   │
│  │  • 技术负责人 (邮件 + 短信)                               │   │
│  │  • 业务方代表 (邮件)                                     │   │
│  │                                                         │   │
│  │  通知内容：                                              │   │
│  │  • 故障时间                                              │   │
│  │  • 影响范围 (服务/用户/功能)                             │   │
│  │  • 检测结果 (错误率/不可达节点)                          │   │
│  │  • 建议措施 (切换/等待/降级)                             │   │
│  │                                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

```
│            │                                                   │
│            ▼                                                   │
│  T+0:30    步骤 2: 数据库切换 (60 秒)                             │

│            │  • 更新数据库连接配置                              │   │

│            ▼                                                   │

│            │  • 激活 NATS 消息消费                               │   │

│            ▼                                                   │
│  T+2:30    步骤 4: 流量验证 (60 秒)                              │
│            │                                                   │
│            │  • 10% 流量验证                                    │   │
│            │  • 健康检查通过                                    │   │
│            │  • 核心功能验证                                    │   │
│            │                                                   │
│            ▼                                                   │
│  T+3:30    步骤 5: 全量切换 (30 秒)                              │
│            │                                                   │
│            │  • 100% 流量切换到上海机房                          │   │

│            ▼                                                   │

│            │                                                   │
│            │  • 监控指标恢复正常                                │   │
│            │  • 错误率<1%                                       │   │
│            │  • 通知切换完成                                    │   │
│            │                                                   │
│            ▼                                                   │
│  T+5:00    切换完成 (RTO = 5 分钟)                                │
│                                                                 │
│  切换后状态：                                                    │
│  • 上海机房承载 100% 流量                                         │

│                                                                 │
```
