## 二、全系统 P0 缺失清单 (25 项)

### 架构层
1. **微前端架构** - 设计为 1 基座+7 子应用，实际单体前端
2. **API Gateway 独立服务** - 无限流/熔断/版本化
3. **服务物理分离** - 所有服务同进程

### AI 层
4. **向量数据库集成** - 无语义检索能力
5. **Token 计费 SDK** - 无法追溯 AI 成本
6. **XGBoost 风险模型** - AI 风险评估仅靠规则引擎

### SRE 层
7. **OnCall 排班系统** - 告警响应无管理机制
8. **灾备切换自动化** - 无法自动执行 DR 切换
9. **5-Agent 自愈架构** - 缺沙箱验证和 PageRank 根因定位

### 安全层
10. **Prompt 注入防护** - AI 安全核心能力缺失
11. **OPA 真实集成** - 策略引擎无真实执行
12. **SBOM 生成** - 供应链安全无保障

### 数据库层
13. **数据持久化** - 30+ 服务使用 Map() 模拟存储
14. **RLS 行级安全** - 多租户数据未隔离
15. **ClickHouse 集成** - 无法进行大数据量分析

### 集成层
16. **NATS 真实消息总线** - 事件仅内存发布
17. **外部系统适配器** - Harbor/Nexus/Gerrit 均无代码

### 制品层
18. **5 阶段制品状态机** - 无法实现制品晋升流程
19. **多级审批流程** - 无合规管控
20. **Neo4j 依赖图** - 无依赖关系图谱

### 效能层
21. **自动周报模块** - Tech Lead 核心需求

### CICD 层
22. **真实插件执行** - 插件在沙箱外执行

### 前端层
23. **API 路径一致性** - ~30 处前后端路径不一致
24. **API 路径一致性** - 运行时 404 错误 (重复归入 API 层)

## 四、跨领域共性问题

### 1. Map() 模拟存储 (影响 30+ 服务)
- 数据库、制品、安全、架构等多个领域均使用 `new Map()` 代替真实数据库
- 这是**最大的系统级技术债务**，影响数据持久性

### 2. 文档-代码脱节 (影响 8/12 领域)
- 设计文档详尽(260份)但代码实现仅 43%
- 已实现功能未在文档中更新记录（如 FinOps 完整功能）
- INDEX.md 引用不存在的设计文档

### 3. API 路径不一致 (~30 处)
- 前端 API 客户端与后端路由路径不匹配
- 影响多模块运行时 404 错误

### 4. 测试覆盖不均
- 效能模块测试覆盖率 5/5，而数据库/制品/IaC 仅 1/5
- 测试集中在 Service 层，Engine 和 API 层测试极少

### 5. 前端优于后端
- 前端页面(~72%)实现度高于后端(~45%)
- AI Review/AI Gateway 等页面前端完成但后端仅框架
