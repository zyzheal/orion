## 1. 统一评分体系

### 评分维度及权重

| 维度 | 权重 | 说明 |
|------|------|------|
| **H**andler Maturity | 20% | 基于 handler 方法数、代码结构规范度 |
| **S**ervice Layer | 20% | 基于 service 方法数、接口定义完备度 |
| **R**epository Layer | 20% | 基于 repo 方法数、接口定义、CRUD 完备度 |
| **T**est Coverage | 15% | 基于测试文件数量 |
| **F**rontend Coverage | 15% | 基于前端 API 文件和页面映射 |
| **Rt** Route Registration | 10% | 是否有 RegisterRoutes 入口 |

### 评分公式

```
总分 = H×0.20 + S×0.20 + R×0.20 + T×0.15 + F×0.15 + Rt×0.10
```

各维度评分标准 (0-10):
- **H/S/R**: 5 分基础（有完整三层架构）+ 增量（方法数/复杂度）
- **T**: 0 分（无测试）~ 10 分（2+ 测试文件，测试覆盖核心路径）
- **F**: 0 分（无前端）~ 10 分（完整 CRUD 前端 + API 客户端）
- **Rt**: 0 分（无 RegisterRoutes）~ 10 分（有 RegisterRoutes）

## 13. Identity 子模块分析

**路径**: `orion-platform-svc-go/internal/identity/`

### 子模块总览

| 子模块 | Handler 文件 | Handler 行数 | Handler 方法 | Service 方法 | Repo 方法 | RegisterRoutes | 测试 |
|--------|------------|-------------|-------------|-------------|----------|---------------|------|
| auth | 7 | 1,705 | 38 | 11 | 47 | 否 | 0 |
| user | 2 | 429 | 17 | 19 | 20 | 否 | 0 |
| tenant | 2 | 464 | 14 | 17 | 24 | 否 | 0 |
| apikey | 2 | ~99 | 4 | 3 | 3 | 是 | 0 |
| confirmation | 2 | ~99 | 4 | 3 | 3 | 是 | 0 |
| session | 2 | ~99 | 4 | 3 | 3 | 是 | 0 |
| sso | 2 | ~99 | 4 | 3 | 3 | 是 | 0 |
| role | 0 | 0 | 0 | 0 | 0 | 无 | 0 |
| **总计** | **19** | **~3,005** | **85** | **59** | **103** | **4/9** | **0** |

### 关键发现

1. **无测试覆盖**: 整个 identity 模块 0 个测试文件，8 个子模块均无单元测试
2. **架构模式不统一**: 4 个模块 (apikey, confirmation, session, sso) 使用规整的 RegisterRoutes 模式，而 auth, tenant, user 三个复杂模块将路由注册外部化
3. **auth 模块最为庞大**: 占所有 handler 方法数的 45% (38/85)，含 5 个独立的 Handler struct
4. **role 模块仅存 model**: 仅有 models 文件，角色功能实现在 user 模块的 RBACService 中
5. **sso 和 auth 的 SSO 功能重叠**: sso/ 目录是独立的轻量级 SSO 提供者 CRUD，而 auth/ssosvc/ 和 auth/handler/oidc_handler.go 实现了完整 OIDC 协议流程

### 功能重叠映射

```
identity/auth (38 handlers, 47 repo methods)
  ├── OIDC SSO ←→ identity/sso (CRUD 提供者)
  ├── MFA ←→ auth-mfa (独立模块)
  ├── User CRUD ←→ user (独立模块) + identity/user
  ├── Tenant ←→ tenant (独立模块) + identity/tenant
  ├── Session ←→ session (独立模块) + identity/session
  └── Permission ←→ permission (独立模块) + role
```

## 总结

### 核心发现 (5 项)

1. **10 域统一评分**: 最高 capability (9.35) > 最低 abac-policy (6.30)，平均分 7.86
2. **功能重叠严重**: 5 处 identity 子模块与独立模块功能重叠，建议废弃 identity 子模块中的重复实现
3. **identity 路由未注册**: 3 个核心 identity 子模块 (auth/user/tenant) 共 69 个 handler 方法未注册到路由
4. **前端 API 缺失**: auth-enhanced 和 auth-mfa 缺少前端 API 客户端
5. **测试覆盖不均**: 10 域模块有测试，但 identity 全部 8 个子模块 0 测试

### 建议优先级

| 优先级 | 行动 | 影响域 | 工作量 |
|--------|------|--------|--------|
| P0 | 废弃 identity/auth/user/tenant，统一到独立模块 | 重叠清理 | 中 |
| P0 | 补齐 auth-enhanced 前端 API 客户端 | 前端完整性 | 小 |
| P1 | 为 identity 子模块添加 RegisterRoutes 或彻底废弃 | 路由完整性 | 中 |
| P1 | 补齐 auth-mfa 前端 API 客户端 | 前端完整性 | 小 |
| P2 | 为 identity 子模块添加测试覆盖 | 测试完整性 | 大 |
| P2 | 统一 SSO 策略 (auth-enhanced/wechat vs identity/auth/oidc vs identity/sso) | 架构统一 | 大 |
