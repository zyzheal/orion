# WebSocket 单例管理详细设计

> 版本：v1.0 | 创建日期：2026-04-10 | 状态：设计稿

---

## 1. 背景与问题

### 1.1 问题陈述

在当前 Orion 前端架构中，WebSocket 连接采用组件级 Hook 模式（useWebSocket），每个组件实例独立管理自己的 WebSocket 连接。这种设计在多 Tab 场景下存在严重问题：

### 1.2 核心问题诊断

#### 问题一：多 Tab 重复连接

```
用户打开 5 个 Tab
     │
     ├─ Tab 1 ──> WebSocket 连接 #1
     ├─ Tab 2 ──> WebSocket 连接 #2
     ├─ Tab 3 ──> WebSocket 连接 #3
     ├─ Tab 4 ──> WebSocket 连接 #4
     └─ Tab 5 ──> WebSocket 连接 #5

结果：单个用户建立 5 个独立 WebSocket 连接
      - 服务器资源浪费 5 倍
      - 消息重复推送 5 份
      - 认证 Token 重复验证 5 次
```

**影响分析：**

| 指标 | 单连接 | 5 Tab 重复连接 | 放大倍数 |
|------|--------|----------------|----------|
| 服务器连接数 | 1 | 5 | 5x |
| 内存占用（客户端） | ~100KB | ~500KB | 5x |
| 消息推送带宽 | 1 份 | 5 份 | 5x |
| 心跳包开销 | 1 个/30s | 5 个/30s | 5x |

#### 问题二：内存泄漏风险

```
组件挂载 ──> 创建 WebSocket 连接
     │
     └─> 组件卸载 ──> cleanup 未正确执行 ──> 连接未关闭
                                              │
                                              ▼
                                    后台定时器持续运行
                                    事件监听器未移除
                                    消息队列未清理
                                    闭包引用未释放
```

**泄漏路径分析：**

1. **定时器泄漏**：心跳定时器、重连定时器未清除
2. **事件监听器泄漏**：WebSocket 事件回调未移除
3. **闭包引用泄漏**：回调函数持有组件状态引用
4. **消息队列泄漏**：待发送消息积压未清理

#### 问题三：状态不一致

```
Tab A                         Tab B
  │                             │
  ├─ 用户操作断开连接            │
  │   connectionState = CLOSED  │
  │                             │
  │                    Tab B 仍显示 CONNECTED
  │                    用户看到过期状态
  │                             │
```

### 1.3 设计目标

| 目标 | 说明 | 验收标准 |
|------|------|----------|
| 单例连接 | 同浏览器多 Tab 共享单连接 | 打开 N 个 Tab 仅建立 1 个 WebSocket |
| 零泄漏 | 无内存泄漏风险 | 长期运行内存增长 < 5MB/小时 |
| 状态同步 | Tab 间连接状态实时同步 | 状态变更 < 100ms 同步到所有 Tab |
| 高可用 | 连接故障自动恢复 | 重连成功率 > 99% |
| 可观测 | 完整监控指标 | 连接数、重连率、延迟可追踪 |

### 2.3 单例实现模式

```typescript
// 单例模式实现示意
class WebSocketManager {
  private static instance: WebSocketManager | null = null;

  private constructor() {
    // 私有构造函数
  }

  public static getInstance(): WebSocketManager {
    if (!WebSocketManager.instance) {
      WebSocketManager.instance = new WebSocketManager();
    }
    return WebSocketManager.instance;
  }

  // 禁止克隆
  private clone() { throw new Error('Singleton cannot be cloned'); }
}
```

### 2.4 主 Tab 选举机制

由于多 Tab 共享单例，需要选举一个"主 Tab"来维护实际 WebSocket 连接：

```
┌─────────────────────────────────────────────────────────────────┐
│                    主 Tab 选举流程                               │
└─────────────────────────────────────────────────────────────────┘

  Tab A 打开          Tab B 打开          Tab C 打开
     │                   │                   │
     ▼                   ▼                   ▼
  ┌─────────┐       ┌─────────┐       ┌─────────┐
  │检查锁   │       │检查锁   │       │检查锁   │
  │无锁     │       │有锁     │       │有锁     │
  └────┬────┘       └────┬────┘       └────┬────┘
       │                 │                 │
       ▼                 │                 │
  ┌─────────┐            │                 │
  │获取锁   │            │                 │
  │成为主 Tab│            │                 │
  └────┬────┘            │                 │
       │                 ▼                 ▼
       │           ┌─────────┐       ┌─────────┐
       │           │成为从 Tab│       │成为从 Tab│
       │           │监听广播 │       │监听广播 │
       │           └─────────┘       └─────────┘
       │
       ▼
  ┌─────────────────────────────────┐
  │      主 Tab 心跳续约 (每 5s)      │
  │      localStorage.lock = expiry │
  └─────────────────────────────────┘
       │
       │ 主 Tab 关闭/崩溃
       ▼
  ┌─────────┐       ┌─────────┐
  │锁过期   │       │锁过期   │
  │竞抢新锁 │       │竞抢新锁 │
  └─────────┘       └─────────┘
```

**锁实现细节：**

```
锁数据结构：
{
  "ws_manager_lock": {
    "tabId": "tab_abc123",      // 持有锁的 Tab ID
    "timestamp": 1234567890,    // 获取锁时间
    "expiry": 1234567895        // 锁过期时间（+5s）
  }
}

续约逻辑：
- 主 Tab 每 2s 检查一次锁，剩余时间 < 2s 时续约
- 从 Tab 每 1s 检查锁状态，发现过期立即尝试获取
```

### 3.2 消息类型定义

```
┌─────────────────────────────────────────────────────────────────┐

│                                                                  │

│     方向：主 Tab → 从 Tab                                        │

│                                                                  │

│     方向：主 Tab → 从 Tab                                        │

│                                                                  │

│     触发：新主 Tab 选举成功时                                    │
│                                                                  │
│  7. LOCK_RELEASED                                               │
│     方向：原主 Tab → 所有 Tab                                    │
│     内容：{ tabId: string, reason: string }                     │

## 4. 连接管理

### 4.1 连接状态机

```
┌─────────────────────────────────────────────────────────────────┐
│                    WebSocket 连接状态机                          │
└─────────────────────────────────────────────────────────────────┘

                          ┌─────────────┐
                          │  INITIAL    │
                          │  (初始状态)  │
                          └──────┬──────┘
                                 │ connect()
                                 ▼
                          ┌─────────────┐
                    ┌─────│ CONNECTING  │─────┐
                    │     │ (连接中)    │     │ 连接失败
                    │     └──────┬──────┘     │
                    │            │ 连接成功    │
                    │            ▼            │
                    │     ┌─────────────┐     │
                    │     │  CONNECTED  │     │
                    │     │ (已连接)    │     │
                    │     └──────┬──────┘     │
                    │            │            │
          主动断开  │    心跳超时 │    网络断开 │
          ▼       │       ▼     │       ▼     │
    ┌─────────┐   │   ┌─────────┐   │   ┌─────────┐
    │ CLOSED  │   │   │RECONNECTING│ │   │ ERROR   │
    │ (关闭)  │   │   │ (重连中)  │   │ (错误)   │
    └─────────┘   │   └────┬────┘   │   └────┬────┘
                  │        │         │        │
                  │        │ 重连成功 │        │ 重试
                  │        └─────────┴────────┘
                  │
                  │ reconnect()
                  ▼
            ┌─────────────┐
            │ RECONNECTING │
            └─────────────┘
```

### 4.2 状态转换表

| 当前状态 | 事件 | 目标状态 | 动作 |
|----------|------|----------|------|
| INITIAL | connect() | CONNECTING | 创建 WebSocket 实例 |
| CONNECTING | open 事件 | CONNECTED | 启动心跳，广播状态 |
| CONNECTING | error 事件 | RECONNECTING | 启动重连流程 |
| CONNECTED | close 事件 (正常) | CLOSED | 清理资源，广播状态 |
| CONNECTED | close 事件 (异常) | RECONNECTING | 启动重连流程 |
| CONNECTED | heartbeat timeout | RECONNECTING | 启动重连流程 |
| RECONNECTING | connect 成功 | CONNECTED | 重置计数，广播状态 |
| RECONNECTING | connect 失败 | RECONNECTING | 指数退避，增加计数 |
| RECONNECTING | max attempts | ERROR | 降级处理，通知用户 |
| ERROR | reconnect() | RECONNECTING | 重置计数，尝试重连 |
| ANY | disconnect() | CLOSED | 清理所有资源 |

│  #5          16s          ±20%          12.8s ~ 19.2s          │
│  #6          30s (上限)   ±20%          24s ~ 36s              │
│  #7+         30s (上限)   ±20%          24s ~ 36s              │
│                                                                  │
│  计算公式：                                                      │
│  delay = min(initialDelay * multiplier^(attempt-1), maxDelay)   │
│  actualDelay = delay * (1 + (random() - 0.5) * 2 * jitter)     │
│                                                                  │
│  参数配置：                                                      │
│  - initialDelay: 1000ms                                         │
│  - multiplier: 2                                                │
│  - maxDelay: 30000ms                                            │
│  - jitter: 0.2 (±20%)                                           │
│  - maxAttempts: 10                                              │
│                                                                  │
│  随机抖动目的：                                                  │
│  - 避免多客户端同时重连导致服务器压力集中                        │
│  - 防止"重连风暴"                                                │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 9. 总结

### 9.1 设计要点回顾

| 模块 | 核心设计 | 解决的问题 |
|------|----------|------------|
| 单例管理 | WebSocketManager + LocalStorage 锁 | 多 Tab 重复连接 |
| Tab 通信 | BroadcastChannel + LocalStorage 降级 | 状态同步 |
| 连接管理 | 状态机 + 心跳 + 指数退避重连 | 连接可靠性 |
| Token 刷新 | 定时检查 + 服务器通知双触发 | 认证连续性 |
| 错误处理 | 分级处理 + 降级策略 | 用户体验 |
| 性能优化 | 消息缓冲 + 压缩 + 可见性感知 | 资源效率 |
| 监控指标 | 完整指标体系 + 告警规则 | 可观测性 |

### 9.2 实施建议

1. **分阶段实施**：先实现单例管理，再逐步添加其他功能
2. **充分测试**：重点测试多 Tab 场景、网络切换、Token 过期场景
3. **灰度发布**：先小范围用户验证，观察监控指标
4. **回滚预案**：保留旧版 useWebSocket Hook 作为降级方案
