## 1. 概述

### 1.1 目的

本文档定义 Orion 平台 AI 自动化场景中**人工确认交互**的设计规范，确保用户体验一致、高效、可追溯。

### 1.2 适用范围

| 范围 | 说明 |
|------|------|
| 适用场景 | 所有需要人工确认的 AI 自动化场景 |
| 适用平台 | Web 工作台、移动端 (钉钉/企微/飞书)、电话/短信 |
| 适用角色 | 开发者、Tech Lead、SRE、DBA、管理员 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **分层确认** | 根据紧急度选择推送渠道 (P0 电话→P1IM→P2 工作台) |
| **统一收拢** | 所有确认请求统一记录到工作台 |
| **批量提效** | P2/P3 场景支持批量操作 |
| **审计追溯** | 完整记录 AI 建议和人工决策 |
| **用户可控** | 支持自定义通知偏好、免打扰、自动通过规则 |

## 2. 分层确认体系

### 2.1 确认类型定义

| 类型 | 紧急度 | 场景示例 | 响应 SLA | 推送渠道 |
|------|--------|---------|---------|---------|
| **P0 紧急** | 极高 | 故障自愈、生产回滚、安全阻断 | 5 分钟 | 电话 + 短信 + IM@ + 工作台 |
| **P1 重要** | 高 | 部署审批、DB 变更、高风险变更 | 30 分钟 | IM@ + 工作台 |
| **P2 常规** | 中 | 代码审查、文档审核、权限申请 | 2 小时 | 工作台 + IM 提醒 (1 次) |
| **P3 批量** | 低 | 低风险变更、合规检查、例行审批 | 24 小时 | 工作台批量 + IM 摘要 |

## 7. 异常处理

### 7.1 超时升级流程

```
P0 紧急确认超时流程：
─────────────────────────────────────────────────────────────────────────────
T+0      AI 生成确认请求 → 推送电话 + 短信+IM
  ↓
T+5min   用户未响应 → 自动升级上级 → 第二次电话
  ↓
T+10min  上级未响应 → 继续升级 → 电话通知 CTO
  ↓
T+15min  CTO 未响应 → 记录事故 → 自动执行 (置信度>90%) 或 等待人工

P1 重要确认超时流程：
─────────────────────────────────────────────────────────────────────────────
T+0      AI 生成确认请求 → 推送 IM+ 工作台
  ↓
T+30min  用户未响应 → 自动升级上级 → IM 通知
  ↓
T+60min  上级未响应 → 继续升级 → 电话通知
  ↓
T+2h     仍未响应 → 记录 + 告警

P2 常规确认超时流程：
─────────────────────────────────────────────────────────────────────────────
T+0      AI 生成确认请求 → 推送工作台
  ↓
T+2h     用户未响应 → IM 提醒 (1 次)
  ↓
T+24h    仍未响应 → 记录 + 告警

P3 批量确认超时流程：
─────────────────────────────────────────────────────────────────────────────
T+0      AI 生成确认请求 → 加入批量队列
  ↓
T+4h     批量通知 (IM 摘要)
  ↓
T+24h    未处理 + 置信度>95% → 自动通过 + 记录审计
```

### 7.2 确认失败处理

| 失败场景 | 处理方式 |
|---------|---------|
| 电话无人接听 | 重拨 1 次 → 短信 +IM |
| IM 推送失败 | 切换备用渠道 (钉钉→企微→飞书) |
| 工作台无法访问 | 短信通知 + 备用链接 |
| 用户拒绝确认 | 记录原因 → 升级人工处理 |
| AI 执行失败 | 自动回滚 → 告警 → 升级人工 |
