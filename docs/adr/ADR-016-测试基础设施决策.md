## 1. 背景

### 1.1 一手实测基线（NEW-EA-16）

| 维度 | 实测值 | 证据 |
|------|--------|------|
| 9 个 DDD 包平均覆盖率 | 38.16% | `go test -cover` 一手执行 |
| eventstore postgresql 覆盖率 | 0% | 397 行生产代码，测试使用 mockEventStore |
| Saga 42 方法 | 23 个 0% | `TestSaga_ChaosRollback` grep 0 匹配 |
| security/secret/service 测试 | 21 行仅断言 `!= nil` | 快照断言反模式 |
| 16 个零测试模块 | 零覆盖 | NEW-EA-16 §4 |
| 企业级综合得分 | 29.2/100 | 架构 34 + 测试 16 + 治理 46 |

### 1.2 问题陈述

当前测试基础设施存在三大根本性缺失：

1. **无统一测试工具包**：每个模块自行编写 fixture/builder/assertion，重复代码严重
2. **无容器化集成测试基座**：Repository 测试使用 mock，无法验证真实 SQL 行为
3. **无契约测试生成器**：Handler 测试无法保证 API 契约稳定性

### 1.3 假绿灯反模式（NEW-EA-19 v2 发现）

| 反模式 | 证据 | 影响 |
|--------|------|------|
| **False Green Light** | eventstore 测试 mockEventStore | 397 行生产代码 0% 覆盖，测试全绿 |
| **Snapshot Assertion** | security/secret 测试 `!= nil` | 字段值错误无法被测试捕获 |
| **Zero Assertion** | 16 个零测试模块 | 无测试 = 无保护 |

## 2. 决策选项对比

### 2.1 方案 A：自建测试基础设施（推荐）

**改造成本**：
- `internal/testutil/` 统一工具包（Builder + Fixture + Assertion）
- Testcontainers-go PostgreSQL 集成测试基座
- OpenAPI 契约测试生成器（Gin routes → schema）
- 4 类测试骨架模板（Service / Repository / Handler / DomainEvent）

**优点**：
- ✅ 与 Orion 代码风格一致（Go + Gin）
- ✅ 可针对 Orion 多租户/DomainEvent 特化
- ✅ 无外部依赖（除 Testcontainers-go）
- ✅ 可演进（AST 检测器扩展 W8-W10）

**缺点**：
- ❌ 初始开发成本高（TEST-1~8 P0 任务）
- ❌ 需团队学习 Testcontainers-go

### 2.2 方案 B：使用第三方测试框架（ testify + gomock ）

**改造成本**：引入 testify/gomock 现成库

**优点**：
- ✅ 快速上手

**缺点**：
- ❌ **无法解决假绿灯**（gomock 仍鼓励 mock）
- ❌ 无契约测试能力
- ❌ 无容器化集成测试
- ❌ 与 Orion DDD 模式不匹配

### 2.3 方案 C：保持现状

**缺点**：
- ❌ 企业级得分 29.2/100（不达标）
- ❌ 假绿灯持续累积
- ❌ 无门控保护（46 门控无法扩展到 60）

## 3. 决策

### 3.1 选定方案

**方案 A：自建测试基础设施**

### 3.2 决策依据

| 判据 | 依据 | 满足度 |
|-----|------|-------|
| D1 解决假绿灯 | NEW-EA-19 v2 W1-W3 证据 | ✅ Testcontainers 替代 mockEventStore |
| D2 企业级达标 | NEW-EA-18 综合得分 | ✅ 预测 53.4 → 72（Phase 5）|
| D3 契约稳定性 | Google SRE Ch.14 | ✅ OpenAPI schema 保证 API 契约 |
| D4 可演进 | AST 检测器扩展（W8-W10）| ✅ design-constraint 扩展 |
| D5 多租户特化 | ADR-011 | ✅ Testcontainers 支持 tenant_id 隔离测试 |

### 3.3 核心组件

```
internal/testutil/
├── builder/          # Builder API（Aggregate/Event/Command）
├── fixture/          # 多租户 Fixture（tenant_id 注入）
├── assertion/        # 字段断言（替代 != nil）
├── container/        # Testcontainers-go PostgreSQL
├── contract/         # OpenAPI schema 生成器
└── templates/        # 4 类测试骨架模板
    ├── service_test.tmpl
    ├── repository_test.tmpl
    ├── handler_test.tmpl
    └── domainevent_test.tmpl
```

## 6. 认知边界（诚实声明）

1. **本 ADR 为草案**（状态 Proposed），需架构团队评审确认
2. **预测值 53.4 为 v2 校准**：v1 预测 70 为过度乐观，诚实下调
3. **Testcontainers-go 在 macOS CI 可能慢**：需评估 CI 时长影响
4. **AST 检测器扩展（W8-W10）依赖 design-constraint 技能**：需技能协同
5. **未估算人天/工期**：遵守 CLAUDE.md 强制约束
6. **RC-03 硬约束**：本 ADR 不修改生产代码，仅定义测试基础设施决策
7. **OpenAPI 契约测试覆盖率 80% 为目标**：并非所有 Gin routes 都适合契约测试（如 SSE/WebSocket）
