# ADR-009: 依赖追踪与自动升级设计

**状态**: 已批准  
**日期**: 2026-04-10  
**作者**: Orion Platform Team

---

## 1. 背景与问题

### 1.1 现状分析

产品评审发现以下问题：

| 问题 | 影响 | 优先级 |
|------|------|--------|
| 依赖追踪实现方案缺失 | 无法感知项目依赖状态 | P0 |
| SBOM 生成流程未定义 | 合规性审计困难 | P0 |
| 漏洞修复 PR 流程缺失 | 安全响应延迟 | P1 |
| 与 GitHub Dependabot 存在差距 | 用户体验不一致 | P2 |

### 1.2 目标

构建统一的依赖追踪系统，实现：
- 自动扫描项目依赖
- 生成标准 SBOM
- 漏洞检测与告警
- 自动创建修复 PR

### 2.2 组件说明

| 组件 | 职责 | 技术选型 |
|------|------|----------|
| Scanner Controller | 调度扫描任务 | Kubernetes CronJob |
| Git Watcher | 监听仓库变更 | Watchme/ArgoCD |

| Reporter Service | 漏洞匹配与报告 | Custom + OSV API |
| AutoPR Worker | 创建修复 PR | GitHub/GitLab API |

## 3. CRD 定义

### 3.1 DependencyTracking CRD

```yaml
apiVersion: orion.io/v1
kind: DependencyTracking
metadata:
  name: project-dependency-tracking
  namespace: default
spec:
  # 扫描配置
  scanSchedule: "0 2 * * *"  # 每日凌晨 2 点
  packageManagers:
    - npm
    - maven
    - pip
    - go
    - cargo
    - gradle
  
  # 漏洞数据源
  vulnerabilitySources:
    - nvd      # National Vulnerability Database
    - github   # GitHub Advisory Database
    - snyk     # Snyk Vulnerability DB
    - osv      # OSV.dev (Google)
  
  # 自动 PR 配置
  autoPR:
    enabled: true
    maxOpen: 5
    maxUpdatesPerRun: 10
    labels:
      - security
      - dependencies
      - bot
    assignees:
      - security-team
    reviewers:
      - tech-lead
    commitMessageTemplate: "chore(deps): upgrade {{package}} to {{version}}"
    prTitleTemplate: "🔒 Security: Upgrade {{package}} to fix {{cve}}"
    
  # 通知配置
  notifications:
    slack:
      enabled: true
      channel: "#security-alerts"
    email:
      enabled: true
      recipients:
        - security@example.com
    
  # 排除配置
  exclude:
    packages:
      - internal-*
    paths:
      - "**/test/**"
      - "**/vendor/**"
    
  # 目标仓库
  repositories:
    - name: frontend-app
      url: https://github.com/org/frontend-app
      branch: main
    - name: backend-service
      url: https://github.com/org/backend-service
      branch: main
```

### 4.3 JSON Schema 定义

```typescript
interface SBOM {
  bomFormat: "CycloneDX" | "SPDX";
  specVersion: string;
  metadata: {
    timestamp: string;
    tools: Tool[];
    component: Component;
  };
  components: Component[];
  vulnerabilities?: Vulnerability[];
}

interface Component {
  type: string;
  name: string;
  version: string;
  purl: string;  // Package URL
  licenses: License[];
  externalReferences?: ExternalReference[];
}

interface Vulnerability {
  id: string;  // CVE ID
  severity: "CRITICAL" | "HIGH" | "MEDIUM" | "LOW";
  cvss: number;
  description: string;
  affects: string[];  // Component refs
  fixedIn?: string;
}
```

## 5. 漏洞扫描策略

### 5.1 扫描触发机制

| 策略 | 触发条件 | 执行频率 | 覆盖范围 |
|------|----------|----------|----------|
| 定期扫描 | Cron 调度 | 每日 02:00 | 所有注册仓库 |
| 提交触发 | PR/Push 事件 | 实时 | 变更文件 |
| 漏洞库更新 | NVD/GitHub 更新 | 实时 | 受影响依赖 |
| 手动触发 | API/CLI 调用 | 按需 | 指定仓库 |

### 5.2 扫描流程图

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Trigger   │────▶│   Scanner   │────▶│   Parser    │
└─────────────┘     └─────────────┘     └─────────────┘
                                              │
                                              ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Report    │◀────│   Match     │◀────│   SBOM      │
└─────────────┘     └─────────────┘     └─────────────┘
       │
       ▼
┌─────────────┐
│   AutoPR    │ (if enabled)
└─────────────┘
```

### 5.3 漏洞 severity 响应 SLA

| Severity | CVSS 范围 | 响应时间 | 修复时限 |
|----------|-----------|----------|----------|
| CRITICAL | 9.0-10.0 | 4 小时 | 24 小时 |
| HIGH | 7.0-8.9 | 24 小时 | 7 天 |
| MEDIUM | 4.0-6.9 | 7 天 | 30 天 |
| LOW | 0.0-3.9 | 30 天 | 90 天 |

## 6. 自动修复 PR 流程

### 6.1 工作流程

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         AutoPR Workflow                                  │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  1. Detect         2. Analyze        3. Create         4. Verify        │
│  ┌────────┐       ┌────────┐       ┌────────┐       ┌────────┐         │
│  │ Vulner │──────▶│ Latest │──────▶│  Git   │──────▶│  CI/   │         │
│  │   able │       │  Ver   │       │  PR    │       │  CD    │         │
│  └────────┘       └────────┘       └────────┘       └────────┘         │
│                                                      │                  │
│                                                      ▼                  │
│  6. Merge        5. Notify                          ┌────────┐         │
│  ┌────────┐       ┌────────┐                        │  Pass? │         │
│  │  Auto  │◀──────│ Slack  │◀───────────────────────│ Yes    │         │
│  │  /Close│       │  /EM   │                        └────────┘         │
│  └────────┘       └────────┘                          │ No             │
│                                                       ▼                 │
│                                                ┌─────────────┐          │
│                                                │  Comment &  │          │
│                                                │  Assign     │          │
│                                                └─────────────┘          │
│                                                                          │
└─────────────────────────────────────────────────────────────────────────┘
```

### 6.2 详细步骤

| 步骤 | 动作 | 负责组件 |
|------|------|----------|
| 1 | 检测漏洞依赖 | Reporter Service |
| 2 | 查询最新安全版本 | Analyzer Engine |
| 3 | 创建分支 & 修改依赖文件 | AutoPR Worker |
| 4 | 提交 PR & 触发 CI | AutoPR Worker |
| 5 | CI 通过后通知 Reviewer | Reporter Service |
| 6 | Review 通过自动合并 | AutoPR Worker |

## 7. 与 Dependabot 对比

| 功能 | Dependabot | Orion Dependency Tracker |
|------|------------|-------------------------|
| 支持包管理器 | ✅ 全面 | ✅ npm/maven/pip/go/cargo |
| SBOM 生成 | ❌ | ✅ CycloneDX/SPDX |
| 自定义扫描调度 | ❌ | ✅ Cron 表达式 |
| 多漏洞源 | ⚠️ GitHub 为主 | ✅ NVD/GitHub/Snyk/OSV |
| 自托管 | ❌ SaaS only | ✅ Kubernetes Native |
| 企业合规 | ⚠️ 有限 | ✅ 完整审计日志 |
| 成本 | 按仓库计费 | 开源免费 |

## 9. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 误报漏洞 | 信任度下降 | 多源交叉验证 |
| PR 过多 | Review 负担 | 限制并发数 |
| CI 失败 | 阻塞流程 | 失败时转人工 |
| 敏感信息泄露 | 安全风险 | 私有部署 + RBAC |
