> 版本：v1.0 | 创建日期：2026-04-11 | 状态：草案

## 1. 概述

### 1.1 设计目标

构建可配置、可扩展的代码规范规则引擎，支持团队自定义代码审查规则，使 AI 代码审查更符合团队风格。

**对应需求**: US-2.5 — 作为开发者，我想要 AI 学习团队规范，以便审查更符合团队风格

### 1.2 核心能力

| 能力 | 说明 | 优先级 |
|------|------|--------|
| 规则 DSL | 领域特定语言定义审查规则 | P0 |
| 热更新 | 规则变更无需重启服务 | P0 |
| 优先级管理 | 规则冲突时按优先级执行 | P0 |
| 团队隔离 | 不同团队可配置独立规则 | P0 |
| 效果评估 | 规则准确率/误报率统计 | P1 |
| 规则市场 | 团队间共享优质规则 | P2 |

### 1.3 与 AI 审查集成

## 3. 规则定义 DSL

### 3.1 DSL 语法

```yaml
# 规则定义示例
rule:
  id: "team-java-001"
  name: "禁止使用 System.out.println"
  description: "生产代码禁止使用 System.out.println 打印日志"
  
  # 适用语言
  language: java
  
  # 规则类型
  type: pattern  # pattern | ast | semantic
  
  # 匹配模式
  pattern:
    regex: "System\\.out\\.println\\s*\\("
    message: "请使用 Logger 代替 System.out.println"
    severity: error
    suggestion: "private static final Logger log = LoggerFactory.getLogger(Xxx.class);"
  
  # 排除路径
  exclude:
    - "**/test/**"
    - "**/*.test.java"
  
  # 元数据
  metadata:
    category: logging
    owasp: null
    team: payment-team
    created_by: tech_lead_wang
    tags: [logging, best-practice]
```

### 3.2 规则类型

| 类型 | 说明 | 示例 | 复杂度 |
|------|------|------|--------|
| **pattern** | 正则匹配 | 禁止使用 println | 低 |
| **ast** | AST 节点匹配 | 方法复杂度>10 | 中 |
| **semantic** | 语义分析 | 未使用的变量 | 高 |

### 3.3 完整 DSL 规范

```yaml
# 规则 DSL 完整 schema
RuleSchema:
  required:
    - id          # 规则唯一标识 (team-language-xxx)
    - name        # 规则名称
    - language    # 适用语言 (java/go/python/ts/js)
    - type        # 规则类型 (pattern/ast/semantic)
    - pattern     # 匹配规则定义
  
  optional:
    - description # 规则描述
    - severity    # 严重程度 (info/warning/error/critical)
    - exclude     # 排除路径列表
    - include     # 包含路径列表 (默认**)
    - fix         # 自动修复配置
    - metadata    # 元数据

PatternDefinition:
  pattern:
    regex: string       # 正则表达式 (pattern 类型)
    ast_query: string   # AST 查询语句 (ast 类型)
    message: string     # 违规提示消息
    suggestion: string  # 修复建议
    code_fix: string    # 自动修复代码 (可选)
```

## 5. 规则优先级与冲突解决

### 5.1 优先级定义

| 优先级 | 数值 | 说明 | 示例 |
|--------|------|------|------|
| **平台级** | 100 | 全平台通用规则 | 安全漏洞、严重语法错误 |
| **组织级** | 200 | 组织内通用规则 | 编码规范、日志规范 |
| **团队级** | 300 | 团队特定规则 | 业务相关规范 |

**数值越小优先级越高**，高优先级规则结果覆盖低优先级。

### 5.2 冲突解决策略

```yaml
conflict_resolution:
  # 同一问题被多条规则匹配
  strategy: "highest_priority"  # 高优先级优先
  
  # 消息合并
  message_merge: true  # 合并多条规则的提示消息
  
  # 建议合并
  suggestion_merge: true  # 合并多条规则的修复建议
  
  # 去重
  deduplicate: true  # 相同问题只报告一次
```

### 5.3 冲突示例

```
代码:
  System.out.println("debug: " + value);

匹配规则:
  1. 平台规则 platform-001: 禁止输出敏感信息 (优先级 100)
  2. 组织规则 org-logging-002: 使用 Logger 代替 println (优先级 200)
  3. 团队规则 team-java-001: 禁止使用 println (优先级 300)

最终输出:
  ┌─────────────────────────────────────────────────────────────────┐
  │ ❌ 禁止输出敏感信息 (platform-001)                               │
  │    位置：UserService.java:45                                    │
  │    原因：可能泄露用户数据                                       │
  │    建议：使用脱敏日志或移除调试信息                             │
  │                                                                 │
  │ ℹ️ 其他匹配规则：                                                │
  │    - org-logging-002: 使用 Logger 代替 println                   │
  │    - team-java-001: 禁止使用 println                            │
  └─────────────────────────────────────────────────────────────────┘
```

### 6.2 结果合并算法

```go
type ReviewResult struct {
    RuleID     string
    Severity   string
    Message    string
    Line       int
    Suggestion string
    Source     string // "rule" or "ai"
}

func MergeResults(ruleResults, aiResults []ReviewResult) []ReviewResult {
    // 1. 去重：相同位置+相同类型的问题只保留一个
    deduped := deduplicate(ruleResults, aiResults)
    
    // 2. 规则问题优先 (确定性 > 概率性)
    sort.Slice(deduped, func(i, j int) bool {
        if deduped[i].Source == "rule" && deduped[j].Source == "ai" {
            return true
        }
        return severityOrder(deduped[i].Severity) < severityOrder(deduped[j].Severity)
    })
    
    // 3. 分类整理
    grouped := groupByCategory(deduped)
    
    return grouped
}
```

## 7. 规则效果评估

### 7.1 评估指标

| 指标 | 计算公式 | 目标值 |
|------|---------|--------|
| **准确率** | 正确问题数 / 总报告数 | >85% |
| **误报率** | 误报数 / 总报告数 | <15% |
| **漏报率** | 漏报数 / 实际问题数 | <10% |
| **规则覆盖率** | 已覆盖场景 / 应覆盖场景 | >80% |
| **规则采用率** | 启用规则数 / 总规则数 | >60% |

### 7.2 反馈收集

```
┌─────────────────────────────────────────────────────────────────────────┐
│  规则反馈收集机制                                                       │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  开发者操作 → 反馈类型 → 规则优化                                        │
│                                                                         │
│  ┌─────────────┐                                                       │
│  │ "这不是问题" │ → 误报反馈 → 调整规则条件/降低优先级                   │
```

### 7.3 规则迭代

```yaml
规则迭代流程:
  1. 收集反馈 (每周自动汇总)
  2. 分析误报 (Top 10 误报规则)
  3. 优化规则 (调整条件/排除路径)
  4. A/B 测试 (小流量验证优化效果)
  5. 全量发布 (更新规则版本)
```

## 9. 数据库设计

### 9.1 规则表

```sql
CREATE TABLE rules (
    id VARCHAR(64) PRIMARY KEY,
    name VARCHAR(256) NOT NULL,
    description TEXT,
    language VARCHAR(32) NOT NULL,
    type VARCHAR(32) NOT NULL,  -- pattern/ast/semantic
    
    -- 规则定义
    pattern_json JSONB NOT NULL,
    exclude_paths TEXT[],
    include_paths TEXT[] DEFAULT ARRAY['**'],
    
    -- 优先级
    priority_level VARCHAR(32) DEFAULT 'team',  -- platform/org/team
    priority_value INT DEFAULT 300,
    
    -- 状态
    enabled BOOLEAN DEFAULT true,
    version INT DEFAULT 1,
    
    -- 元数据
    category VARCHAR(64),
    team_id VARCHAR(64),
    org_id VARCHAR(64),
    created_by VARCHAR(64),
    updated_by VARCHAR(64),
    
    -- 时间戳
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_rules_team ON rules(team_id, language, enabled);
CREATE INDEX idx_rules_org ON rules(org_id, language, enabled);
CREATE INDEX idx_rules_category ON rules(category);
```

### 9.2 规则反馈表

```sql
CREATE TABLE rule_feedback (
    id BIGSERIAL PRIMARY KEY,
    rule_id VARCHAR(64) REFERENCES rules(id),
    user_id VARCHAR(64),
    pr_id VARCHAR(64),
    
    -- 反馈类型
    feedback_type VARCHAR(32),  -- false_positive/true_positive/ignored
    
    -- 反馈内容
    comment TEXT,
    
    -- 时间戳
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_feedback_rule ON rule_feedback(rule_id, created_at);
```
