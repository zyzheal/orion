# Orion 平台修复执行计划 (v2, 2026-08-02)

> **基于**: `全模块深度分析报告-2026-08-02.md` (v3)
> **实测数据**: 282 模块 / 510,923 行 / 259 有路由 / 171 已 wiring / **89 未 wiring**

> **状态**: 全新计划，替换旧版 Phase1-3

## 一、问题全景

```
平台代码 510,923 行 (282 模块)
├── 309,435 行 (60.6%) — 真正可用 (178 模块, wiring + routes 齐全)
├── 106,982 行 (21.0%) — 有路由但未 wiring (89 模块, 可修复)
│   ├── 49 模块 — 有真实路由 (265 个端点, 修复后直接可用)
│   └── 40 模块 — 基础设施/中间件 (27,904 行, 非路由模块)
└── 94,506 行 (18.4%)  — 基础设施/工具层 (25 模块, 无需修复)
```

**关键事实**: 这不是"代码没写"，而是**写了但没接线**。修复成本极低（3 个文件改动/模块），收益极高。

|------|:------:|:------:|:------:|------|
| **A 类: 可接线业务模块** | 49 | ~116,000 | **265** | 有 RegisterRoutes + handler，缺 wiring |
| B 类: 基础设施/中间件 | 25 | ~27,000 | 0 | 非路由模块（如 auto-exec/domain/roweditor） |
| C 类: 子模块/重复 | 15 | ~8,000 | 0 | 父模块子目录或重复实现 |

## 二、修复策略

### 优先级框架

```
P0: 接线 49 个有路由的业务模块 (影响 10+ 域, +116K 行可用)
P1: 清理 196 个方法孤儿 (mlops/metadata/inspection/test-gen)
P1: 为 56 个零测试模块补充测试 (覆盖率 5.2→7.0)
P2: 清理 5 对重复模块
P2: 注册基础设施模块 wiring (domain/auto-exec/startup/roweditor)
P3: 功能增强 (ITSM 新功能/CMDB 漂移检测/ChatOps 引擎)
```

### 接线模式（已验证）

每个模块接线仅需 3 步，~10 行代码：

```go
// 1. wiring.go 顶部 import (加入模块 handler/repo/service import)
x_handler "orion/platform-svc-go/internal/xxx/handler"
x_repo    "orion/platform-svc-go/internal/xxx/repository"
x_service "orion/platform-svc-go/internal/xxx/service"

// 2. wiring.go var 声明区
xH *x_handler.Handler

// 3. wiring.go initWiring() 函数
xRepo := x_repo.NewRepository(infra.db.DB)
xSvc := x_service.NewService(xRepo)
xH = x_handler.NewHandler(xSvc)

// 4. router.go RegisterRoutes (如已有则跳过)
if xH != nil { xH.RegisterRoutes(api) }
```
