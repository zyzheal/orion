**对标**: Grafana Alerting + PagerDuty

#### 2.1.1 现状

```
alert (8文件/✅ wired)              — 告警 CRUD/状态/规则
alert-adapter (11文件/❌ wired)     — 114S SPI 适配器 (Prometheus/Zabbix/Grafana/Kafka/Webhook/Slack/Email/WeChat/DingTalk/PagerDuty)

alert-breaker (9文件/✅ wired)      — 熔断 (6H/6S/6R)
alert-correlation (6文件/❌ wired)  — 告警关联 (2H/1S/2R)
alert-deduplication (3文件/❌ wired)— 告警去重 (1H/1S/0R)
alert-pipeline (16文件/❌ wired)    — 6 阶段管道 (0H/0S/0R)
alert-silence (5文件/❌ wired)      — 静默规则 (1H/1S/2R)
```

#### 2.1.2 完善路径

**Step 1 — 接线 13 个未 wiring 模块（P0, 0.5 天）**

| 模块 | 接线方式 | 暴露能力 |
|------|---------|---------|
| alert-adapter | wiring.go 注入 AlertAdapterFactory | 10 种数据源适配器 |
| alert-correlation | wiring.go 注入 | 告警关联分析 |
| alert-deduplication | wiring.go 注入 + 补 Repo | 去重 (Fingerprint 算法) |
| alert-silence | wiring.go 注入 | 静默规则 |
| alert-pipeline | 补 handler + service + wiring | 6 阶段管道 (validate→dedup→correlate→silence→route→notify) |

**Step 2 — 补全告警管道 6 阶段链路（P1, 2 天）**

```
当前 alert-pipeline 已有 16 文件实现 6 阶段 Stage:
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ Receive  │→ │ Validate │→ │ Dedup    │→ │ Correlate │→ │ Route    │→ │ Notify   │
│ Stage    │   │ Stage    │   │ Stage    │   │ Stage    │   │ Stage    │   │ Track    │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

- 补 `handler.go`：`POST /api/alerts/pipeline/execute` 统一入口
- 补 `service.go`：`Execute(ctx, alert) error` 串联 6 Stage
- 补 `router.go`：注册管道端点

**Step 3 — 告警拓扑可视化（P2, 3 天）**

- 新增 `internal/alert-topology/` — 告警依赖关系图
- 前端 `AlertTopologyPage.tsx` — 展示告警→服务→CMDB 级联关系
- 对标 Grafana Alerting 的 Alert Graph

**Step 4 — 告警规则编辑器增强（P2, 2 天）**

- 当前 `alert/service/service.go` 支持阈值/时间窗口/组合条件
- 增加：表达式引擎 (PromQL-like) + 可视化条件编辑器
- 前端增加 `AlertRuleEditor.tsx`
