### 3.1 E2E-01: 标准 PR 流程 (无数据库变更)

#### 场景概述

| 属性 | 值 |
|------|-----|
| **场景名称** | 标准 PR 流程 (无数据库变更) |
| **场景 ID** | E2E-01 |
| **优先级** | P0 |
| **MVP** | ✅ 是 |
| **主要用户** | 初级开发、高级开发 |
| **使用频率** | 每日 5-10 次/团队 |
| **预计耗时** | 8-15 分钟 (从提交到部署) |

#### 参与者

| 角色 | 职责 | 系统/工具 |
|------|------|----------|
| 开发者 | 提交代码、修复问题 | IDE、GitLab |
| AI 审查引擎 | 自动审查代码 | Orion AI Service |
| Tech Lead | 审批合并、部署 | Orion 审批台、钉钉 |
| 流水线引擎 | 执行构建测试部署 | Tekton + Orion |
| 通知中心 | 发送状态通知 | 钉钉/企微 |

#### 前置条件

- [ ] 开发者已完成本地开发并自测通过
- [ ] 开发者已创建特性分支
- [ ] GitLab 仓库已配置 Orion 集成

#### 主流程 (Happy Path)

```
┌─────────────────────────────────────────────────────────────────────────┐
│  E2E-01 主流程：标准 PR 流程                                            │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  步骤 1: 创建 PR                                                        │
│  ──────────────────                                                     │

│  1.3  GitLab Webhook 触发 Orion 流水线                                    │
│       └─ 期望：5 秒内响应                                                 │
│                                                                         │
│  步骤 2: AI 代码审查                                                      │
│  ───────────────────                                                    │
│  2.1  Orion 自动触发 AI 代码审查 Task                                     │
│  2.2  AI 分析代码变更 (安全/性能/规范)                                    │
│  2.3  AI 在 PR 中发表评论 (问题 + 修复建议)                                │
│       └─ 期望：30 秒内完成，准确率>80%                                   │
│       └─ 期望：无 Critical 问题自动标记为"AI 审查通过"                     │
│                                                                         │
│  步骤 3: 流水线执行                                                      │
│  ────────────────────                                                   │

│  3.2  Stage 2 - Build: 编译打包                                          │
│       └─ 期望：3 分钟内完成，产物推送到 Harbor                            │

│       └─ 期望：5 分钟内完成，覆盖率>80%                                  │
│       └─ 期望：AI 只选择相关测试，节省 50% 时间                            │
│  3.4  Stage 4 - Deploy (Dev): 自动部署到 Dev 环境                          │
│       └─ 期望：2 分钟内完成，健康检查通过                                │
│                                                                         │
│  步骤 4: Tech Lead 审批                                                  │
│  ──────────────────────                                                 │
│  4.1  Orion 发送审批通知到钉钉 (含 AI 审查报告 + 流水线结果)               │
│  4.2  Tech Lead 查看审批详情 (风险评分 + 影响面)                          │

│       └─ 期望：审批响应<1 秒                                              │
│                                                                         │
│  步骤 5: 部署到 Staging                                                 │
│  ──────────────────────────                                             │
│  5.1  审批通过后自动部署到 Staging                                       │
│  5.2  自动执行集成测试 + 冒烟测试                                         │
│  5.3  通知开发者验证                                                     │
│                                                                         │
│  步骤 6: 部署到 Production (可选)                                        │
│  ──────────────────────────────────                                     │
│  6.1  Tech Lead 二次审批生产部署                                         │
│  6.2  灰度发布 (10% → 50% → 100%)                                       │

│                                                                         │
```
