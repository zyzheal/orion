# 灰度发布配置指南

> 最后更新：2026-09-25

## 概述

Orion API Gateway 实现了基于 Redis Pub/Sub 的灰度发布路由系统，支持按路径、权重将请求动态路由到不同服务版本。

**核心能力**：
- 动态路由规则配置（无需重启网关）
- 按路径+权重分流（0-100）
- Redis Pub/Sub 实时推送
- 故障自动降级（Redis 不可用时回退到默认目标）
- 多目标路由（TS/Go 双版本兼容）

## 架构

```
                    ┌──────────────┐
                    │  灰度管理 API │
                    │  /gray/config │
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │  Redis 存储  │
                    │ gray:config  │
                    │ gray:pubsub  │
                    └──────┬───────┘
                           │ Pub/Sub
                    ┌──────▼───────┐
                    │  网关路由引擎 │
                    │  GrayRelease │
                    └──────┬───────┘
                           │
              ┌────────────┴────────────┐
              │                         │
       ┌──────▼──────┐         ┌──────▼──────┐
       │   Go 版本   │         │   TS 版本   │
       │  :3001 (Go) │         │  :3001 (TS) │
       └─────────────┘         └─────────────┘
```

## 配置

### 灰度配置结构

```json
{
  "version": 1,
  "defaultTarget": "go",
  "routeTargets": [
    {"path": "/api/v1/pipelines", "target": "go", "weight": 50},
    {"path": "/api/v1/agents", "target": "ts", "weight": 100}
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `version` | int | 是 | 配置版本号，每次修改递增 |
| `defaultTarget` | string | 是 | 默认目标：`go` 或 `ts` |
| `routeTargets` | array | 是 | 路由规则列表 |
| `routeTargets[].path` | string | 是 | 匹配路径前缀 |
| `routeTargets[].target` | string | 是 | 目标：`go` 或 `ts` |
| `routeTargets[].weight` | int | 是 | 权重 0-100 |

### 服务端口配置

```yaml
# config/config.yaml
gray_release:
  enabled: true
  redis_addr: "localhost:6379"
  default_target: "go"
  targets:
    go:
      url: "http://localhost:3001"
    ts:
      url: "http://localhost:4001"
```

## 使用方式

### 1. 配置灰度规则

```bash
redis-cli SET gray:config '{
  "version": 1,
  "defaultTarget": "go",
  "routeTargets": [
    {"path": "/api/v1/pipelines", "target": "go", "weight": 50}
  ]
}'
```

### 2. 路由逻辑

1. 请求进入网关
2. 查找匹配的路径规则（最长前缀匹配）
3. 根据权重决定目标版本
4. 转发请求到对应服务

### 3. 流量分配示例

```
请求 /api/v1/pipelines
  → 匹配规则: path=/api/v1/pipelines, target=go, weight=50
  → 50% 流量 → Go 服务 (:3001)
  → 50% 流量 → TS 服务 (:4001)
```

## 降级策略

| 场景 | 降级行为 |
|------|---------|
| Redis 不可用 | 使用默认目标（defaultTarget） |
| 配置解析失败 | 使用默认目标 + 记录错误日志 |
| 目标服务超时 | 熔断器自动断开，重试其他目标 |
| 无匹配规则 | 使用默认目标 |

## 监控

### Redis 指标

```bash
redis-cli GET gray:config
redis-cli SUBSCRIBE gray:pubsub
```

### 日志关键字

```
gray_release_config_loaded   - 灰度配置加载完成
gray_release_route_decision  - 路由决策
gray_release_redis_error     - Redis 连接错误
gray_release_fallback        - 降级到默认目标
```

## 与熔断器配合

灰度发布与熔断器（CircuitBreaker）配合使用：

```
请求 → 灰度路由 → 目标服务
                    │
              ┌─────┴─────┐
              │           │
           成功          失败
              │           │
         recordSuccess  recordFailure
              │           │
              │      熔断器打开
              │           │
              └───→ 后续请求走另一目标
```

## 最佳实践

1. **渐进式发布**：从 0% → 10% → 50% → 100% 逐步放量
2. **监控告警**：为灰度路径配置独立告警规则
3. **快速回滚**：将 weight 设为 0 即可立即回滚
4. **版本追踪**：每次配置变更递增 version 号
5. **测试验证**：在预发布环境验证后再在生产环境放量
