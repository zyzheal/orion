### 2.2 `domain/` — CQRS/Event Sourcing 架构 (90%)

**282 模块中架构最完整的模块**，实现了企业级架构模式：

```
domain/
├── aggregates/    — 聚合根 (FeatureFlag/Approval/Pipeline)
│   ├── aggregate_root.go  — AggregateRoot interface + BaseAggregate
│   ├── pipeline.go        — PipelineAggregate + 生命周期事件
│   ├── approval.go        — ApprovalAggregate + ApprovalLevel 多级审批
│   └── feature_flag.go    — FeatureFlagAggregate + 开关状态机
├── commands/      — 命令总线
│   ├── command_bus.go     — CommandBus interface + InMemoryCommandBus
│   └── command_bus_test.go
├── events/        — 领域事件
│   ├── domain_event.go    — DomainEvent interface + BaseDomainEvent
│   ├── pipeline_events.go — 10+ Pipeline 领域事件
│   └── publisher.go       — 事件发布器
├── eventstore/    — 事件存储
│   ├── eventstore.go      — EventStore interface
│   ├── postgresql.go      — PostgreSQL 事件存储实现
│   ├── snapshot_store.go  — 快照存储 (性能优化)
│   └── stored_event.go    — 持久化事件模型
└── readmodel/     — 读模型
    ├── read_model.go      — 读模型基类
    └── read_model_test.go
```

**关键能力**：
- **EventStore**: PostgreSQL 持久化 + 快照，支持事件回放
- **CommandBus**: InMemory 命令总线，支持异步处理
- **Aggregates**: 3 个聚合根 (Pipeline/Approval/FeatureFlag)，每个有完整状态机
- **10+ 领域事件**: PipelineCreated/Activated/Deactivated/Started/Completed/Cancelled...

## 四、⚠️ 重大新发现：方法孤儿 (Dead Code)

**前一份报告 (§3.2) 声称 mlops/inspection/metadata/test-generation 为"模板复制"，精确量化后修正为更严重的问题：方法孤儿。**

### 4.1 孤儿方法统计

| 模块 | 总 Handler 方法 | 已注册路由 | 业务方法 | **孤儿方法** | 孤儿率 |
|------|:-------------:|:---------:|:--------:|:----------:|:------:|
| mlops | 62 | 16 | 60 | **44** | 73% |
| metadata | 62 | 8 | 60 | **52** | 87% |
| inspection | 62 | 12 | 60 | **48** | 80% |
| test-generation | 63 | 9 | 61 | **52** | 85% |
| **合计** | **249** | **45** | **241** | **196** | **81%** |

> 孤儿方法 = 已定义但**未注册到路由**，永远不会被 HTTP 请求调用。

### 4.2 孤儿方法内容验证

抽查 mlops 中的孤儿方法，**确实实现了完整业务逻辑**（含 OpenTelemetry 追踪）：

```go
func (h *Handler) Trigger(c *gin.Context) {
    ctx, span := otel.Tracer("orion-platform-svc").Start(c.Request.Context(), "Trigger")
    defer span.End()
    tenantID := c.GetString("tenant_id")
    // ... 完整业务逻辑，仅缺路由注册
}
```

**结论**: 这不是模板复制（每个模块路由不同），而是 **Wiring 注册不完整** — 实现了 196 个方法却只暴露了 45 条路由。

### 4.3 孤儿方法示例 (mlops 模块)

| 孤儿方法 | 应注册路由 | 影响 |
|---------|-----------|------|
| Trigger | POST /mlops/:id/trigger | 无法触发 ML Pipeline |
| Forecast | GET /mlops/:id/forecast | 无法获取预测 |
| AddTag/DeleteTag | POST/DELETE /mlops/:id/tags | 无法管理标签 |
| CheckCompatibility | POST /mlops/:id/compatibility | 无法检查兼容性 |
| GetCoverage | GET /mlops/:id/coverage | 无法获取覆盖率 |
| ... 39 more | | |
