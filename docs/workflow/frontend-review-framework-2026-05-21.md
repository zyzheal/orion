## 一、使用说明

当需要对前端模块进行交互审查时：

1. 读取目标页面所有 `.tsx` 文件和关联的 `.ts` API 文件
2. 逐层执行以下 5 个检查
3. 输出问题清单，每个问题标注 P0/P1/P2 优先级

---

## 二、检查 1：逐元素交互链

对页面上每个可操作元素，填写下表：

| 元素（代码位置） | 类型 | 可交互？ | 点击/操作后 | 有无 loading | 有无反馈 | 问题 |
|-----------------|------|---------|------------|-------------|---------|------|
| 例：第 167 行"执行"按钮 | Button | ✓ onClick | 调用 executeWorkflow | ✗ 无 | ✓ message.success | 缺少 loading 状态 |

**判定标准**：
- 可操作元素无 `onClick`/`onChange` → **缺失**
- 操作后无 `message.success/error` → **缺失**
- 异步操作无 `loading`/`disabled` → **可重复点击风险**

---

## 三、检查 2：逐字段读写状态

对每个表单/详情面板（Modal、Drawer、Form），列出所有字段：

| 字段名 | 组件类型 | 只读/可编辑 | 有无校验 | 保存方式 | 问题 |
|--------|---------|-----------|---------|---------|------|
| 例：节点名称 | `<Text>` | ✗ 只读 | — | — | 应可编辑，改为 `<Input>` |

**判定标准**：
- 本应可编辑的字段用 `<Text>`/`<Descriptions.Item>` → **缺失编辑能力**
- 可编辑字段无 `rules`/`validator` → **缺失校验**
- 表单底部无保存按钮 → **无法持久化**

---

## 四、检查 3：CRUD 完整性

对页面管理的数据实体，检查 CRUD 是否完整：

| 操作 | 有无入口 | 有无确认 | 有无反馈 | API 是否调用 | 问题 |
|------|---------|---------|---------|-------------|------|
| Create | ✓ 弹窗 | — | ✓ success | ✓ createWorkflow | — |
| Read | ✓ 列表 | — | — | ✓ getWorkflowList | — |
| Update | ✗ 无 | — | — | ✗ updateWorkflow 未 import | **完全缺失** |
| Delete | ✓ 按钮 | ✓ Modal.confirm | ✓ success | ✓ deleteWorkflow | — |

**判定标准**：
- 任一 CRUD 操作缺失 → **P0**
- 操作有入口但 API 未调用 → **P0**
- 操作有 API 但页面无入口 → **P0**

---

## 五、检查 4：场景逆向验证

选以下场景走一遍，记录卡在哪一步：

### 场景 A：完整 CRUD
```
创建 → 查看列表 → 查看详情 → 编辑 → 保存 → 删除
```

### 场景 B：修改核心字段
```
找到目标 → 打开编辑 → 修改值 → 点击保存 → 确认刷新
```

### 场景 C：操作失败
```
触发错误 → 查看错误提示 → 重试 → 确认恢复
```

**记录格式**：
```
场景 A：卡在"编辑"步骤 — 详情页无编辑按钮，字段全部只读
场景 B：卡在"点击保存"步骤 — 表单底部无保存按钮
场景 C：卡在"查看错误提示"步骤 — catch 块只 console.error 无 message
```

## 六、检查 5：反模式检测

| 反模式 | 检测方法 | 修复建议 |
|--------|---------|---------|
| 全部 Descriptions 只读 | 搜索 `<Descriptions` 确认有无 `<Form.Item>` | 添加编辑模式 |
| 操作后无 message | 搜索 `message.success` / `message.error` 覆盖度 | 补全提示 |
| 按钮无 loading | 搜索 `onClick` 对应的 async 函数有无 loading 状态 | 添加 loading |
| Empty 无引导 | 搜索 `<Empty` 确认有无操作按钮 | 加引导按钮 |
| 表单无提交按钮 | 搜索 `<Form` 确认底部有无提交按钮 | 加固定保存按钮 |

## 八、工具能力支撑

### 8.1 已有检测器

| 检测器 | 功能 | 状态 |
|--------|------|------|
| ast-analyzer.ts | 交互完整性分析 | ✅ 已实现 |
| code-quality-analyzer.ts | 代码质量检测 | ✅ 已实现 |
| checker.ts | 检查执行引擎 | ✅ 已实现 |
| detector.ts | 自动识别代码类型 | ✅ 已实现 |
| reporter.ts | 报告生成 | ✅ 已实现 |

### 8.2 检测能力覆盖

| 检测项 | 状态 | 精度 | 说明 |
|--------|------|------|------|
| 缺少 loading 状态 | ✅ 已实现 | 中 | 检测异步函数缺少 loading |
| 缺少操作反馈 | ✅ 已实现 | 中 | 检测 message.success/error |
| 缺少提交按钮 | ✅ 已实现 | 高 | 支持多种模式 |
| 缺少编辑入口 | ✅ 已实现 | 高 | 排除只读页面 |
| 缺少 Empty 引导 | ⚠️ 待增强 | 低 | 仅基础检测 |

### 8.3 工具调用链路

```
用户输入
    ↓
Skill 入口 (design-constraint:check)
    ↓
自动识别 (detector.ts)
    ↓
选择检测器
  ├── ast-analyzer.ts (交互)
  └── code-quality-analyzer.ts (质量)
    ↓
执行检测 + 生成报告
    ↓
输出结果
```
