## 一、IaC AI 审查架构

### 1.1 审查范围

```
┌─────────────────────────────────────────────────────────────────┐
│              IaC AI 审查范围                                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  支持的 IaC 类型：                                               │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ • Terraform (.tf/.tf.json)                               │   │
│  │ • Kubernetes Manifest (.yaml/.json)                      │   │
│  │ • Helm Chart (templates/)                                │   │
│  │ • CloudFormation (.yaml/.json)                           │   │
│  │ • Pulumi (TypeScript/Python/Go)                          │   │
│  │ • Ansible Playbook (.yaml)                               │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  审查维度：                                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 1. 安全性审查                                            │   │
│  │    • 敏感信息泄露 (密码/密钥/Token)                        │   │
│  │    • 网络安全组配置 (开放端口/入站规则)                    │   │
│  │    • 加密配置 (存储加密/传输加密)                          │   │
│  │    • 访问控制 (IAM 权限/角色)                              │   │
│  │                                                         │   │
│  │ 2. 成本优化审查                                          │   │
│  │    • 资源规格是否过大                                     │   │
│  │    • 是否有闲置资源                                       │   │
│  │    • 是否使用 Spot 实例                                   │   │
│  │    • 存储生命周期配置                                     │   │
│  │                                                         │   │
│  │ 3. 最佳实践审查                                          │   │
│  │    • 资源命名规范                                         │   │
│  │    • 标签完整性 (team/project/env)                        │   │
│  │    • 版本锁定 (Provider 版本)                             │   │
│  │    • 状态文件配置 (远程后端/加密)                          │   │
│  │                                                         │   │
│  │ 4. 合规性审查                                            │   │
│  │    • 等保三级合规                                         │   │
│  │    • GDPR 合规                                             │   │
│  │    • 公司内部规范                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 审查流程总览

```
┌─────────────────────────────────────────────────────────────────┐
│              IaC AI 审查流程总览                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  代码提交 → Terraform Plan → AI 审查 → 审批 → 执行               │
│                                                                 │
│  ┌──────────┐                                                   │
│  │ 1. 代码提交 │ 开发者提交 Terraform 变更                        │
│  └────┬─────┘                                                   │
│       │                                                         │
│       ▼                                                         │
│  ┌──────────┐                                                   │
│  │ 2. Plan   │ 执行 terraform plan 生成变更计划                   │
│  │           │ 输出：JSON 格式的变更详情                          │

│       │                                                         │

│       ▼                                                         │

│                                                                 │
```

## 三、审查规则库

### 3.1 安全性审查规则

| 规则 ID | 规则名称 | 严重度 | 检查内容 | 修复建议 |
|--------|---------|--------|---------|---------|
| SEC-001 | 敏感信息检测 | CRITICAL | 检测明文密码/密钥/Token | 使用变量引用或 Secret 管理 |
| SEC-002 | 安全组开放 | HIGH | 检测 0.0.0.0/0 入站规则 | 限制到特定 IP 范围 |
| SEC-003 | 数据库公网访问 | HIGH | 检测 RDS 公网可达 | 禁用公网访问，使用内网 |
| SEC-004 | 存储加密 | MEDIUM | 检测 S3/EBS 未加密 | 启用服务端加密 |
| SEC-005 | IAM 权限过大 | MEDIUM | 检测 * 通配符权限 | 使用最小权限原则 |
| SEC-006 | 日志审计缺失 | LOW | 检测关键服务未开启日志 | 开启 CloudTrail/操作审计 |

### 3.2 成本优化审查规则

| 规则 ID | 规则名称 | 严重度 | 检查内容 | 修复建议 |
|--------|---------|--------|---------|---------|
| COST-001 | 实例规格过大 | MEDIUM | 检测 CPU/Memory 利用率<30% | 降配到合适规格 |
| COST-002 | 闲置资源检测 | HIGH | 检测 7 天无流量资源 | 删除或缩容 |
| COST-003 | Spot 实例建议 | LOW | 检测可替换为 Spot 的场景 | 使用 Spot 实例节省成本 |
| COST-004 | 存储生命周期 | MEDIUM | 检测 S3 无生命周期配置 | 配置自动转冷存储 |
| COST-005 | 预留实例建议 | LOW | 检测长期运行实例 | 购买预留实例 |

### 3.3 最佳实践审查规则

| 规则 ID | 规则名称 | 严重度 | 检查内容 | 修复建议 |
|--------|---------|--------|---------|---------|
| BP-001 | 资源命名规范 | LOW | 检测命名不符合规范 | 使用 team-env-resource 格式 |
| BP-002 | 标签完整性 | MEDIUM | 检测缺少必要标签 | 添加 team/project/env 标签 |
| BP-003 | Provider 版本锁定 | MEDIUM | 检测未锁定 Provider 版本 | 使用 version 约束 |
| BP-004 | 状态文件配置 | HIGH | 检测使用本地状态 | 配置远程后端 (S3+DynamoDB) |
| BP-005 | 模块复用 | LOW | 检测重复资源定义 | 抽取为 Terraform Module |

## 四、审批流程

### 4.1 风险等级与审批路由

```
┌─────────────────────────────────────────────────────────────────┐
│              风险等级与审批路由                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  风险评分    风险等级    审批流程           审批人              │
│  ─────────────────────────────────────────────────────────     │
│  0-30       LOW        自动通过          无需审批              │
│                                                                 │
│  31-60      MEDIUM     一级审批          Tech Lead             │
│                                                                 │
│  61-80      HIGH       二级审批          Tech Lead + SRE       │

│                                                                 │

│  • 成本增加>1000 元/月 → 必须产品经理审批                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 五、成本预估模型

### 5.1 成本预估流程

```
┌─────────────────────────────────────────────────────────────────┐
│              Terraform 变更成本预估流程                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  输入：Terraform Plan (变更资源列表)                              │
│                          │                                      │
│                          ▼                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 步骤 1: 识别资源类型                                      │   │
│  │ • aws_instance → EC2                                     │   │
│  │ • aws_rds_cluster → RDS                                  │   │
│  │ • aws_s3_bucket → S3                                     │   │
│  │ • aws_lambda_function → Lambda                           │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 步骤 2: 查询单价                                          │   │
│  │ • 从云厂商价格 API 获取实时单价                             │   │
│  │ • 从本地价格缓存获取 (每日更新)                           │   │
│  │ • 考虑折扣：预留实例/Spot/企业协议                        │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 步骤 3: 计算成本                                          │   │
│  │ • EC2 成本 = 实例规格单价 × 数量 × 运行时长                │   │
│  │ • RDS 成本 = 实例规格单价 + 存储单价 × 容量                │   │
│  │ • S3 成本 = 存储单价 × 容量 + 请求单价 × 次数              │   │
│  │ • Lambda 成本 = 请求单价 × 次数 + GB-秒单价 × 用量         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 步骤 4: 对比变更前后                                      │   │
│  │ • 变更前的月度成本                                        │   │
│  │ • 变更后的月度成本                                        │   │
│  │ • 成本差异 = 变更后 - 变更前                              │   │
│  │ • 成本变化率 = 差异 / 变更前 × 100%                       │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│  输出：成本预估报告                                              │
│  • 当前月度成本：10,000 元                                       │
│  • 变更后月度成本：10,500 元                                     │
│  • 成本增加：500 元/月 (5%)                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```
