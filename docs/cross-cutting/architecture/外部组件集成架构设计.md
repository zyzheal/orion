## 一、概述

### 1.1 集成背景

Orion 平台采用**核心域 + 支撑域**架构设计，遵循"增强而非替代"的设计原则。对于成熟的开源解决方案，我们采用集成而非重复造轮子的策略。

### 1.2 外部组件清单

| 组件 | 定位 | 集成方式 | 技术栈 | 许可证 | Namespace |
|------|------|---------|--------|--------|-----------|
| **orion-visor** | CMDB 服务器/应用/终端管理 | 微服务 API 集成 | Java + Vue3 | Apache-2.0 | orion-cmdb |
| **orion-dba** | SQL 审计 (Yearning + gemini-next) | 独立服务 + 微前端 | Go + React | AGPL-3.0 | orion-dba |
| **orion-knowledge** (PandaWiki) | 知识库/RAG 问答 | 可插拔微服务 | Go + Next.js | AGPL-3.0 | orion-knowledge |

**说明**:
- **orion-dba** = Yearning (后端) + gemini-next (前端) 的统一服务名称
- 所有外部组件均以独立 Namespace 部署，通过 API Gateway 和微前端基座集成

### 1.3 Build vs Integrate 决策

```
决策原则:
├── ✅ 集成 (不重复造轮子)
│   ├── 已有成熟开源方案 (orion-dba/Yearning SQL 审计 3.3k+ stars)
│   ├── 功能边界清晰 (CMDB 资产管理)
│   ├── 技术栈互补 (Go/Java 多语言生态)
│   └── 可独立部署 (降低系统耦合度)
│
└── 🔧 增强 (AI 能力提升)
    ├── AI 智能审核 (orion-dba + Orion AI Service)
    ├── 智能问答 (orion-knowledge RAG + LLM)
    ├── 自愈联动 (CMDB 拓扑 + 自愈引擎)
    └── 统一认证 (SSO + RBAC 集成)
```

#### 3.3.3 RAG 集成

```python
# Orion AI Service 调用 orion-knowledge RAG
class RAGIntegration:
    def __init__(self):
        self.knowledge_api = "http://orion-knowledge:8090/api/v1"
        self.vector_store = ChromaDB()
    
    async def query_knowledge(self, question: str, context: dict) -> str:
        # 1. 检索相关文档
        docs = await self._retrieve_documents(question)
        
        # 2. 构建 prompt
        prompt = self._build_prompt(question, docs, context)
        
        # 3. 调用 LLM 生成回答
        answer = await self.llm.generate(prompt)
        
        # 4. 验证并返回
        return self._validate_answer(answer, docs)
    
    async def _retrieve_documents(self, query: str) -> List[Document]:
        # 调用 orion-knowledge 检索 API
        response = await http.post(
            f"{self.knowledge_api}/rag/retrieve",
            json={"query": query, "top_k": 5}
        )
        return [Document(**doc) for doc in response["documents"]]
```

```
服务器变更数据流:

1. orion-visor 检测到服务器变更
         │
         ▼
2. 发布 NATS 事件：cmdb.server.updated
   {
     "server_id": "srv-123",
     "change_type": "config_change",
     "detail": {...}
   }
         │
         ▼
3. Orion Core 订阅事件
   ├── Pipeline Service: 更新可用构建节点
   ├── Workflow Service: 触发健康检查
   └── Insight Service: 记录变更指标
```

### 6.2 SQL 审计数据流

```
SQL 审核数据流:

1. 开发者提交 SQL (gemini-next)
         │
         ▼
2. Yearning 规则引擎审核
   ├── 语法检查
   ├── 规则检查
   └── 风险评估
         │
         ▼
3. Orion AI Service 增强
   ├── AI 优化建议
   └── 智能风险预测
         │
         ▼
4. 返回审核结果 (gemini-next 展示)
```

### 6.3 知识同步数据流

```
文档同步数据流:

1. Git 仓库文档变更 (webhook)
         │
         ▼
2. Orion Core 提取文档
   ├── Markdown 解析
   ├── 元数据提取
   └── 版本关联
         │
         ▼
3. orion-knowledge 处理
   ├── 向量化 (Embedding)
   ├── 索引构建
   └── 知识图谱更新
```

## 七、容错与降级

### 7.1 熔断策略

```yaml
# API Gateway 熔断配置
circuit_breaker:
  orion-visor:
    failure_threshold: 5      # 连续 5 次失败触发熔断
    recovery_timeout: 30s     # 30 秒后尝试恢复
    half_open_requests: 3     # 半开状态允许 3 次请求
    
  yearning:
    failure_threshold: 3      # SQL 审计关键路径，更敏感
    recovery_timeout: 60s
    half_open_requests: 1
    
  orion-knowledge:
    failure_threshold: 5
    recovery_timeout: 30s
    half_open_requests: 3
```

### 7.2 降级方案

| 组件 | 降级触发条件 | 降级行为 | 恢复条件 |
|------|-------------|---------|---------|
| **orion-visor** | 连续 5 次失败 | 使用本地缓存的 CMDB 快照 | 连续 3 次成功 |
| **Yearning** | 服务不可用 | 降级为规则引擎 + AI 审核 | 服务恢复 |
| **orion-knowledge** | RAG 不可用 | 降级为纯 LLM 回答 | 服务恢复 |

### 7.3 故障切换

```
Yearning 故障切换流程:

1. 检测到 Yearning 服务不可用 (连续 3 次健康检查失败)
         │
         ▼
2. API Gateway 触发熔断，返回 503
         │
         ▼
3. Orion Core 降级逻辑
   ├── 规则引擎：使用本地规则库
   ├── AI 审核：LLM + Orion 规则
   └── 工单流程：临时存储，待恢复后同步
         │
         ▼
4. 告警通知 SRE (PagerDuty/钉钉)
         │
         ▼
5. SRE 执行 runbook 恢复
```
