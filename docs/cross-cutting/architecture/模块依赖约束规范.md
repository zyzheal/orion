# Orion 模块依赖约束规范

> 本文档定义模块间的依赖方向，防止循环依赖，为未来可能的服务拆分做准备。
> 当前为单体架构，依赖约束通过**代码规范**实施，而非物理隔离。

---

## 一、核心域 vs 支撑域划分

### 核心域（Core Domain）— 高频迭代，直接面向研发流程

| 模块 | 服务文件 | 路由 |
|------|---------|------|
| Pipeline 引擎 | `services/pipeline/` | `build-routes.ts` |
| 构建环境 | `services/build/` | `build-routes.ts` |
| 多工具链 | `services/plugin/` `services/plugin-spi/` | `plugin-spi-routes.ts` |
| 代码管理 | `services/code-repo/` | `code-repo-routes.ts` |
| 配置管理 | `services/config-mgmt/` | `config-routes.ts` |
| 智能部署 | `services/smart-deploy/` | `deploy-routes.ts` |

| 模块 | 服务文件 | 路由 |
|------|---------|------|
| AI 增强 | `services/ai/` `services/ai-review/` `services/ai-security/` | `ai-gateway-routes.ts` 等 |

| 知识管理 | `services/knowledge/` | `knowledge-routes.ts` |

### 平台基础（Foundation）— 跨域通用能力

| 模块 | 服务文件 | 路由 |

## 二、依赖规则

### 规则 1: 核心域 → 支撑域（允许）

核心域可以读取支撑域的能力数据，但不应强依赖其可用性。

```
✅ 允许:
PipelineEngine → MonitoringService (查询监控指标)
DeployService → AIGateway (AI 审查部署配置)
BuildService → CMDBIntegration (查询服务器资源)

❌ 禁止:
PipelineEngine 调用 TicketService.createTicket() (应通过事件总线)
DeployService 直接修改 FinOps 数据 (应发布事件)
```

### 规则 2: 支撑域 → 核心域（仅事件订阅，禁止同步调用）

支撑域通过消费核心域发布的事件来响应变化，不应直接调用核心域的 Service。

```
✅ 允许:
FinOpsService 订阅 PipelineEventPublisher 的流水线完成事件
TicketService 订阅 DeploymentEventPublisher 的部署失败事件
MonitoringService 订阅所有事件用于告警关联

❌ 禁止:
FinOpsService 直接调用 PipelineService.getPipelineRun()
TicketService 直接调用 DeployService.deploy()
SelfHealingService 直接修改 PipelineEngine 内部状态
```

### 规则 3: 支撑域 ↔ 支撑域（禁止直接调用）

支撑域之间必须通过平台基础层（事件总线、通知、工单）中转。

```
✅ 允许:
SelfHealingService → EventBusService.publish() → MonitoringService 消费
ChatOpsService → TicketingService (通过工单系统 API，非直接 Service 调用)

❌ 禁止:
SelfHealingService 直接调用 MonitoringService.alert()
FinOpsService 直接调用 TicketService.createTicket()
CMDBService 直接调用 SelfHealingService.heal()
```

### 规则 4: 所有域 → 平台基础（允许）

所有业务域都可以使用平台基础能力。

```
✅ 允许:
任何 Service → AuditService.record()
任何 Service → EventBusService.publish()
任何 Service → TenantMiddleware.getTenant()
任何 Controller → AuthenticationService.verify()
```

## 四、实施检查

### 4.1 代码审查检查点

在 PR 审查中检查以下违规：

1. **核心域 import 支撑域 Service**: `import { XService } from '../ticketing/'`（允许 import 类型，禁止 import 实现类）
2. **支撑域直接调用核心域方法**: `pipelineService.getRun()`（应通过事件或 API）
3. **支撑域之间互相 import**: `import { SelfHealingService } from '../self-healing/'`

## 五、当前违规情况

经代码审查，以下模块存在轻微违规（可接受，未来拆分时需修复）：

| 违规 | 文件 | 严重程度 | 修复建议 |
|------|------|---------|---------|
| SelfHealingService 调用 DeployService | 低 | 拆分时改为事件驱动 |
| ChatOps 直接调用多个支撑域 Service | 低 | ChatOps 是聚合层，拆分时改为 API 调用 |
| FinOpsV2Controller 直接查询多个支撑域数据 | 低 | 拆分时改为独立 API |
