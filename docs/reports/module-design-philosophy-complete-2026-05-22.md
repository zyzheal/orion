## 一、Orion 平台核心理念

**核心理念**: "不替代现有工具链，而是让现有工具链变聪明"

### 六大颠覆性亮点

| 亮点 | 问题解决 | 行业现状 | Orion 能力 |
|------|---------|---------|-----------|
| 自主事件指挥官 | 出故障靠人协调 (30-60min) | 人工响应 | AI 自主协调 (2-5min)，MTTR↓90% |
| 零代码服务接入 | 接入流程繁琐 (4-8h) | 手写配置 | 说一句话 30 秒搞定，接入效率↑500x |
| 数字孪生+预测预防 | 故障总是事后才发现 | 被动响应 | 提前 2 小时预测，故障↓90% |
| 组织知识永动机 | 经验随人走/文档过期 | 知识流失 | 自动积累+自动推送，新人上手↓90% |
| 自进化流水线 | 流水线配置靠人调 | 静态配置 | 自动持续优化，CI 时间↓80% |
| 端到端 AI 增强 | AI 只做单点工具 | 碎片化 | AI 贯穿全链路，全链路提效 |

## 二、八大菜单模块设计理念

### 2.1 工作台 (/workbench)
**定位**: 统一工作入口，个人效能中心
**设计理念**: 多视角视图、效能导向、统一收拢
**子模块**: 总览看板、个人看板、经理看板、Executive总览、效能分析、风险看板

### 2.2 控制台 (/console)
**定位**: 系统管理与配置中心
**设计理念**: 可扩展性、配置驱动、权限细化
**子模块**: 控制台首页、插件管理、系统配置、用户管理、子应用管理

### 2.3 交付 (/delivery)
**定位**: 从代码到制品的全链路交付中心
**设计理念**: 持续交付、质量内建、可观测
**子模块**: 流水线、部署、灰度分析、变更智能、代码管理、制品管理、二方库、测试管理

### 2.4 可观测性 (/observability)
**定位**: 全面可观测性覆盖，从监控到自愈
**设计理念**: 全栈监控、智能诊断、自愈自动化
**子模块**: 监控中心、告警、指标看板、诊断中心、自愈系统

### 2.5 AI 平台 (/ai)
**定位**: AI 驱动的研发效能提升
**设计理念**: AI 贯穿、统一入口、可观测 AI
**子模块**: ChatOps、AI Review、AI 文档、AI 网关、Agent 调度、LLM Trace、AI 成本、AI 知识库、AI 安全

### 2.6 基础设施 (/infra)
**定位**: 全生命周期基础设施管理
**设计理念**: 即代码、自愈能力、统一 CMDB
**子模块**: 环境管理、临时环境、构建环境、IaC 管理、队列管理、向量存储、事件总线、CMDB、拓扑图、Web 终端、批量执行、审计日志、会话管理、备份恢复、值班管理

### 2.7 治理 (/governance)
**定位**: 安全合规与配置治理中心
**设计理念**: 安全左移、合规内置、成本治理
**子模块**: 策略管理、审计日志、SBOM、租户列表、租户配额、角色管理、配置管理、审批流、工作流设计器、成本治理

### 2.8 生态 (/ecosystem)
**定位**: 垂直领域专业工具与扩展能力市场
**设计理念**: 开放扩展、市场生态、动态加载
**子模块**: 文档中心、Skill 市场、SPI 扩展点

## 三、三轮评审报告

### 3.1 综合评分

| 评审维度 | 评分 | 结论 |
|---------|------|------|
| 架构层面 | 7.5/10 | 设计理念清晰，模块划分基本合理 |
| 代码质量 | 6.5/10 | 设计落地有差距，Repository 迁移不完整 |
| 安全依赖 | 6.5/10 | 安全基础有但不完善 |
| **综合** | **6.8/10** | 需要明确边界+完善安全+推进落地 |

### 3.2 架构层面问题

| 问题 | 严重程度 | 建议 |
|------|---------|------|
| 模块边界模糊 | P0 | 交付/可观测性/AI 平台存在职责重叠 |
| 技术选型偏差 | P1 | 补充 NATS 事件总线、明确 svc 目录实际状态 |
| 演进路线模糊 | P2 | 补充微服务拆分路线图（Phase 1/2/3） |
| 缺少容灾设计 | P2 | 补充多活架构、RTO/RPO 目标 |

### 3.3 代码质量层面问题

| 问题 | 严重程度 | 建议 |
|------|---------|------|
| Repository 迁移不完整 | P1 | 仅 15 个 Repository，250+ Services |
| 异常处理不统一 | P1 | 仅 AIGateway 有完整熔断 |
| 多租户隔离不一致 | P1 | 仅约 10 个文件实现 tenant_id 过滤 |
| Controller 职责过薄 | P2 | 业务逻辑散落在 routes/Controller |

### 3.4 安全层面问题

| 问题 | 严重程度 | 建议 |
|------|---------|------|
| JWT 密钥管理缺失 | P1 | 补充 KMS 方案、Token 吊销机制 |
| 租户 Header 伪造风险 | P1 | x-tenant-id 应由网关自动注入 |
| 数据加密方案缺失 | P1 | 补充 TDE、AES-256、TLS 版本 |
| AI 供应链安全缺失 | P1 | 补充 API Key KMS 存储、跨境合规 |
| 合规映射缺失 | P2 | 补充 GDPR/等保 2.0/SOC2 对应措施 |

## 四、页面设计详细规范 (150+ 页面)

### 4.1 通用设计规范

**按钮栏设计原则**:
- 主按钮：页面主要操作，右上角或左上角
- 次按钮：辅助操作，与主按钮组合
- 操作列：表格行内操作，每行独立
- 批量操作：选中后显示，顶部或底部
- 刷新/导出：通用操作，放置在按钮栏末端

**显示栏设计原则**:
- 统计摘要：顶部聚合指标，1-4 个卡片
- 筛选条件：表格/列表顶部，可折叠
- 分页/无限滚动：列表底部，页码或加载更多
- 空状态：无数据时显示，引导操作
- 加载状态：Skeleton 或 Spin 占位

**交互完整性原则**:
- 操作反馈：成功 `message.success`，失败 `message.error`
- Loading 状态：异步操作显示 loading 或 disabled
- 二次确认：删除/禁用等危险操作需确认
- 空状态引导：Empty 组件 + 引导按钮
- 操作后刷新：增删改后自动刷新列表

### 4.2 跨页面交互模式

| 跳转类型 | 实现方式 | 典型场景 |
|---------|---------|---------|
| 路由跳转 | `useNavigate()` | 列表→详情、菜单导航 |
| 抽屉打开 | Drawer 组件 | 编辑、详情查看 |
| 模态框 | Modal 组件 | 确认、新建表单 |
| 全屏跳转 | React Router | 独立功能模块 |

**状态同步机制**:
- 列表刷新：即时更新 / 局部更新 / 轮询/SSE
- 跨组件状态：URL Params + Context + Zustand Store
- 乐观更新：先更新 UI → 调用 API → 失败回滚

### 4.3 典型跨页面操作流程

**工单流程**: TicketList → TicketDetail → ApprovalService → ApprovalManagement → WorkflowService → PipelineService → NotificationService

**Pipeline执行**: PipelineList → PipelineDetail → PipelineRunLive → TaskRunner → PipelineRunList → NotificationService

**部署流程**: DeploymentList → DeploymentDetail → K8s Controller → Monitoring → SelfHealing → NotificationService

### 4.4 认证与安全设计

**认证流程**: 用户输入凭证 → 验证码校验 → API 登录请求 → 生成 Access Token + Refresh Token → 前端存储 → 跳转首页

**Token 刷新机制**: Access Token 有效期 15 分钟（内存） / Refresh Token 有效期 7 天（httpOnly Cookie） / 自动刷新（拦截 401，提前 5 分钟刷新）

**安全设计**:
- XSS 防护：输入校验 + 输出转义 + CSP + HttpOnly
- CSRF 防护：Token + SameSite=Strict + Referer 校验
- 敏感信息：密码不存储、Token 内存存储、API Key 仅显示前缀

## 五、关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 后端架构 | Node.js + Fastify 单体 | 简化部署，渐进式演进到微服务 |
| 前端技术栈 | React 18 + Vite + Ant Design + Zustand | 生态成熟，Vite 极速 |
| 微前端策略 | Wujie → Orion-MF | 渐进式迁移降低风险 |
| 数据存储 | PostgreSQL (主) + Redis (缓存) | 成熟稳定，70+ migrations |

## 六、改进建议优先级

**高优先级 (P0-P1)**:
1. 明确模块边界（变更智能→AI 平台，自愈系统→基础设施）
2. 完善安全设计（租户 Header 自动注入、数据加密、JWT 密钥管理）
3. 推进代码落地（Repository 迁移计划、全局租户中间件、公共 CircuitBreaker）

**中优先级 (P2)**:
1. 补充微服务演进路线图
2. 补充容灾与多活设计
3. 补充合规性映射（GDPR/等保/SOC2）
4. 补充 SDL 内容（CVE/SAST/DAST）
